## Task 1: Introduction

<img width="402" height="413" alt="image" src="https://github.com/user-attachments/assets/c600b558-d2de-46dc-a8ac-041a7da66498" />


The **Pyramid of Pain** is a cybersecurity model that shows how difficult it is for hackers to change their attack methods when security teams detect and block them.

It helps **SOC Analysts**, **Threat Hunters**, and **Incident Responders** understand and stop cyberattacks.

> **Example**: Blocking a malicious IP is easy for an attacker to bypass by changing IPs. Detecting their attack techniques makes it much harder for them to continue.

## Task 2: Hash Values (Trivial)

A **hash value** is like a digital fingerprint of a file. It helps identify files and detect changes.



#### Three Common Hash Algorithms

| Algorithm | Full Name | Developed By | Defined By | Hash Size | Security |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **MD5** | Message Digest Algorithm 5 | Ron Rivest (1992) | RFC 1321 | 128 bits (32 hex characters) | Insecure |
| **SHA-1** | Secure Hash Algorithm 1 | NSA; published by NIST (1995) | RFC 3174, FIPS 180 | 160 bits (40 hex characters) | Insecure |
| **SHA-2** | Secure Hash Algorithm 2 | NSA; standardized by NIST (2002) | FIPS 180-2, FIPS 180-4 | 224–512 bits | Secure for appropriate uses |
| **SHA-256** | Secure Hash Algorithm 256-bit | NSA / NIST | FIPS 180-4, RFC 6234 | 256 bits (64 hex characters) | Secure |


##### Why security analyst the hashes?
- **Identify malware**: Check whether a file matches known malware.
- **Detect changes**: See if a file has been modified.
- **Investigate attacks**: Search for suspicious files.
- **Check file reputation**: Use websites like [VirusTotal](https://www.virustotal.com/gui/), [Metadefender Cloud - OPSWAT](https://metadefender.opswat.com/?lang=en).


> Even a tiny change to a file can produce a completely different hash value.


**Example**: Before and After Modification


**Before modification:**
````shell
Get-FileHash .\OpenVPN_2.5.1_I601_amd64.msi -Algorithm MD5
````
Hash: ``D1A008E3A606F24590A02B853E955CF7``

**After modification:**
````shell
echo "AppendTheHash" >> .\OpenVPN_2.5.1_I601_amd64.msi
````

This command adds text to the end of the file.


**Check the hash again:**
````shell
Get-FileHash .\OpenVPN_2.5.1_I601_amd64.msi -Algorithm MD5
````

New hash: ``9D52B46F5DE41B73418F8E0DACEC5E9F``

## Task 3: IP Address (Easy)

**IP Address** is a unique network address used to identify devices and communicate over a network.

##### Why Are IP Addresses Important?

- **Identify attackers**: Detect suspicious IP addresses.
- **Track connections**: Monitor communication with malicious servers.
- **Block threats**: Use firewalls to block known malicious IPs.


##### How Does It Work?
- **Detect**: SOC Analyst discovers a malicious IP address.
- **Block**: Firewall blocks connections from that IP.
- **Bypass**: Attacker changes to another public IP address.
- **Continue**: Attacker attempts to reconnect using the new IP.

Example:

- Attacker IP: ``192.0.2.10``
- Firewall blocks: ``192.0.2.10``
- Attacker switches to: ``192.0.2.20``
- The original firewall rule no longer blocks the attacker.


Malicious IP connections [app.any.run](https://app.any.run/tasks/a66178de-7596-4a05-945d-704dbf6b3b90):

<img width="1867" height="1017" alt="image" src="https://github.com/user-attachments/assets/2fdca6fd-cf1d-4739-bf03-06597423c16e" />


**Fast Flux** is a DNS technique used by attackers to constantly change the IP addresses associated with a domain, making malicious servers harder to block and track.

##### How Does Fast Flux Work?
**For example**, a malicious domain malware.example changes IP addresses frequently:
- ``10:00 AM`` → ``192.0.2.10``
- ``10:05 AM`` → ``192.0.2.20``
- ``10:10 AM`` → ``192.0.2.30``

> These are example IP addresses, not real malicious servers.


##### Why Do Attackers Use Fast Flux?
- **Avoid detection**: Make malicious infrastructure harder to identify.
- **Bypass IP blocking**: Switch IP addresses when defenders block them.
- **Hide C2 servers**: Conceal malware communication.
- **Maintain attacks**: Keep malicious services accessible.

## Task 4: Domain Names (Simple)

**Domain Name** is a human-readable name that helps users access a website or server without remembering its IP address.

##### Example of Domain Names
- Domain: ``evilcorp.com``
- Subdomain: ``tryhackme.evilcorp.com``
- IP Address: ``192.0.2.10``

> DNS translates domain names into IP addresses.


##### Why Are Domain Names Important in Cybersecurity?
- **Identify threats**: Detect malicious domains.
- **Block attacks**: Prevent access to malicious websites.
- **Detect C2 communication**: Identify malware connecting to attacker-controlled domains.

##### Why Are Domain Names Harder to Change?
Attackers may need to:
- Purchase a new domain.
- Register and configure it.
- Update DNS records.
- Redirect their malware or phishing traffic.

> However, some DNS providers offer APIs that make these changes faster.

##### What Is a URL Shortener?
A **URL shortener** turns a long website link into a short one.

For example:
- **Original**: ``https://example.com/long-page``
- **Shortened**: ``https://bit.ly/example123`` (illustrative)

Attackers may use shortened URL to hide malicious destinations.

> **Note**: Not every shortened URL is malicious.

##### What Are Malicious C2 Domains?
**C2 = Command and Control**

A **C2** domain allows malware to communicate with an attacker-controlled server.

> Attackers may use these connections to send commands or receive stolen data.

The attackers normally use the following URL-shortening services to generate malicious links: 

- ``bit.ly``
- ``goo.gl``
- ``ow.ly``
- ``s.id``
- ``smarturl.it``
- ``tiny.pl``
- ``tinyurl.com``
- ``x.co``

## Task 6: Network Artifacts (Annoying)

**Network artifacts** are suspicious traces or patterns left by attackers in network traffic.

**Examples:**
- **User-Agent:** Unusual strings identifying the software making HTTP requests.
- **C2 (Command and Control):** Communication between malware and an attacker's server.
- **URI Patterns:** Suspicious web paths used in HTTP requests.
- **HTTP POST Requests:** Requests potentially used to send stolen data or communicate with C2 servers.

**Detection Tools:**
- **Wireshark / TShark:** Analyze network packets (PCAP files).
- **[Snort (IDS)](https://www.snort.org/):** Detect suspicious network traffic and generate alerts.

**Impact on Attackers:** Detecting network artifacts forces attackers to modify their tools or communication patterns, costing more time and resources.


<img width="1572" height="139" alt="image" src="https://github.com/user-attachments/assets/d6f46d2e-5e74-4184-afb7-19188a24c957" />


Identifying malware from HTTP requests alone can be difficult. Security analysts examine network indicators, such as the **User-Agent**, to find suspicious activity.


Sample command:
````shell
tshark --Y http.request -T fields -e http.host -e http.user_agent -r analysis_file.pcap
````

<img width="1395" height="338" alt="image" src="https://github.com/user-attachments/assets/b0848bab-fd90-4dd2-ad5d-b09e8f9cc20a" />



**Emolet Trokjan:**
- **Emotet**: Malware that can use specific User-Agent strings in network traffic.
- **Detection**: Security analysts identify suspicious User-Agent strings.
- **Prevention**: Block known malicious patterns to disrupt malware communication.
- **Impact**: Forces attackers to change their methods, costing more time and resources.

## Task 8: TTPs (Tough)

**TTPs** stand for **Tactics**, Techniques, and Procedures. They describe how attackers plan, perform, and execute cyberattacks.

| Term             | Explanation                                                         |
| ---------------- | ------------------------------------------------------------------- |
| **Tactics**      | The attacker's goals (WHY), such as stealing data.                  |
| **Techniques**   | Methods used to achieve those goals (HOW), such as phishing.        |
| **Procedures**   | Specific steps attackers follow to carry out techniques.            |
| **MITRE ATT&CK** | A framework documenting real-world attacker tactics and techniques. |

**Examples:**

- **Phishing:** Tricking users into revealing information or executing malware.
- **Persistence:** Maintaining access to a compromised system.
- **Lateral Movement:** Moving between computers inside a network.
- **Data Exfiltration:** Stealing data from a compromised network.
- **Pass-the-Hash:** Using stolen password hashes to authenticate without knowing the plaintext password.
