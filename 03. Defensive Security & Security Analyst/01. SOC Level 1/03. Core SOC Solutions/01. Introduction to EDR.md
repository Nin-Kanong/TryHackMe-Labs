## Task 2: What is an EDR?

**Endpoint Detection and Response (EDR)** protects computers, laptops, and servers from cyber threats, even when employees work remotely.


#### Why EDR is Needed?

- Protects devices inside and outside company networks.
- Detects malware, ransomware, and suspicious activities.
- Monitors remote employees' devices.
- Helps SOC analysts investigate and respond to attacks.

### Detection

**Detection** identifies suspicious activities and potential threats on endpoint devices.

#### Main Detection Capabilities

- **Signature-Based Detection**: Detects known malware using signatures.
- **Behaviour-Based Detection**: Identifies unusual or suspicious activities.
- **Machine Learning**: Detects abnormal behaviour compared to normal activity.
- **Fileless Malware Detection**: Detects malware running in memory without traditional malicious files.
- **Custom IOCs**: Uses indicators of compromise, such as malicious IPs, domains, and file hashes, to detect threats.

#### Detection Dashboard

Each detection provides important information:

| Field        | Meaning                                                |
| ------------ | ------------------------------------------------------ |
| Severity     | How serious the threat is.                             |
| Time         | When the threat was detected.                          |
| File         | File that triggered the detection.                     |
| Hostname     | Affected computer.                                     |
| Username     | Account involved.                                      |
| MITRE ATT&CK | Maps the detection to attacker tactics and techniques. |

> EDR Detection helps SOC analysts identify known and unknown threats using signatures, behaviour analysis, machine learning, and custom IOCs.

## Task 3: Beyond the Antivirus


### Why do we need an EDR when we already have an Antivirus (AV) on the endpoints?

**Antivirus (AV)** and **EDR** both protect endpoint devices, but they provide different levels of security.

#### AV vs EDR

| Antivirus (AV)                         | EDR                                            |
| -------------------------------------- | ---------------------------------------------- |
| Detects and blocks known malware.      | Detects known and unknown threats.             |
| Mainly uses signature-based detection. | Uses signatures and behaviour-based detection. |
| Provides basic endpoint protection.    | Provides detailed endpoint monitoring.         |
| Limited investigation capabilities.    | Supports threat investigation and response.    |
| Focuses on blocking malware.           | Detects, investigates, and contains attacks.   |


#### Airport Security

- **Antivirus (AV)**: Checks passports against a database of known criminals.
- **EDR**: Security officers monitor activities inside the airport and identify suspicious behaviour.

Even when an attacker bypasses antivirus, EDR can detect suspicious activities inside the endpoint.

> Antivirus mainly blocks known malware, while EDR monitors endpoint behaviour to detect, investigate, and respond to advanced threats.


---


### Scenario Breakdown

* **Step #1**: A user receives a phishing email with a Word document embedded with a malicious macro (VBA script)
* **Step #2**: The user downloads the document and opens it
* **Step #3**: The malicious macro is silently executed, and it spawns PowerShell
* **Step #4**: The malicious macro runs an obfuscated PowerShell command to download a sophisticated second-stage payload
* **Step #5**: The payload is injected into a legitimate svchost.exe
* **Step #6**: The attacker gains remote access to the system

<img width="1920" height="1080" alt="image" src="https://github.com/user-attachments/assets/7244da63-e9a3-4dea-be49-acbdf21eb560" />



| Attack Steps | AV's Response | EDR's Response |
| :--- | :--- | :--- |
| **Step #1** | Does nothing if the downloaded file has no previous signature in the database | Logs the file download activity and monitors it |
| **Step #2** | Does nothing upon the opening of the document since winword.exe is a legitimate utility | Records the execution of winword.exe and keeps monitoring |
| **Step #3** | Does nothing if the executed macro has no previous signature | Detects and flags the macro execution due to the unusual parent-child relationship of winword.exe and PowerShell.exe processes |
| **Step #4** | Typically, AVs will not detect obfuscated PowerShell scripts | Flags the obfuscated script execution |
| **Step #5** | Will not flag malicious injection into svchost.exe since it does not monitor the memory injections | Detects Process Injection in svchost.exe |
| **Step #6** | Lacks Network Level Visibility | Flags the unexpected behaviour of svchost.exe, making an outbound connection |
| **Final Action** | May be marked as clean | Generates an alert with the full attack chain and enables the analyst to take actions from within the EDR |


> **Note**: Some modern AVs may have more enhanced visibility and detection. However, an EDR is ahead as it levels up the detection and response in an endpoint.  

**Attack Chain**: ``Phishing`` → ``Malicious Macro`` → ``PowerShell`` → ``Malware Download`` → ``Process Injection`` → ``Remote Access``.

## Task 4: How an EDR words?



**EDR** works using three main mechanisms:

- **Visibility**: An EDR agent installed on endpoints continuously collects activity data, such as processes, files, and network connections.
- **Detection**: Analyses collected data using signatures, behaviour analysis, and machine learning to identify threats.
- **Response**: Allows security analysts to take action, such as isolating infected devices, stopping malicious processes, and removing malware.

> EDR collects data, detects suspicious activities, and helps SOC analysts stop threats before they cause serious damage.

### Agents

**EDR Agents (also called Sensors)** are software installed on endpoint devices to monitor activities and send security data to a central EDR console.

**Main Responsibilities**:
- **Monitor**: Track processes, files, user actions, and network activities.
- **Collect Data**: Send endpoint activity information to the EDR console in real time.
- **Detect Threats**: Perform basic signature-based and behaviour-based detection.
- **Generate Alerts**: Report suspicious activities to the EDR console.


````mermaid
flowchart TD
    A["Endpoint Device"] --> B["EDR Agent / Sensor"]
    B --> C["Monitor and Collect Data"]
    C --> D["EDR Central Console"]
    D --> E["Generate Security Alerts"]
    E --> F["SOC Analyst Investigation"]
````

---


### EDR Console

**EDR Console** is the central management platform that receives and analyses security data from all EDR agents.

Main Responsibilities
1. Collect Data: Receives endpoint information from EDR agents.
2. Analyse Data: Uses detection rules and machine learning to identify threats.
3. Threat Intelligence: Matches endpoint activity with known threat information.
4. Generate Alerts: Creates alerts when suspicious activity is detected.
5. Centralised Monitoring: Gives SOC analysts an overview of all protected endpoints.


````mermaid
flowchart TD
    A["EDR Agents"] --> B["EDR Central Console"]
    B --> C["Correlate and Analyse Data"]
    C --> D["Threat Detection"]
    D --> E["Generate Security Alerts"]
    E --> F["SOC Analyst Investigation"]
````

> **EDR agents** collect endpoint data, while the EDR console analyses it, detects threats, and generates security alerts.

### What happens after Detection?

After **EDR** detects a threat, the SOC analyst must investigate and decide what action to take.

#### Main Steps after detection:

- **Acknowledge**: Review the security alert.
- **Prioritise**: Investigate based on severity: Critical → High → Medium → Low → Informational.
- **Investigate**: Check files, processes, network connections, and registry changes.
- **Classify**: Decide whether it is a True Positive or False Positive.
- **Respond**: If it is a real threat, take action using the EDR console.

> ``Detect`` → ``Prioritise`` → ``Investigate`` → ``Classify`` → ``Respond``.

## Task 5: EDR Telemetry


### What is Telemetry?

**Telemetry** is the data collected by EDR agents from endpoint devices and sent to the central EDR console for monitoring, detection, and investigation.

#### Samples of Telemetry

- Process activities
- File and folder changes
- Network connections
- Registry modifications
- User activities

> Telemetry is the endpoint's activity data that helps SOC analysts detect and investigate cyber threats.



### Collected Telemetry

**Telemetry** is detailed information collected by EDR agents from endpoint devices to help SOC analysts detect suspicious activities and investigate attacks.

<img width="650" height="365" alt="canvas" src="https://github.com/user-attachments/assets/d1400780-8a1e-4f91-8d26-e3217da8335a" />



#### 5 Main Types of Telemetry

| Type                           | What It Monitors                                                             |
| ------------------------------ | ---------------------------------------------------------------------------- |
| 1. Process Execution           | Tracks running processes, created processes, and parent-child relationships. |
| 2. Network Connections         | Monitors connections to IPs, ports, and suspicious servers.                  |
| 3. Command Line Activity       | Records commands executed in CMD and PowerShell.                             |
| 4. File & Folder Modifications | Tracks file creation, modification, and deletion.                            |
| 5. Registry Modifications      | Monitors Windows Registry changes that may indicate malicious activity.      |

#### Why Is It Important?

Telemetry helps SOC analysts:

- Detect malware and suspicious processes.
- Identify Command and Control (C2) connections.
- Detect data theft and lateral movement.
- Investigate malicious commands.
- Identify ransomware activities.

> EDR collects endpoint telemetry to help SOC analysts understand what happened, detect attacks, and investigate suspicious activities.
