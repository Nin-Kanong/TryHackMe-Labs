## Task 1: Introduction

**SIEM (Security Information and Event Management)** is a security solution that collects, normalizes, and analyses logs from different devices in an organisation.

#### Main functions
- **Log Collection**: Collects logs from servers, firewalls, computers, and applications.
- **Normalization**: Converts different log formats into a standard format.
- **Correlation**: Connects related events to identify suspicious activities.
- **Threat Detection**: Generates security alerts for SOC analysts.
- **Investigation**: Helps analysts investigate security incidents.


#### How SIEM works

````mermaid
flowchart TD
    A["Servers"] --> E["SIEM"]
    B["Firewalls"] --> E
    C["Endpoints"] --> E
    D["Applications"] --> E
    E --> F["Normalize and Correlate Logs"]
    F --> G["Detect Threats"]
    G --> H["Generate Alerts"]
    H --> I["SOC Analyst"]
````

## Task 2: Logs Everywhere, Answers Nowhere

### Logs Everywhere

**Log Sources** are devices that generate records of activities happening in a network.

#### Examples of Log Sources

- **Endpoints**: Windows and Linux computers.
- **Servers**: Store and manage company data.
- **Websites**: Record website requests and activities.
- **Network Devices**: Routers and firewalls record network traffic.

#### Why Are Logs Important?
- **Security Monitoring**: Detect suspicious activities.
- **Threat Investigation**: Track attacker activities.
- **Troubleshooting**: Identify system and network problems.


<img width="921" height="801" alt="image" src="https://github.com/user-attachments/assets/e317dbee-90c4-4995-878a-2ac54df5d040" />


> Every device generates logs that help SOC analysts monitor systems, detect attacks, and investigate security incidents.

### 1. Host-Centric Log Sources

**Host-Centric Logs** record activities that happen on individual devices, such as Windows, Linux computers, and servers.

#### Examples

| Log Activity         | Description                                        |
| -------------------- | -------------------------------------------------- |
| File Access          | User opens or accesses a file.                     |
| Authentication       | User login attempts (successful or failed).        |
| Process Execution    | Programs or processes are started.                 |
| Registry Changes     | Processes create, modify, or delete registry keys. |
| PowerShell Execution | Commands or scripts executed in PowerShell.        |

> Host-centric logs help SOC analysts monitor user activities, detect suspicious processes, and investigate attacks on individual devices.



### Network-Centric Logs

**Network-Centric Logs** record communication and activities between devices across a network or the Internet.

#### Examples

| Log Activity         | Description                                             |
| -------------------- | ------------------------------------------------------- |
| SSH Connection       | Records remote connections to systems.                  |
| FTP Access           | Records file transfers using FTP.                       |
| Web Traffic          | Records website requests and connections.               |
| VPN Access           | Records users connecting to company resources remotely. |
| Network File Sharing | Records file access and sharing across networks.        |

**Common Log Sources:** Firewalls, IDS/IPS, routers, and network devices.

> Network-centric logs help SOC analysts monitor network traffic, detect suspicious connections, and investigate attacks.



### Answers Nowhere

Managing logs from many devices is difficult for SOC analysts because of the large volume of data, different formats, and lack of centralisation.

#### 5 Main Challenges

| Challenge               | Detailed Explanation                                                                                                                                      | Example                                                                                                       |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Numerous Log Sources** | Organisations have many devices generating hundreds or thousands of events every second. Finding important security events among these logs is difficult. | Windows PCs, Linux servers, firewalls, and routers all generate logs.                                         |
| **No Centralisation**    | Logs are stored separately on each device. Analysts must connect to individual systems using SSH or RDP to collect and investigate logs.                  | An analyst must log in to multiple servers to check suspicious login attempts.                                |
| **Limited Context**      | A single log may look normal, but combining logs from different devices can reveal a cyberattack.                                                         | A user accesses a file normally, but other logs reveal the user gained access through a compromised computer. |
| **Limited Analysis**     | The huge number of logs makes manual investigation slow and difficult. Analysts may miss important security events.                                       | An analyst cannot manually review millions of events every day.                                               |
| **Format Issues**        | Different devices generate logs in different formats, making it difficult to compare and analyse them together.                                           | Windows, Linux, and firewalls may record timestamps and event details differently.                            |

## Task 3: Why SIEM?


**SIEM (Security Information and Event Management)** is a security solution that collects, centralises, and analyses logs from multiple devices to detect cyber threats.

#### Main Functions

- **Log Collection**: Collects logs from Windows, Linux, servers, firewalls, and applications.
- **Normalisation**: Converts different log formats into a standard format.
- **Correlation**: Connects related events to identify suspicious activities.
- **Threat Detection**: Uses detection rules to identify malicious activities.
- **Alert Generation**: Sends security alerts to SOC analysts for investigation.

<img width="500" height="500" alt="image" src="https://github.com/user-attachments/assets/96fe3723-30e6-407b-a138-de977f670501" />

### Features of SIEM

The SIEM solution not only solves the issues we discussed in the previous task but also provides capabilities to enhance security operations. Let's discuss some of the core features that a SIEM provides.

#### Centralized Log Collection

**SIEM** collects logs from different devices, such as computers, servers, firewalls, and applications, and stores them in one central platform.

- **Agents**: Software installed on devices to forward logs to SIEM.
- **APIs**: Allow SIEM to retrieve logs from other systems.
- **Centralization**: Combines all logs in one location.
- **Benefit**: SOC analysts can monitor and investigate activities without accessing each device individually.

> **Example**: SIEM collects Windows login logs, Linux server logs, and firewall traffic logs into one dashboard.


#### Normalization of Logs

**Log Normalization** means converting logs from different devices (Windows, Linux, firewalls) into one consistent format so SIEM can easily analyse and compare them.

- **Parsing**: Breaks raw logs into separate fields, such as username, IP address, and timestamp.
- **Normalization**: Converts those fields into a standard format across different log sources.

> **Example**: Windows and Linux login logs are converted into the same structure.

---



#### Correlation of Logs

**Log Correlation** means connecting related logs from different sources to identify suspicious activities or attack patterns.

Example:
| Step | Activity                                               |
| ---- | ------------------------------------------------------ |
| 1    | Haris logs in through VPN using an unusual IP address. |
| 2    | Haris accesses sensitive shared files.                 |
| 3    | Haris executes a PowerShell script.                    |
| 4    | The system makes an unusual outbound connection.       |

> **Benefit**: SIEM connects these events and may detect a potential data exfiltration attack caused by compromised VPN credentials.

> Log Correlation connects individual events to reveal the bigger picture of a possible cyberattack.

---

#### Real-Time Alerting

**Real-time Alerting** means SIEM automatically generates security alerts when suspicious activities match predefined detection rules.

- **Default Rules**: SIEM comes with built-in detection rules.
- **Custom Rules**: Analysts can create rules to detect specific threats.
- **Alert Generation**: SIEM triggers alerts when rule conditions are met.
- **Notification**: SOC analysts receive alerts for investigation.

> Example: SIEM detects 20 failed login attempts within 5 minutes and generates a Brute Force alert.

> Benefit: Helps SOC analysts detect and respond to threats quickly.


#### Dashboards and Reporting

**Dashboards** and Reporting display security information in visual formats, helping SOC analysts monitor and analyse activities in one place.

| Dashboard Information | Purpose                                        |
| --------------------- | ---------------------------------------------- |
| Alert Highlights      | Shows important security alerts.               |
| System Notifications  | Displays system messages and updates.          |
| Health Alerts         | Identifies SIEM or device health problems.     |
| Failed Login Attempts | Shows unsuccessful login activities.           |
| Events Ingested Count | Displays the number of logs collected.         |
| Rules Triggered       | Shows which detection rules generated alerts.  |
| Top Domains Visited   | Displays the most frequently accessed domains. |

> Benefit: Helps SOC analysts monitor security activities, identify problems, and investigate threats quickly.

## Log Sources and Ingestion


### Log Source

Log Sources are devices that generate logs whenever activities occur on them.

#### Examples

- **Windows/Linux**: User login and process execution.
- **Firewall**: Network traffic and blocked connections.
- **Router**: Network communication.
- **Web Server**: Website visits and HTTP requests.
- **SSH Server**: Remote login attempts.

> Log sources record device activities and send logs to SIEM for monitoring, threat detection, and investigation.



### Windows Machine

**Windows Event Logs** record activities happening on Windows computers and servers.

- **Event Viewer**: Windows tool used to view and manage system logs.
- **Event ID**: A unique number assigned to each type of event.
- **Log Forwarding**: Windows logs are sent to SIEM for centralised monitoring and investigation.

Example Event IDs:
| Event ID | Description                |
| -------- | -------------------------- |
| ``4624``     | Successful login           |
| ``4625``     | Failed login               |
| ``4688``     | Process creation           |
| ``4720``     | User account created       |
| ``1102``     | Security audit log cleared |

> Windows Event Viewer records system activities, while SIEM collects these logs to help SOC analysts detect suspicious activities.

### Linux Machine

**Linux Logs** record system activities, errors, warnings, authentication events, and scheduled tasks.

#### Common Linux Log Locations

| Log Location        | Purpose                                            |
| ------------------- | -------------------------------------------------- |
| `/var/log/httpd`    | Stores HTTP requests, responses, and errors.       |
| `/var/log/cron`     | Records scheduled task activities (cron jobs).     |
| `/var/log/auth.log` | Stores authentication events (Debian/Ubuntu).      |
| `/var/log/secure`   | Stores authentication events (RHEL-based systems). |
| `/var/log/kern`     | Records kernel-related events.                     |

#### Example: Cron Logs

Cron logs record scheduled tasks and their execution.

| Log Entry                           | Meaning                                      |
| ----------------------------------- | -------------------------------------------- |
| `crond started`                     | Cron service started.                        |
| `user root job sys-hourly`          | Root user has an hourly scheduled task.      |
| `unable to exec /usr/sbin/sendmail` | Cron could not execute the sendmail program. |

> Linux stores logs in `/var/log/`, and SIEM collects them to help SOC analysts monitor system activities and investigate security incidents.

### Log Ingestion

**Log Ingestion** is the process of collecting and sending logs from different devices to a SIEM platform for analysis.

#### Main Log Ingestion Methods

| Method               | Explanation                                                                    | Example                                       |
| -------------------- | ------------------------------------------------------------------------------ | --------------------------------------------- |
| 1. Agent / Forwarder | Installs lightweight software on endpoints to collect and send logs to SIEM.   | Splunk Universal Forwarder.                   |
| 2. Syslog            | Uses the Syslog protocol to send logs from devices to a central SIEM server.   | Firewalls, routers, and Linux servers.        |
| 3. Manual Upload     | Allows analysts to upload existing log files for analysis.                     | Uploading `.log` or `.csv` files into Splunk. |
| 4. Port Forwarding   | Sends logs to a specific port where the SIEM server listens for incoming data. | Sending logs to Splunk on TCP port 9997.      |

> Log ingestion collects logs from different sources and sends them to SIEM so SOC analysts can monitor, analyse, and detect threats.

## Task 5: Alerting Process and Analysis

**Detection Rules** are conditions configured in SIEM to identify suspicious activities and automatically generate security alerts.

#### Examples of Detection Rules

| Condition                                        | Generated Alert                                |
| ------------------------------------------------ | ---------------------------------------------- |
| 5 failed login attempts within 10 seconds.       | Multiple Failed Login Attempts                 |
| Successful login after multiple failed attempts. | Successful Login After Multiple Login Attempts |
| User connects a USB device.                      | USB Device Connected                           |
| Outbound traffic exceeds 25 MB.                  | Potential Data Exfiltration                    |

> SIEM uses detection rules to identify suspicious activities and automatically alert SOC analysts for investigation.


---

### How is a detection rule created?

To explain how the rule works, consider the following Eventlog use cases:

#### Use-Case 1

Attackers may clear Windows Event Logs to hide their activities.

| Condition  | Value             |
| ---------- | ----------------- |
| Log Source | WinEventLog       |
| Event ID   | 104               |
| Action     | Trigger an alert  |
| Alert Name | Event Log Cleared |

##### Detection Rule Logic

```
IF Log Source = WinEventLog
AND Event ID = 104
THEN Generate Alert: "Event Log Cleared"
```

> SIEM checks incoming logs against detection rules and generates alerts when the specified conditions match.


---


#### Use-Case 2

Attackers may use the `whoami` command after gaining access to a system to identify their current user privileges.

##### Detection Rule

| Field          | Value                             |
| -------------- | --------------------------------- |
| Log Source     | WinEventLog                       |
| Event ID       | 4688 (Process Creation)           |
| NewProcessName | Contains `whoami`                 |
| Alert Name     | WHOAMI Command Execution DETECTED |

##### Rule Logic

```
IF Log Source = WinEventLog
AND Event ID = 4688
AND NewProcessName contains "whoami"
THEN Generate Alert
```
> SIEM detects suspicious process execution by matching log field values against detection rules. Normalized logs make this process easier and more accurate.


---


### Alert Investigation

**Alert Investigation** means analysing triggered alerts to determine whether they are real threats or false positives.

#### Main Actions

| Action              | Explanation                                                |
| ------------------- | ---------------------------------------------------------- |
| False Positive      | Tune detection rules to reduce repeated false alerts.      |
| True Positive       | Perform deeper investigation.                              |
| Contact Asset Owner | Confirm whether the activity is legitimate.                |
| Isolate Host        | Disconnect an infected device to prevent attack spreading. |
| Block Suspicious IP | Prevent communication with malicious IP addresses.         |

> Investigate alerts, verify threats, and take appropriate actions to protect the organisation.
