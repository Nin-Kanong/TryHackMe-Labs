## Task 1: Introduction

SOC L1 analysts may need help when investigating alerts or handling serious cyberattacks.

1. **Alert Reporting**: Document and report suspicious activities and investigation findings.
2. **Escalation**: Send complex or serious alerts to senior analysts (L2/L3).
3. **Communication**: Share incident information with teammates and relevant departments.

> Report findings, escalate serious threats, and communicate clearly to handle security incidents effectively.

## Task 2: Alert Funnel

### Alert Workflow

1. **L1 Receives Alerts**: From SIEM, EDR, or ticket platforms.
2. **L1 Investigates**: Checks whether alerts are real threats or false positives.
3. **Close Alerts**: False positives or issues resolved at L1 are closed.
4. **Escalate to L2**: Complex or serious threats are sent to senior analysts.
5. **L2 Remediates**: Investigates deeper and helps stop security breaches.

### Alert Reporting 

**Alert Reporting** means documenting investigation findings before closing or escalating an alert.

- Record investigation steps.
- Include important evidence.
- Explain our findings and verdict.
- Report True Positives clearly for escalation.

> Document evidence and findings so other analysts can understand the incident.

---

### Alert Escalation

**Alert Escalation** means forwarding a confirmed security threat (True Positive) to an L2 analyst for deeper investigation or action.

- Escalate serious threats to L2.
- Follow SOC procedures.
- Provide the alert report and evidence.
- Help L2 save investigation time.


  
### Communication

**Communication** means contacting other departments to verify information during an investigation.

- **IT Team**: Confirm user permissions or system changes.
- **HR Team**: Verify employee information.
- **Other Teams**: Share incident details and request clarification.

## Task 3: Reporting Guide

Having L1 analysts write alert reports serves several key purposes:

| Alert Report Purpose | Explanation |
| :--- | :--- |
| **Provide context for escalation** | <ul><li>A well-written report saves lots of time for L2 analysts</li><li>Also, it helps them quickly understand what happened</li></ul> |
| **Save findings for the records** | <ul><li>Raw SIEM logs are stored for 3-12 months, but alerts are kept indefinitely</li><li>As a result, it's better to keep all the context inside the alert, just in case</li></ul> |
| **Improve investigation skills** | <ul><li>If you can't explain it simply, you don't understand it well enough</li><li>Report writing is a great way to boost L1 skills by summarising alerts</li></ul> |


---


### Report Format

Use the [5Ws](https://en.wikipedia.org/wiki/Five_Ws) to write a clear security alert repor:

| W     | Meaning                                    |
| ----- | ------------------------------------------ |
| Who   | Who performed the activity?                |
| What  | What happened?                             |
| When  | When did it happen?                        |
| Where | Which device, IP, or website was involved? |
| Why   | Why is it suspicious or legitimate?        |

> Use the Five Ws to document incidents clearly and help other analysts understand our investigation.

## Task 4: Escalation Guide

Escalate an alert to SOC L2 when:

1. **Major Attack**: A serious cyberattack needs deeper investigation.
2. **Remediation Needed**: Malware removal, host isolation, or password reset is required.
3. **External Communication**: Management, customers, or law enforcement must be contacted.
4. **Need Help**: We don't understand the alert and need senior support.

> L1 handles basic alerts; L2 handles complex threats and serious incidents.



### Escalation Steps

1. **Reassign**: Transfer the alert to the SOC L2 analyst.
2. **Notify**: Contact L2 through corporate chat or in person.
3. **Review**: L2 reads your report and investigates further.
4. **Validate**: L2 confirms whether it is a real threat.
5. **Respond**: L2 coordinates with other teams and starts Incident Response if needed.

### Requesting L2 Support

SOC L1 analysts should ask L2 for help when they don't understand an alert.

1. **Ask for Help**: Contact an experienced L2 analyst.
2. **Share Details**: Explain the alert and your findings.
3. **Clarify**: Ask questions and follow SOC procedures.
4. **Continue**: Investigate or escalate based on L2 guidance.

### SOC Dashboard Escalation

1. **In Progress**: Change the alert status and investigate.
2. **Report**: Write our findings and set the verdict (e.g., True Positive).
3. **Reassign**: Assign the alert to the SOC L2 analyst.
4. **Notification**: L2 receives the alert and continues the investigation using our report.

## Task 5: SOC Communication 

**Crisis Communication** means following procedures to communicate effectively during serious security incidents.

- Follow the company's emergency communication procedures.
- Notify the right people quickly.
- Share accurate incident information.
- Coordinate with SOC, IT, management, and other teams.
- Stay calm and avoid spreading unverified information.


### Communication Cases

As a SOC L1 Analyst, we must know how to handle unexpected situations and communicate with the right people.

| Situation              | What Should we Do?                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------ |
| L2 Unavailable      | Contact L2 → L3 → SOC Manager using emergency contacts.                                 |
| Compromised Account | Contact the affected user by phone, not through the compromised Slack or Teams account. |
| Too Many Alerts     | Prioritise critical alerts first and inform L2 about the alert volume.                  |
| Missed Threat       | Immediately inform L2, explain the mistake, and investigate again.                      |
| SIEM Problem        | Investigate available evidence and report the issue to L2 or the SOC Engineer.          |
