| Web Server             | Technology             | What to identify                              |
| ---------------------- | ---------------------- | --------------------------------------------- |

| **Nginx**              | Modern web server      | Autoindex, directories, `nginx_status`        |

- Enumerate Apache directories, status pages, and backup files.
- Identify debug endpoints, verbose errors, and environment-variable exposure in Node.js Express.
- Detect Nginx autoindex directories and exposed ``nginx_status``.
- Perform security-header auditing using ``curl`` and ``nikto``.

### 2. What Does It Serve?
The server exposes the **entire directory where the command was run**.

For example:
````
/home/user/project/
│
├── .env
├── backup.zip
├── config.txt
└── notes.txt
````

If we run:
````
python3 -m http.server 8000
````
those files can become accessible through:
````
http://TARGET:8000/
````
Unlike Apache/Nginx, Python's simple HTTP server doesn't provide the same access-control/configuration features.

### 3. The mod_status Page

#### /server-status 

Try:
````
http://10.48.177.12/server-status
````
<img width="1919" height="1021" alt="image" src="https://github.com/user-attachments/assets/559d44f0-6c9b-4cca-8269-2e236ac8ce2a" />


Normally this page should be restricted to localhost/internal users. An incorrectly configured ``Require all granted`` can expose it.

> **Info**: ``mod_status`` is enabled by default on Ubuntu's **Apache** package and ships with a ``Require local`` restriction in ``conf-available/security.conf``. However, a ``Require all granted`` directive anywhere in a virtual host configuration silently overrides that restriction, exposing ``/server-status`` to all IPs without touching the module config. Always check /server-status even on servers that appear to be using default settings.

### 4. Find Unlinked Files

#### Command Syntax:
````
gobuster dir -u http://TARGET_IP:80 -w /usr/share/wordlists/SecLists/Discovery/Web-Content/common.txt -x bak,txt,html -t 20
````

| Part                  | Meaning      | Explanation                                    |
| --------------------- | ------------ | ---------------------------------------------- |
| `gobuster`            | Tool         | Used to discover hidden directories and files  |
| `dir`                 | Mode         | Directory/file enumeration mode                |
| `-u`                  | URL          | Specifies the target website                   |
| `http://TARGET_IP:80` | Target       | Web server running on port `80`                |
| `-w`                  | Wordlist     | Specifies the wordlist to use                  |
| `common.txt`          | Wordlist     | Contains common directory/file names to test   |
| `-x`                  | Extensions   | Adds file extensions to each word              |
| `bak`                 | Extension    | Searches for backup files such as `config.bak` |
| `txt`                 | Extension    | Searches for text files such as `notes.txt`    |
| `html`                | Extension    | Searches for HTML files such as `admin.html`   |
| `-t`                  | Threads      | Controls how many requests run concurrently    |
| `20`                  | Thread count | Runs up to 20 concurrent requests              |


Gobuster can search for files that aren't linked from the website:
````
gobuster dir -u http://10.48.177.12:80 -w /usr/share/wordlists/seclists/Discovery/Web-Content/common.txt -x bak,txt -t 20
````
<img width="1418" height="756" alt="image" src="https://github.com/user-attachments/assets/7c1b42ac-1cef-4a22-8e87-0f12bd2d121d" />


A ``.bak`` file is especially interesting because it may contain an old configuration or source-code copy.

The application decides what each URL/route returns. Common security issues include:
- Debug endpoints being exposed
- Detailed error messages
- Exposed environment variables
- Accidentally exposed credentials

You would need shell access or a different route to reach it.
