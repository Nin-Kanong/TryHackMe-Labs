## Task 3: Viewing The Page Source

**Page Source** is the ``HTML/CSS/JavaScript`` code that the web server sends to your browser.

### 1. What is Page Source?

- Right‑click anywhere on the page → View Page Source, or
- Press Ctrl+U, or
- Type view-source: http://10.49.148.108/ in the address bar.

Think like:
````
Website
   │
   │ HTTP Request
   ▼
Web Server
   │
   │ HTML + CSS + JavaScript
   ▼
Browser
   │
   ▼
🌐 Website
````

The browser uses the returned code to know:
- What text to display
- What images to show
- What links exist
- What CSS to use
- What JavaScript to execute
- How the page is structured

### Summary:

What is the debugger useful for?

The Debugger lets we pause JavaScript while it is running so you can see what the code is doing at that exact moment.

````
flash.min.js
     ↓
line 110
     ↓
flash['remove']();
     ↓
🛑 Breakpoint
     ↓
JavaScript paused
````

Because execution is paused before 
````
flash['remove']()
````
runs, the red box stays on the screen and reveals.

#### Useful: 
| Use                             | What it helps you do                                      |
| ------------------------------- | --------------------------------------------------------- |
| 🐞 Debug JavaScript             | Understand how a web app works                            |
| ⏸️ Breakpoints                  | Stop code at an important point                           |
| 🔍 Inspect variables            | See values while the program runs                         |
| 🔎 Find hidden behavior         | See what JavaScript changes/hides                         |
| 🧪 Understand client-side logic | Learn how browser-side controls work                      |
| 🕵️ Investigate web apps        | Understand application behavior during authorized testing |

#### Cookie security flags
| Flag                  | Meaning                                      |
| --------------------- | -------------------------------------------- |
| **HttpOnly**          | JavaScript cannot normally access the cookie |
| **Secure**            | Cookie should only be sent over HTTPS        |
| **SameSite**          | Helps protect against CSRF                   |
| **Expires / Max-Age** | Controls how long the cookie lasts           |

---

### Summary:

| Item                  | Short Meaning                               | Security Importance                       |
| --------------------- | ------------------------------------------- | ----------------------------------------- |
| **Storage**           | Data saved by a website in your browser     | Can reveal useful application information |
| 🍪 **Cookies**        | Stores session/authentication data          | Very important for session security       |
| 💾 **Local Storage**  | Stores data persistently                    | May contain user/preferences/app data     |
| ⏳ **Session Storage** | Stores temporary data for a tab/session     | Useful for understanding session behavior |
| 📦 **Cache Storage**  | Stores cached files/resources               | May reveal cached application resources   |
| 🗄️ **IndexedDB**     | Stores larger structured browser data       | Can contain application data              |
| **HttpOnly**          | Prevents normal JavaScript access to cookie | Helps reduce cookie theft through XSS     |
| **Secure**            | Cookie sent only over HTTPS                 | Protects cookie in transit                |
| **SameSite**          | Controls cross-site cookie sending          | Helps reduce CSRF                         |
| **Session cookie**    | Identifies your current browser session     | Important for authentication              |


> **Note**: Storage lets you inspect data the website stores in your browser, especially cookies used for sessions and authentication.
