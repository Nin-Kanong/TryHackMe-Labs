### Getting Admin flag:

#### Vulnerable Merge
The lab's vulnerable function works conceptually like this:
````
function merge(target, source) {
    for (let key in source) {
        if (typeof source[key] === 'object' && source[key] !== null) {
            if (!target[key]) target[key] = {};
            merge(target[key], source[key]);
        } else {
            target[key] = source[key];
        }
    }
    return target;
}
````
The problem is that it does not safely handle special prototype-related properties.
````
No protection for dangerous prototype properties
````

##### What it does

The function takes:
````
target
source
````
and copies the properties from ``source`` into ``target``.

For normal data:
````
source
 |
 +-- name
 +-- email
````
the function copies those values into the target object.


- The Important Problem: ``__proto__``:
The lesson uses this payload:
````
{"__proto__":{"isAdmin":true}}
````
The function sees:
````
key = "__proto__"
````
and checks:
````
typeof source[key] === 'object'
````
Because the value is an object:
````
__proto__
   |
   +-- isAdmin: true
````
the function calls itself again:
````
merge(target[key], source[key]);
````
The important part is:
````
target["__proto__"]
        ↓
Object.prototype
````
So the recursive merge writes:
````
Object.prototype.isAdmin = true
````

## Task 3: React / Next.js


### Stack Identity
``Next.js`` is a React framework used for production web applications.
````
Next.js
   ↓
React
   ↓
Node.js
````
``Next.js`` uses the ``App Router`` and React Server Components.

Important CVEs:
- ``CVE-2025-29927`` — Middleware Bypass
- ``CVE-2025-55182`` — React Server Components / Flight Protocol issue

> Both CVEs apply to production build mode. They do not manifest in development mode.

> **Note**: Both ``CVE-2025-29927`` and ``CVE-2025-55182`` affect Next.js apps in production build mode (npm run build && npm start). They do not manifest in development mode (next dev). If fingerprinting confirms a development server, neither CVE applies.

### React Server Components and Flight Protocol
The App Router can run React components on the server.
````
React Component
      ↓
   Next.js
      ↓
RSC Flight Protocol
      ↓
   Browser
````

The Flight protocol is the communication format used to stream React Server Component results to the client.


> **RSC = React Server Components**

### CVE-2025-29927: Middleware Bypass
Middleware runs before the request reaches the page.
````
Request
   ↓
Middleware
   ↓
Authentication check
   ↓
Page
````

````
/dashboard
    ↓

    ↓
Valid session?
    ↓
    No
    ↓
/login
````

The flaw was that ``Next.js`` did not properly verify whether the header came from an internal request or an external client.

### 4. CVE-2021-35042: The Vulnerability

#### Where is the problem?
The application takes the value from:
````
/products/?order=YOUR_INPUT
````
and puts it directly into SQL:  
````
order = self.request.GET.get('order', 'name')
sql = (
    'SELECT id, name, price, description FROM products_product '
    f'ORDER BY (CASE WHEN (1=1) THEN {order} ELSE name END)'
)
````

The problem is:
````
User input
    ↓
order parameter
    ↓
SQL query
    ↓
No validation
    ↓
SQL Injection
````

#### Why does CASE WHEN matter?
In this path:
````
CASE WHEN (1=1) THEN {order} ELSE name END
````
Mean:
````
1 = 1
 ↓
TRUE
 ↓
use {order}
````
So whatever is supplied in ``order`` reaches the SQL ``THEN`` section.

| Item                  | Easy meaning                              |
| --------------------- | ----------------------------------------- |
| **Target**            | `/products/?order=`                       |
| **Problem**           | `order` input goes directly into SQL      |
| **Vulnerability**     | SQL Injection                             |
| **`CASE WHEN (1=1)`** | Always TRUE → uses the `order` value      |
| **`updatexml()`**     | Forces a MySQL error containing data      |
| **`0x7e`**            | `~` marker for identifying extracted data |
| **Django DEBUG=True** | Shows detailed database errors            |
| **Database**          | MySQL                                     |
| **CVE**               | **CVE-2021-35042**                        |


> **Note**: Warning: The ``updatexml()`` technique only works when ``DEBUG = True`` is set in ``settings.py``. A production app with ``DEBUG = False`` returns a generic 500 page with no error details. In this lab, the debug setting is on, but on a real engagement, verify this first. If debug output is suppressed, blind time-based injection using ``SLEEP()`` is the fallback.

### 3. CVE-2021-41773: The Vulnerability

``Apache 2.4.49`` has a path-traversal problem in ``ap_normalize_path()``.


Normally Apache blocks:
````
../
````
But:
````
.%2e/
````
can bypass the filter because ``%2e`` represents ``.``.

Flow:
````
Apache 2.4.49
      ↓
Path traversal filter
      ↓
.%2e/  ← filter doesn't recognize as ../
      ↓
Filesystem sees it as ../
      ↓
Path traversal
````


#### Why mod_cgi Matters

Path traversal alone can read files.

But the screenshot shows ``mod_cgi`` enabled on:
````
/cgi-bin/
````
If traversal reaches:
````
/bin/sh
````
Apache can execute it as a CGI program.

````
/cgi-bin/
    ↓
.%2e/
    ↓
.%2e/
    ↓
.%2e/
    ↓
.%2e/
    ↓
/bin/sh
    ↓
Command execution
````

#### Why --path-as-is Is Required
``curl`` normally cleans/normalizes URLs.

Without:
````
--path-as-is
````
the encoded traversal may be changed before it reaches Apache.

With it:
````
curl --path-as-is ...
````
``curl`` sends the path exactly as written.



### 4. Exploitation

````
mod_cgi

/cgi-bin/
````
