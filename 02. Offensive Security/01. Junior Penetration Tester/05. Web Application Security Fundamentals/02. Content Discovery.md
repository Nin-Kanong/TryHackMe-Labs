## Task 1: Introduction

This room is about **finding hidden or unlinked content on a web application**.

### 1. What is Content Discovery?

**Content discovery** means finding web resources that exist on a server but aren't obvious from the normal website.

Example:
````
🌐 Website
 ├── /admin
 ├── /backup
 ├── /old-site
 ├── /config
 ├── /uploads
 └── /hidden-page
````


### Learning Objectives

| # | Objective        | What it means                                                                                            |
| - | ---------------- | -------------------------------------------------------------------------------------------------------- |
| 1 | Manual Discovery | Find hidden content using `robots.txt`, `sitemap.xml`, favicons, HTTP headers, and framework information |
| 2 | OSINT            | Use public sources such as Google Dorking, Wayback Machine, GitHub, and S3                               |
| 3 | Gobuster         | Automatically discover directories, subdomains, and virtual hosts                                        |
| 4 | Methodology      | Follow an organized process during a penetration test                                                    |

## Task 2: Manual Discovery: Common Files

This section is teaching us two important files used during web reconnaissance:



### 1. robots.txt

Go to:
````
http://MACHINE_IP/robots.txt
````

Example:
````
http://10.49.128.25/robots.txt
````
<img width="756" height="293" alt="image" src="https://github.com/user-attachments/assets/a2de225b-3f78-4045-bb7a-2885440bb74b" />

| Part                      | Meaning                                   |
| ------------------------- | ----------------------------------------- |
| `User-agent: *`           | Applies to all crawlers                   |
| `Allow: /`                | Crawlers can access the site              |
| `Disallow: /staff-portal` | Crawlers are asked not to index this path |

> Disallow ≠ Protected



### 2. sitemap.xml

Go to:
````
http://MACHINE_IP/sitemap.xml
````

Example:
````
http://10.49.128.25/sitemap.xml
````
<img width="1265" height="927" alt="image" src="https://github.com/user-attachments/assets/fbaba177-10a2-4895-bced-e196a7bcf87f" />

| Found                | Why useful               |
| -------------------- | ------------------------ |
| `/news`              | Discover page            |
| `/contact`           | Discover page            |
| `/news/article?id=1` | Shows an input parameter |
| `/customers/login`   | Login endpoint           |
| `/s3cr3t-area`       | Interesting hidden path  |


#### Flow:
````
Target Website
      |
      +-- robots.txt
      |      |
      |      +-- Find paths developers don't want crawlers to visit
      |
      +-- sitemap.xml
             |
             +-- Find URLs/endpoints listed by the website
````

## Task 3: Manual Discovery: Headers & Framework Stack


### 1. HTTP Headers

#### Syntax:
````
curl http://MACHINE_IP -v
````
The ``-v`` means verbose, so curl shows the HTTP response headers.

Example:
````
curl http://10.49.128.25 -v
````
<img width="1463" height="1015" alt="image" src="https://github.com/user-attachments/assets/20ea6c52-5b03-495b-b692-dae6d67590ce" />

| Header         | What it tells you                                           |
| -------------- | ----------------------------------------------------------- |
| `Server`       | Web server software/version                                 |
| `X-Powered-By` | Application/framework information                           |
| `Content-Type` | Type of returned content                                    |
| `Set-Cookie`   | Cookies created by the server                               |
| Custom headers | May contain application information or, in this lab, a flag |

## Task 4: OSINT: Search Engines & Web Tools
This task introduces OSINT (Open-Source Intelligence) for discovering information about a target website.


### 1. Google Hacking / Dorking

Google search operators let we make more specific searches.

| Operator    | Example               | Meaning                              |
| ----------- | --------------------- | ------------------------------------ |
| `site:`     | `site:tryhackme.com`  | Search only one domain               |
| `inurl:`    | `inurl:admin`         | Find pages with `admin` in the URL   |
| `filetype:` | `filetype:pdf`        | Find a specific file type            |
| `intitle:`  | `intitle:admin`       | Find pages with `admin` in the title |
| `intext:`   | `intext:password`     | Find pages containing a word         |
| `cache:`    | `cache:tryhackme.com` | Search Google's cached version       |

Example:
````
site:tryhackme.com filetype:pdf
````

## Task 5: OSINT: Repositories & Archives

This task covers 3 important OSINT sources:
| Source              | What it is                          | What you can discover                         |
| ------------------- | ----------------------------------- | --------------------------------------------- |
| **Wayback Machine** | Archive of old versions of websites | Old pages, old login forms, removed APIs      |
| **GitHub**          | Platform for Git repositories       | Source code, old commits, configuration files |
| **S3 Buckets**      | Cloud storage                       | Publicly exposed files and website assets     |



### 1. Wayback Machine
Source: https://web.archive.org/

The Wayback Machine stores historical snapshots of websites.
````
Current Website
      ↓
Wayback Machine
      ↓
Older snapshots
      ↓
Old / removed content
````

Useful for finding:
- Old login pages
- Removed endpoints
- Old APIs
- Previous versions of a website


### 2. GitHub

Source: https://git-scm.com/

GitHub stores Git repositories and their history.

Important point from the task:

> Don't only look at the current files. Check the commit history.

For example:
````
Repository
    |
    +-- Current files
    |
    +-- Commit history
           |
           +-- Old configuration
           +-- Removed files
           +-- Previous code
````
Potentially sensitive items mentioned in the task:

| Item          | Example           |
| ------------- | ----------------- |
| API keys      | `API_KEY=...`     |
| Credentials   | Username/password |
| Configuration | `.env`            |
| Secrets       | Tokens            |



### 3. S3 Buckets

Source: https://aws.amazon.com/pm/serv-s3/

Amazon S3 is cloud storage used for files and static website content.

The task gives this general URL pattern:
````
https://{name}.s3.amazonaws.com
````
Common naming patterns:
````
{company}-assets
{company}-backup
{company}-www
{company}-dev
````
