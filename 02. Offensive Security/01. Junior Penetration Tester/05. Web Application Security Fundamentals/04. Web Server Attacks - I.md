- Identify debug endpoints, verbose errors, and environment-variable exposure in Node.js Express.
- Detect Nginx autoindex directories and exposed ``nginx_status``.
- Perform security-header auditing using ``curl`` and ``nikto``.

The server exposes the **entire directory where the command was run**.

For example:
````

│
├── .env
├── backup.zip
├── config.txt
└── notes.txt
````

If we run:
````
python3 -m http.server 8000
````
those files can become accessible through:
````
http://TARGET:8000/
````
Unlike Apache/Nginx, Python's simple HTTP server doesn't provide the same access-control/configuration features.

### 3. The mod_status Page

#### /server-status 

Try:
````
http://10.48.177.12/server-status
````
<img width="1919" height="1021" alt="image" src="https://github.com/user-attachments/assets/559d44f0-6c9b-4cca-8269-2e236ac8ce2a" />


Normally this page should be restricted to localhost/internal users. An incorrectly configured ``Require all granted`` can expose it.

> **Info**: ``mod_status`` is enabled by default on Ubuntu's **Apache** package and ships with a ``Require local`` restriction in ``conf-available/security.conf``. However, a ``Require all granted`` directive anywhere in a virtual host configuration silently overrides that restriction, exposing ``/server-status`` to all IPs without touching the module config. Always check /server-status even on servers that appear to be using default settings.

### 4. Find Unlinked Files

#### Command Syntax:
````
gobuster dir -u http://TARGET_IP:80 -w /usr/share/wordlists/SecLists/Discovery/Web-Content/common.txt -x bak,txt,html -t 20
````

| Part                  | Meaning      | Explanation                                    |
| --------------------- | ------------ | ---------------------------------------------- |
| `gobuster`            | Tool         | Used to discover hidden directories and files  |
| `dir`                 | Mode         | Directory/file enumeration mode                |
| `-u`                  | URL          | Specifies the target website                   |
| `http://TARGET_IP:80` | Target       | Web server running on port `80`                |
| `-w`                  | Wordlist     | Specifies the wordlist to use                  |
| `common.txt`          | Wordlist     | Contains common directory/file names to test   |
| `-x`                  | Extensions   | Adds file extensions to each word              |
| `bak`                 | Extension    | Searches for backup files such as `config.bak` |
| `txt`                 | Extension    | Searches for text files such as `notes.txt`    |
| `html`                | Extension    | Searches for HTML files such as `admin.html`   |
| `-t`                  | Threads      | Controls how many requests run concurrently    |
| `20`                  | Thread count | Runs up to 20 concurrent requests              |


Gobuster can search for files that aren't linked from the website:
````
gobuster dir -u http://10.48.177.12:80 -w /usr/share/wordlists/seclists/Discovery/Web-Content/common.txt -x bak,txt -t 20
````

### 4. Directory Listing with Autoindex

#### What is autoindex?

``autoindex on;`` tells Nginx:

> If someone visits a directory, show them the files inside it.

Example configuration:
````
location /files/ {
    autoindex on;
    root /var/www/nginx/;
}
````
| Configuration          | Meaning                              |
| ---------------------- | ------------------------------------ |
| `location /files/`     | Handles requests to `/files/`        |
| `autoindex on`         | Enable directory listing             |
| `root /var/www/nginx/` | Files are served from this directory |

> Normally, Nginx does not show a directory's contents automatically.

##Task 7: Common Misconfigurations
This task is about checking ``security headers`` and using ``Nikto`` to quickly identify common web-server misconfigurations.


**Security headers** are HTTP response headers that tell the browser how it should handle website content.

They help protect against attacks such as clickjacking, MIME sniffing, and XSS.

| Header                        | What it protects against                                                       | Example value                   |
| ----------------------------- | ------------------------------------------------------------------------------ | ------------------------------- |
| **X-Frame-Options**           | Clickjacking — prevents the page from being embedded in an iframe              | `DENY` / `SAMEORIGIN`           |
| **X-Content-Type-Options**    | MIME sniffing — prevents the browser from guessing content types               | `nosniff`                       |
| **Content-Security-Policy**   | Controls where scripts, stylesheets, images, and other resources can load from | `default-src 'self'`            |
| **Referrer-Policy**           | Controls what information is sent in the `Referer` header                      | `no-referrer` / `strict-origin` |
| **Strict-Transport-Security** | Forces browsers to use HTTPS for future requests                               | `max-age=31536000`              |



Audit each server with ``curl``:
````
for port in 80 8000 3000 8080; do echo "=== Port $port ==="; curl -sI http://10.49.164.138:$port/ | grep -iE "x-frame-options|x-content-type|content-security-policy|strict-transport|referrer-policy" || echo "(no security headers found)"; done
````
<img width="1908" height="276" alt="image" src="https://github.com/user-attachments/assets/808cb887-dffe-4f92-b069-c5510e45b648" />


| Part                      | Meaning                            |
| ------------------------- | ---------------------------------- |
| `for port in ...`         | Tests all four web servers         |
| `curl -sI`                | Requests HTTP headers only         |
| `grep -iE`                | Searches for security-header names |
| `x-frame`                 | Clickjacking protection            |
| `x-content-type`          | MIME-sniffing protection           |
| `content-security-policy` | Restricts resource/script sources  |
| `referrer-policy`         | Controls Referrer information      |
| `strict-transport`        | HSTS / forces HTTPS                |


> **Note**: HSTS (``Strict-Transport-Security``) is only meaningful over HTTPS, so its absence on these HTTP services isn't necessarily a vulnerability.


### 2. Understand the Important Headers

### 3. Automated Scanning with Nikto

Instead of manually checking everything, Nikto can perform a quick web-server audit.

For Apache:
````

````

This section is describing how to use Nikto to scan a web server for common misconfigurations and known web-server issues.

| Option / Term            | Meaning                                               |
| ------------------------ | ----------------------------------------------------- |
| `nikto`                  | Web server vulnerability scanner                      |
| `-h TARGET`              | Specifies the target host                             |
| `-nointeractive`         | Runs without stopping to ask for user input           |
| `-Tuning 123`            | Restricts the scan to selected Nikto check categories |
| `+`                      | Nikto commonly prefixes findings with `+`             |
| `/server-status`         | Apache status page that may expose server information |
| `backup.bak`             | Potentially exposed backup file                       |
| `/files/`                | Potential directory listing                           |
| Missing security headers | HTTP responses lack recommended security headers      |


What these findings mean
````
Apache version
      ↓
Technology fingerprint

/server-status
      ↓
Exposed server statistics

/files/
      ↓
Directory listing

/backup.bak
      ↓
Potentially sensitive backup
````

> **Tip**: Nikto's output can be verbose. The ``-Tuning`` option lets we restrict which checks it runs. For a quick scan, ``nikto -h TARGET -Tuning 123`` covers the most common findings without running the full signature set. Note that tuning codes are concatenated, not comma-separated.

#### What -Tuning 123 means
````
nikto -h TARGET -Tuning 123
````
| Value | Idea                             |
| ----- | -------------------------------- |
| `1`   | Interesting/common files         |
| `2`   | Misconfiguration / default files |
| `3`   | Information disclosure           |


So:
````
-Tuning 123
       │││
       ││└── Category 3
       │└─── Category 2
       └──── Category 1
````
