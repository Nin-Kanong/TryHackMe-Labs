## Task 3: Privilege Escalation: Public Exploits


### Public Exploits 
**Public exploit** means exploit code or a technique that has been publicly published to take advantage of a known software vulnerability.

- **Misconfiguration**: The software works correctly, but someone configured it insecurely.
- **Public exploit**: The software itself has a bug/vulnerability. Examples: Buffer overflow, race condition, logic error.
- **CVE**: A unique ID assigned to a known vulnerability.
- **Exploit**: Code or a technique that takes advantage of the vulnerability.


### Methodology
Don’t just download an exploit and run it. Follow a process first so we don’t use the wrong exploit, waste time, or crash the system.

| Step          | Easy Meaning                                                                               |
| ------------- | ------------------------------------------------------------------------------------------ |
| **Enumerate** | Find the software, versions, kernel, SUID files, and root services.                        |
| **Research**  | Search for CVEs and public exploits matching what you found.                               |
| **Evaluate**  | Check whether the exploit works with the target's version, architecture, and requirements. |
| **Exploit**   | Transfer, compile if needed, and run the exploit.                                          |
| **Verify**    | Check `whoami` and `id` to confirm you gained higher privileges.                           |


### Where to Find Public Exploits

There are several go-to resources for finding exploit code. You should be comfortable using all of them:

| Resource              | Easy Meaning                                                                       | Example                             |
| --------------------- | ---------------------------------------------------------------------------------- | ----------------------------------- |
| **searchsploit**      | A Kali command that searches the local Exploit-DB database for public exploits.    | `searchsploit <software> <version>` |
| **GitHub**            | A place where people publish exploit code for known CVEs.                          | Search `CVE-<id> github`            |
| **Enumeration Tools** | Tools like **LinPEAS** can find vulnerable software and often show the CVE number. | Find CVE → research the exploit     |

### The Polling Issue

**pspy** is a Linux process-monitoring tool that lets a normal user observe processes and commands running on the system, including short-lived processes such as cron jobs.

| Point                  | Meaning                                                       |
| ---------------------- | ------------------------------------------------------------- |
| **Normal enumeration** | Gives you a snapshot of the system                            |
| **Problem**            | Short-lived processes may start and finish too quickly to see |
| **pspy**               | Watches for processes and commands as they execute            |
| **Root required?**     | No                                                            |
| **Can see**            | Processes, cron jobs, and commands run by other users         |
| **Useful for**         | Finding hidden/scheduled activity during privilege escalation |

Source: https://github.com/dominicbreuker/pspy


### Event-driven Approach

pspy doesn't continuously ask “is there a new process?” Instead, it watches for activity and reacts when something happens.

| Concept                  | Meaning                                                                           |
| ------------------------ | --------------------------------------------------------------------------------- |
| **Polling**              | Repeatedly checking the system for processes                                      |
| **Problem with polling** | Very short processes may finish before the next check                             |
| **Event-driven**         | Waits for activity and reacts when it occurs                                      |
| **inotify**              | Watches filesystem activity in directories such as `/etc`, `/tmp`, `/usr`, `/var` |
| **`/proc`**              | Provides information about running processes                                      |
| **UID**                  | User who started the process                                                      |
| **PID**                  | Process ID                                                                        |
| **Timestamp**            | When the process started                                                          |
| **Full command**         | Exact command/process arguments                                                   |
| **Root required?**       | No                                                                                |

What ``UID=0`` means:

``UID=0`` means the process is running as root. Our output repeatedly shows ``/var/local/syslog-backup.sh`` being executed with UID 0.

How to identify the interesting process:
When using ``pspy``, look for:
| What we see                | Meaning                                                                 |
| --------------------------- | ----------------------------------------------------------------------- |
| `UID=0`                     | Process is running as root                                              |
| `/bin/bash /some/script.sh` | Root is executing a shell script                                        |
| Script appears repeatedly   | It is probably scheduled or running in a loop                           |
| Script is outside `/root`   | There is a chance you can inspect it                                    |
| Script is in `/root`        | Usually we cannot directly read it as `john`, so look at what it calls |


> Why we indentify it as interest?
>
> ``UID=0`` by itself does not mean the script is vulnerable. It only tells us that root is executing it. Your pspy output repeatedly shows root running /var/local/syslog-backup.sh

## Task 6: Conclusion 



| Topic                      | Remember                                                      |
| -------------------------- | ------------------------------------------------------------- |
| **Automated Enumeration**  | Quickly finds misconfigurations and vulnerable software.      |
| **LES**                    | Finds possible CVEs and public exploits.                      |
| **Public Exploit Method**  | **Enumerate → Research → Evaluate → Exploit → Verify**        |
| **pspy**                   | Watches processes, including short-lived processes.           |
| **`UID=0`**                | Means the process is running as root.                         |
| **Root + Writable Script** | If root executes a script you can modify, investigate it.     |
| **SUID**                   | Find privileged binaries with the SUID bit.                   |
| **Capabilities**           | Find binaries with special Linux capabilities.                |
| **Cron**                   | Check scheduled jobs running as root.                         |
| **Main Lesson**            | Automation finds the target; you must understand the finding. |


### Commands 

| Command                                       | Purpose                                          |
| --------------------------------------------- | ------------------------------------------------ |
| `./linux-exploit-suggester.sh`                | Find possible privilege-escalation exploits/CVEs |
| `searchsploit <software> <version>`           | Search public exploits                           |
| `scp <file> john@IP:/home/john/`              | Upload an exploit                                |
| `./pspy64`                                    | Monitor running processes                        |
| `sudo -l`                                     | Check sudo permissions                           |
| `find / -type f -perm -04000 -ls 2>/dev/null` | Find SUID files                                  |
| `getcap -r / 2>/dev/null`                     | Find capabilities                                |
| `cat /etc/crontab`                            | Check cron jobs                                  |
| `ls -la <file>`                               | Check ownership/permissions                      |
| `cat <file>`                                  | Read a script/configuration                      |
| `whoami`                                      | Check current user                               |
| `id`                                          | Check UID/GID                                    |
