## Task 1: Introduction

### What Does “Privilege Escalation” Mean?

**Privilege escalation** means going from a **normal/low-privileged user** to a **higher-privileged user**, usually ``root``.

``Low Privilege`` -> ``Find a weakness`` -> ``Exploit the weakness`` -> ``root``



### Why Is It Important?

Initial access usually gives us **limited permissions`**, not ``root``.

Getting higher privileges can allow us to:
| What we can gain     | Example                             |
| --------------------- | ----------------------------------- |
| **More access**       | Read protected files                |
| **Account control**   | Change passwords or user privileges |
| **System control**    | Modify software/configuration       |
| **Command execution** | Run administrative commands         |
| **Persistence**       | Maintain access to the system       |



The possible method depends on things like:
| Factor              | Example                              |
| ------------------- | ------------------------------------ |
| **Kernel**          | Vulnerable kernel version            |
| **Applications**    | Vulnerable or misconfigured software |
| **Configuration**   | Weak permissions or services         |
| **Credentials**     | Other users' passwords               |
| **Languages/Tools** | Python, Perl, etc. available         |



### Learning Objectives
- Understand the purpose and importance of enumeration in Linux privilege escalation
- Identify key OS information using manual enumeration commands
- Find hidden files
- Enumerate users, groups, and permissions on a Linux system
- Enumerate basic network information
- Discover potential privilege escalation vectors through manual enumeration

### Enumeration

**Enumeration** is one of the most important steps in Linux privilege escalation because you need to understand the system before trying to exploit it.


During enumeration, we collect information such as:
| What to Check              | Why                                          |
| -------------------------- | -------------------------------------------- |
| **Kernel version**         | Look for possible vulnerabilities            |
| **Installed applications** | Identify vulnerable or interesting software  |
| **User permissions**       | Understand what your account can do          |
| **Scheduled tasks**        | Find jobs running with higher privileges     |
| **Network configuration**  | See services, ports, and connections         |
| **System configuration**   | Find insecure settings and misconfigurations |

### The cron Service

``Cron`` is a Linux scheduler. It automatically runs a command or script at a specific time.


````
cat /etc/crontab
````
<img width="1276" height="587" alt="image" src="https://github.com/user-attachments/assets/e91937c9-5ec8-456d-8c23-5e69498f4d28" />


| Cron Entry        | Meaning                        |
| ----------------- | ------------------------------ |
| `*/5 * * * *`     | Runs **every 5 minutes**       |
| `root`            | Runs as the **root user**      |
| `/root/backup.sh` | Executes the **backup script** |


| Field               | Meaning                     | Example                      |
| ------------------- | --------------------------- | ---------------------------- |
| **1. Minute**       | When the job runs by minute | `30` = at minute 30          |
| **2. Hour**         | When the job runs by hour   | `2` = at 2 AM                |
| **3. Day of Month** | Which day of the month      | `*` = every day              |
| **4. Month**        | Which month                 | `*` = every month            |
| **5. Day of Week**  | Which day of the week       | `1` = Monday                 |
| **6. User**         | Who runs the task           | `root` = root                |
| **7. Command**      | What is executed            | `/home/ubuntu/clear-mail.sh` |


So in this:
````
*/5 * * * * root /root/backup.sh
````
It mean: `Every 5 minutes, Linux runs /root/backup.sh as root.`

Why this is important

For privilege-escalation enumeration, we now want to check the script and its permissions:
````
ls -l /root/backup.sh
````
Also check the directory:
````
ls -ld /root
````
The key question is: ``Cron job runs as root`` -> ``What script does it run?`` -> ``Who can modify that script?``

> Search from ``/`` for a file named ``flag.txt``.

search based on different properties:
| Command                       | Short Explanation                                                  |
| ----------------------------- | ------------------------------------------------------------------ |
| `find . -name flag1.txt`      | Finds `flag1.txt` in the **current directory and subdirectories**. |
