### Commnon network protocol

| Protocol    | Full Name                        | Default Port | Main Purpose            | Easy Meaning          |
| ----------- | -------------------------------- | -----------: | ----------------------- | --------------------- |
| 🌐 **HTTP** | Hypertext Transfer Protocol      |       **80** | Transfer web pages/data | Browse websites       |
| 📁 **FTP**  | File Transfer Protocol           |       **21** | Transfer files          | Upload/download files |
| 📥 **POP3** | Post Office Protocol v3          |      **110** | Retrieve email          | Download emails       |
| 📤 **SMTP** | Simple Mail Transfer Protocol    |       **25** | Send email              | Send emails           |
| 📬 **IMAP** | Internet Message Access Protocol |      **143** | Access/manage email     | Read & sync emails    |

#### Why learn them?
These protocols are important because we can communicate with services directly from a terminal, rather than only through a browser or email application.

<img width="1536" height="1024" alt="image" src="https://github.com/user-attachments/assets/fcbb7ba4-050d-4b00-9007-43a20b804bcd" />





### Security point
The basic versions can transmit information in cleartext, making sensitive data such as credentials vulnerable to interception.

| Unencrypted | Secure alternative |
| ----------- | ------------------ |
| HTTP        | **HTTPS**          |
| FTP         | **FTPS / SFTP**    |
| POP3        | **POP3S**          |
| SMTP        | **SMTP + TLS**     |
| IMAP        | **IMAPS**          |

## Task 2: Telnet

**Telnet** is an application-layer protocol used to remotely access and interact with another computer through a text-based terminal.

| Item                 | Telnet                              |
| -------------------- | ----------------------------------- |
| 📛 Protocol          | **Telnet**                          |
| 🔢 Default Port      | **TCP 23**                          |
| 🎯 Purpose           | Remote terminal access              |
| 🔐 Encryption        | ❌ None                              |
| 👤 Authentication    | Username + Password                 |
| ⚠️ Main weakness     | Everything travels in **cleartext** |
| ✅ Secure replacement | **SSH (Secure Shell)**              |

## Task 3: Hypertext Transfer Protocol (HTTP)

<img width="1200" height="800" alt="image" src="https://github.com/user-attachments/assets/b904630e-7973-4068-925b-c61802c506a6" />


### HTTP:

| Topic              | Meaning                                            |
| ------------------ | -------------------------------------------------- |
| **HTTP**           | Hypertext Transfer Protocol                        |
| **Purpose**        | Transfer web pages/files between client and server |
| **Default port**   | TCP **80**                                         |
| **Security**       | ❌ Cleartext / no encryption                        |
| **Secure version** | HTTPS                                              |
| **HTTPS port**     | TCP **443**                                        |
| **Client**         | Browser, `curl`, Telnet, Netcat                    |
| **Server**         | Nginx, Apache, IIS, etc.                           |


### HTTP vs HTTPS
| HTTP                               | HTTPS                             |
| ---------------------------------- | --------------------------------- |
| 🔓 Not encrypted                   | 🔒 Encrypted with TLS             |
| Data sent as cleartext             | Data protected in transit         |
| Usually port **80**                | Usually port **443**              |
| Browser may show **Not Secure**    | Browser shows a secure connection |
| Traffic can be read if intercepted | Intercepted traffic is encrypted  |

### Web Server vs Web Client
````
CLIENT                         SERVER
──────                         ──────
Chrome                         Nginx
Firefox       ← HTTP →         Apache
Edge                           IIS
Safari                         Caddy
                               Node.js
````
| Type               | Examples                      | Job                  |
| ------------------ | ----------------------------- | -------------------- |
| 🖥️ **Web Client** | Chrome, Firefox, Edge, Safari | Requests web content |
| 🌐 **Web Server**  | Nginx, Apache, IIS            | Provides web content |

> Client asks → Server answers


### 3. HTTP Versions
| Version      | Transport     | Main feature                      | Easy meaning     |
| ------------ | ------------- | --------------------------------- | ---------------- |
| **HTTP/1.1** | TCP           | Human-readable text               | Traditional HTTP |
| **HTTP/2**   | TCP           | Multiplexing + header compression | Faster HTTP      |
| **HTTP/3**   | QUIC over UDP | Improved latency/performance      | Modern HTTP      |


#### HTTP/1.1

This is what you just manually tested:
````
GET /index.html HTTP/1.1
Host: telnet
````

Because HTTP/1.1 is text-based, it's easy to learn and manually interact with using tools such as Telnet or Netcat.

#### HTTP/2
````
HTTP/1.1
Request ──►
Response ◄──
Request ──►
Response ◄──

HTTP/2
Request 1 ──►
Request 2 ──►
Request 3 ──►
Responses ◄──
````
It supports multiplexing, allowing multiple streams over one connection.

#### HTTP/3
````
HTTP/1.1 → TCP
HTTP/2   → TCP
HTTP/3   → QUIC over UDP
````

## Task 4: File Transfer Protocol (FTP)

**FTP = File Transfer Protocol**

It is used to upload and download files between a client and server.

| Item                | FTP                    |
| ------------------- | ---------------------- |
| Full name           | File Transfer Protocol |
| Main port           | TCP **21**             |
| Purpose             | Transfer files         |
| Encryption          | ❌ No — cleartext       |
| Secure alternatives | **SFTP / FTPS**        |




### How FTP Works
FTP normally uses separate connections for commands and **file/data** transfer.

<img width="650" height="800" alt="image" src="https://github.com/user-attachments/assets/1a6d2a6d-7a46-4d1c-a9f4-baceb56c1038" />

> Port 21 = control/commands
> Data connection = files

<img width="1200" height="592" alt="image" src="https://github.com/user-attachments/assets/87f2af94-6ae6-4920-ae3d-5a9ede2be851" />

| Step             | FTP Command | Example         | Server Response                    | Meaning                                  |
| ---------------- | ----------- | --------------- | ---------------------------------- | ---------------------------------------- |
| **2️⃣ Username** | `USER`      | `USER frank`    | `331 Please specify the password.` | Username accepted → password required    |
| **3️⃣ Password** | `PASS`      | `PASS D2xc9CgD` | `230 Login successful.`*           | Sends password → login succeeds if valid |

* `230 Login successful` is a common successful FTP response; the exact server response can vary.

## Task 6: POP3

**POP3 (Post Office Protocol v3) is used to receive/download emails from a mail server to your device.**

<img width="1200" height="800" alt="image" src="https://github.com/user-attachments/assets/96d8c12e-febe-409c-97da-b3eb24765bb6" />

#### POP3 Ports
|    Port | Security               | Meaning |
| ------: | ---------------------- | ------- |
| **110** | ❌ Cleartext by default | POP3    |
| **995** | 🔒 TLS                 | POP3S   |

| Protocol    | Main Purpose                 | Direction                              | Common Ports       |
| ----------- | ---------------------------- | -------------------------------------- | ------------------ |
| 📤 **SMTP** | **Send email**               | Client → Mail Server / Server → Server | `25`, `587`, `465` |
| 📥 **POP3** | **Receive / download email** | Mail Server → Client                   | `110`, `995` 🔒    |

#### Common POP3 Commands
| Command         | Easy Meaning               |
| --------------- | -------------------------- |
| `USER frank`    | Username                   |

| `STAT`          | Number/size of emails      |
| `LIST`          | List emails                |

### How POP3 Works
````
POP3 Server
     │
     │ Authenticate
     ▼
 USER + PASS
     │
     ▼
 LIST Emails
     │
     ▼
 RETR Email
     │
     ▼
📥 Download to Device
````

Traditionally, POP3 follows a download-and-delete style, although clients can be configured to leave copies on the server.


### POP3 vs IMAP
| POP3                            | IMAP                      |
| ------------------------------- | ------------------------- |

## Task 7: IMAP

**IMAP (Internet Message Access Protocol)** is used to access and synchronize email while keeping messages on the mail server.
````
Mail Server
    │
    │ IMAP
    ▼
📱 Phone
💻 Laptop
🖥️ PC
    ↕
All stay synchronized
````


#### IMAP Ports
|    Port | Security                                 | Meaning |
| ------: | ---------------------------------------- | ------- |
| **143** | ⚠️ Cleartext / can upgrade with STARTTLS | IMAP    |
| **993** | 🔒 TLS                                   | IMAPS   |

> **Note**: ``143`` = IMAP, ``993`` = Secure IMAP.



### Manual IMAP with Telnet
````
telnet 10.48.160.16 143
````
<img width="1922" height="725" alt="image" src="https://github.com/user-attachments/assets/c11495f0-c5a7-4b4a-a0a7-2d5b315eeb04" />


Unlike POP3, IMAP commands need a tag such as ``c1``, ``c2``, ``c3``.

| Step            | IMAP Command              | Purpose                  |
| --------------- | ------------------------- | ------------------------ |
| 👤 Login        | `c1 LOGIN frank D2xc9CgD` | Authenticate as `frank`  |

#### Common IMAP Commands
| Command           | Easy Meaning             |
| ----------------- | ------------------------ |
| `LOGIN user pass` | 🔑 Login                 |
| `LIST "" "*"`     | 📁 List folders          |
| `SELECT INBOX`    | 📬 Open inbox read/write |
| `EXAMINE INBOX`   | 👀 Open inbox read-only  |
| `FETCH 1 BODY[]`  | 📧 Read email #1         |
| `SEARCH ALL`      | 🔎 Find/list messages    |
| `STORE`           | ✏️ Change message flags  |
| `LOGOUT`          | 🚪 Exit                  |


### POP3 vs IMAP

| POP3                   | IMAP                     |
| ---------------------- | ------------------------ |
| 📥 Downloads email     | ☁️ Keeps email on server |
| Mainly local copy      | Server copy              |
| Poor multi-device sync | 🔄 Multi-device sync     |
| Port `110`             | Port `143`               |
| Secure `995`           | Secure `993`             |

## Task 8: Summary

### Key Takeaways

All protocols covered here use cleartext by default, meaning usernames, passwords, emails, and transferred data can potentially be captured from network traffic.

Telnet can also be used as a simple testing client to manually communicate with text-based TCP services such as HTTP, FTP, SMTP, POP3, and IMAP.


### Protocol Reference
| Protocol   |  Port | Purpose               | Secure Alternative |   Secure Port |
| ---------- | ----: | --------------------- | ------------------ | ------------: |
| **FTP**    |  `21` | File transfer         | FTPS / SFTP        |  `990` / `22` |
| **HTTP**   |  `80` | Web browsing          | HTTPS              |         `443` |
| **IMAP**   | `143` | Email synchronization | IMAPS              |         `993` |
| **POP3**   | `110` | Download email        | POP3S              |         `995` |
| **SMTP**   |  `25` | Send email            | SMTPS / STARTTLS   | `465` / `587` |
| **Telnet** |  `23` | Remote terminal       | SSH                |          `22` |
