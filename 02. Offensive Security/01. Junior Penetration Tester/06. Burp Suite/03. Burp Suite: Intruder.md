## Task 2: What is Intruder


### What is Intruder?
**Burp Suite Intruder** is a tool used to **automatically modify and resend HTTP requests** with different input values.


It is useful for:

- Brute-forcing login forms
- Fuzzing parameters
- Finding hidden directories/files
- Testing application inputs
- Sending many variations of the same request

Intruder works similarly to tools such as ffuf and wfuzz, but it is integrated directly into Burp Suite.

### The 4 Main Intruder Tabs

#### 1. 1. Positions

The Positions tab controls **where the payload will be inserted**.

For example:
````
GET /products/1 HTTP/1.1
````
Select 1 as the position:
````
GET /products/§1§ HTTP/1.1
````
``§ §`` means:

> "Put payloads here."

We can also choose the Attack type here.



#### 2. Payloads

The **Payloads** tab controls what values will be inserted into the positions.

Example wordlist:
````
admin
user
test
guest
````
Intruder will automatically substitute each value into:
````
GET /login?username=§admin§
GET /login?username=§user§
GET /login?username=§test§
GET /login?username=§guest§
````
We can also configure payload processing, such as:

- Prefix/suffix
- Encoding
- Payload filtering


#### 3. Resource Pool

The **Resource Pool** controls how Burp allocates resources to automated tasks.

For the Community Edition, this section is less important because Intruder is rate-limited.

#### 4. Settings

The **Settings** tab controls how the attack behaves.

For example, you can configure how Burp handles:
- Redirects
- Results
- Response matching
- Attack behavior

## Task 3: Positions

The **Positions** tab is where you tell Burp Intruder which part of the request should be changed by the payloads.


### What is a Payload Position?

A payload position is marked with:
````
§value§
````
Everything between § marks is where Intruder will insert different payloads.

For example:
````
username=§Pentester§&password=Exploit3d
````
Intruder will replace ``Pentester`` with values from OUR payload list.

| **Clear §**           | Remove all selected payload positions               |
| **Auto §**            | Automatically detect likely payload positions       |
| **Refresh**           | Refresh the request/position information            |

## Task 5: Introduction to Attack Type

<img width="1145" height="727" alt="image" src="https://github.com/user-attachments/assets/ef9e1398-7a1f-4fe1-aa4a-9c708e30ce7d" />


| Attack Type          | How it works                                              | Best use                                                   |
| -------------------- | --------------------------------------------------------- | ---------------------------------------------------------- |
| **Sniper** 🎯        | Uses **one payload at a time** on each position           | Testing one parameter at a time                            |
| **Battering Ram** 🔨 | Uses the **same payload simultaneously** in all positions | Testing when the same value must appear in multiple places |
| **Pitchfork** 🍴     | Uses different payload lists **together, item-by-item**   | Testing multiple parameters with matching payload pairs    |
| **Cluster Bomb** 💣  | Tries **every combination** of payloads across positions  | Testing multiple parameters with many combinations         |


### 1. Sniper (Default)
How it works: Uses ONE payload set and tests ONE position at a time

Example: Testing a username field with 10 usernames
|  # | Request Username | Other Fields |
| -: | ---------------- | ------------ |
|  1 | `admin`          | Unchanged    |
|  2 | `user`           | Unchanged    |
|  3 | `test`           | Unchanged    |

When to use:
- Testing a single parameter (e.g., username, password)
- Fuzzing one input field
- Brute-forcing a single field

Best for: When you have ONE position and ONE payload list



### 2. Battering Ram
**How it works**: Uses ONE payload set but inserts SAME payload into ALL positions simultaneously

Example: Testing both username AND password fields with 10 payloads

| Request | Username | Password |
| ------: | -------- | -------- |
|       1 | `admin`  | `admin`  |
|       2 | `user`   | `user`   |
|       3 | `test`   | `test`   |

When to use:
- Testing race conditions
- When multiple parameters need the SAME value
- Testing for parameter duplication vulnerabilities

**Best for**: When you have MULTIPLE positions but ONE payload list (same value goes everywhere)



### 3. Pitchfork
How it works: Uses MULTIPLE payload sets (one per position) and pairs them together

Example: Testing username AND password with separate lists
| Request | Username (Set 1) | Password (Set 2) |
| ------: | ---------------- | ---------------- |
|       1 | `admin`          | `password123`    |
|       2 | `user`           | `qwerty`         |
|       3 | `test`           | `letmein`        |


When to use:
- Testing username/password combinations
- Testing pairs of parameters
- When different positions need DIFFERENT payload sets

Important: Stops when the SMALLEST payload set is exhausted

Best for: When you have MULTIPLE positions and MULTIPLE payload lists (different values for each)



### 4. Cluster Bomb
How it works: Uses MULTIPLE payload sets and tests ALL combinations (Cartesian product)

Example: Testing username AND password with 3 usernames × 3 passwords = 9 requests

| Request | Username (Set 1) | Password (Set 2) |
| ------: | ---------------- | ---------------- |
|       1 | `admin`          | `password123`    |
|       2 | `admin`          | `qwerty`         |
|       3 | `admin`          | `letmein`        |
|       4 | `user`           | `password123`    |
|       5 | `user`           | `qwerty`         |
|       6 | `user`           | `letmein`        |
|       7 | `test`           | `password123`    |
|       8 | `test`           | `qwerty`         |
|       9 | `test`           | `letmein`        |

When to use:
- Comprehensive testing of all parameter combinations
- When you need to test every possible combination
- Brute-forcing with multiple variables

Important: Can generate MANY requests (size1 × size2 × size3 × ...)

Best for: When you have MULTIPLE positions and want ALL combinations of payloads

## Task 6: Sniper

The **Sniper attack** type is the default and most commonly used attack type in Burp Suite Intruder.

It is particularly useful for **single-position attacks**, such as password brute-force or fuzzing API endpoints.


In a Sniper attack, we provide a set of payloads, which can be a wordlist or a range of numbers. Intruder inserts each payload into **each defined position in the request**.

````
POST /support/login/ HTTP/1.1
Host: 10.49.134.214
User-Agent: Mozilla/5.0 (X11; Ubuntu; Linux x86_64; rv:80.0) Gecko/20100101 Firefox/80.0
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8
Accept-Language: en-US,en;q=0.5
Accept-Encoding: gzip, deflate
Content-Type: application/x-www-form-urlencoded
Content-Length: 37
Origin: http://10.49.134.214
Connection: close
Referer: http://10.49.134.214/support/login/
Upgrade-Insecure-Requests: 1

username=§pentester§&password=§Expl01ted§
````

## Task 7: Battering Ram

The **Battering Ram** attack type in Burp Suite Intruder is different from **Sniper**.

The main difference is:
> Battering Ram puts the SAME payload into EVERY position at the same time.



#### Example Request
We have two positions:

````
username=Spntester&password=Exploited
        ↑                    ↑
     Position 1          Position 2
````
So:
````
Position 1 → username
Position 2 → password
````

````
POST /support/login/ HTTP/1.1
    Host: 10.49.134.214
    User-Agent: Mozilla/5.0 (X11; Ubuntu; Linux x86_64; rv:80.0) Gecko/20100101 Firefox/80.0
    Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8
    Accept-Language: en-US,en;q=0.5
    Accept-Encoding: gzip, deflate
    Content-Type: application/x-www-form-urlencoded
    Content-Length: 37
    Origin: http://10.49.134.214
    Connection: close
    Referer: http://10.49.134.214/support/login/
    Upgrade-Insecure-Requests: 1
    
    username=§pentester§&password=§Expl01ted§
````


Our wordlist contains: ``burp``, ``suite``, ``intruder``.



### Payload suite

Now it takes suite and puts it into **both positions**.
````
username=suite&password=suite
````

## Task 9 — Cluster Bomb

The **Cluster Bomb** attack is different from Pitchfork.

The main idea is:

> **Cluster Bomb tries EVERY possible combination of payloads.**

It can use a separate payload set for each position.

---

### 1. We have two positions

```
username=§Spntester§&password=§Exploited§
         ↑                         ↑
      Position 1               Position 2
```

So:

```
Position 1 → username
Position 2 → password
```

---

### 2. We have two wordlists

#### Username wordlist

```
joel
harriet
alex
```

#### Password wordlist

```
J031
Emma1815
Sk1ll
```

We **don't know which password belongs to which username**.

Therefore, we need to test **every combination**.

---

### 3. First password: `J031`

Burp tries `J031` with **every username**:

```
Request 1
username=joel&password=J031

Request 2
username=harriet&password=J031

Request 3
username=alex&password=J031
```

---

### 4. Second password: `Emma1815`

Now Burp tries `Emma1815` with every username:

```
Request 4
username=joel&password=Emma1815

Request 5
username=harriet&password=Emma1815

Request 6
username=alex&password=Emma1815
```

---

### 5. Third password: `Sk1ll`

Finally:

```
Request 7
username=joel&password=Sk1ll

Request 8
username=harriet&password=Sk1ll

Request 9
username=alex&password=Sk1ll
```

---

#### Complete Table

| Request | Username  | Password   |
| ------: | --------- | ---------- |
|       1 | `joel`    | `J031`     |
|       2 | `harriet` | `J031`     |
|       3 | `alex`    | `J031`     |
|       4 | `joel`    | `Emma1815` |
|       5 | `harriet` | `Emma1815` |
|       6 | `alex`    | `Emma1815` |
|       7 | `joel`    | `Sk1ll`    |
|       8 | `harriet` | `Sk1ll`    |
|       9 | `alex`    | `Sk1ll`    |

---

#### Why 9 Requests?

There are:

```
3 usernames
    ×
3 passwords
    =
9 requests
```

The important point is that **every username is tested with every password**.

<img width="1199" height="1312" alt="image" src="https://github.com/user-attachments/assets/75aa3048-6314-4b81-91c3-686747b61095" />

### Compare All 4 Attack Types

| Attack            | How it works                                    |
| ----------------- | ----------------------------------------------- |
| **Sniper**        | One payload set → tests positions one at a time |
| **Battering Ram** | One payload → inserted into all positions       |
| **Pitchfork**     | Multiple lists → matching items together        |
| **Cluster Bomb**  | Multiple lists → **every combination**          |

## Task 13: Conclusion


| Intruder Attack Type | What It Does                                                          | Example                                                           |
| -------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **Sniper**           | Tests **one position** with a payload list.                           | Test `username=§admin§` with many usernames.                      |
| **Battering Ram**    | Uses the **same payload** in multiple positions at the same time.     | `username=§test§&password=§test§`                                 |
| **Pitchfork**        | Uses multiple payload lists and pairs items **by position**.          | Username `admin` + Password `123`, then `user` + `456`.           |
| **Cluster Bomb**     | Uses multiple payload lists and tests **every possible combination**. | `admin` + `123`, `admin` + `456`, `user` + `123`, `user` + `456`. |
