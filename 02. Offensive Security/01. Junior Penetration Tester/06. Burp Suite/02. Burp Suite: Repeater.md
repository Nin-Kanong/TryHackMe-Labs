## Task 2: What is Repeater

**Burp Suite Repeater** allows us to take an HTTP request, modify it, resend it, and analyze the response repeatedly.

| # | Section                | What it does                                     |
| - | ---------------------- | ------------------------------------------------ |
| 1 | **Request List**       | Shows all requests currently in Repeater         |
| 2 | **Request Controls**   | Send, cancel, and navigate request history       |
| 3 | **Request & Response** | Edit the request and view the server response    |
| 4 | **Layout Options**     | Change how Request/Response panels are displayed |
| 5 | **Inspector**          | Easily view and modify request details           |
| 6 | **Target**             | Shows where the request will be sent             |

<img width="1283" height="829" alt="image" src="https://github.com/user-attachments/assets/8d3311ac-cfe4-4785-9287-fdda0c79fc1b" />

#### 1. Request List
- Located at the top-left.
- Stores multiple requests.
- Each request sent to Repeater appears here.

#### 2. Request Controls
- Located below the request list.
- Send → sends the request.
- Cancel → stops a request.
- History controls → move between previous requests.


#### 3. Request & Response View
- Request → edit the HTTP request.
- Response → see what the server returns.
- Useful for testing how changes affect the response.


#### 4. Layout Options

Controls how Request and Response are displayed:
- Side-by-side
- Vertical
- Separate tabs


#### 5. Inspector
- Located on the right side.
- Helps inspect and modify:
- Parameters
  - Cookies
  - Headers
  - Request body

## Task 5: Inspector

**Inspector** is a visual tool in Burp Suite that lets we can view and modify parts of HTTP requests without editing the raw request manually.

<img width="1912" height="1078" alt="image" src="https://github.com/user-attachments/assets/34223d1e-ec07-492f-b914-7d4ff5fd9b10" />

### 1. Request Attributes

Shows important request information:

| Attribute    | What you can do               |
| ------------ | ----------------------------- |
| **Protocol** | Switch HTTP/1.1 ↔ HTTP/2      |
| **Method**   | Change `GET`, `POST`, etc.    |
| **Path**     | Change the requested URL path |

Example:
````
GET /admin HTTP/1.1
````
we can change the path to:
````
GET /login HTTP/1.1
````


### 2. Request Query Parameters

Parameters contained in the URL.

Example:
````
https://example.com/?redirect=false
````

| Parameter  | Value   |
| ---------- | ------- |
| `redirect` | `false` |

We can **view, add, edit, or remove query parameters**.



### 3. Request Body Parameters

Parameters sent inside the request body, commonly with ``POST``.

Example:
````
POST /login HTTP/1.1

username=admin&password=test
````
Inspector lets you modify these parameters more easily.



### 4. Request Cookies

Shows cookies sent with the request.

Example:
````
Cookie: session=abc123
````
We can inspect and modify cookie values.



### 5. Request Headers

Shows headers sent to the server.

Example:
````
Host: example.com
User-Agent: Mozilla/5.0
Content-Type: application/json
````
We can add, edit, or remove request headers.

6. Response Headers

Shows headers returned by the server.

Example:
````
HTTP/1.1 200 OK
Content-Type: text/html
Server: nginx
````
 
> Response headers cannot be modified because they come from the server.



#### Summary:

| Section              | Remember                 |
| -------------------- | ------------------------ |
| **Attributes**       | Method + Path + Protocol |
| **Query Parameters** | URL data                 |
| **Body Parameters**  | POST/body data           |
| **Cookies**          | Session/browser data     |
| **Request Headers**  | Client → Server          |
| **Response Headers** | Server → Client          |

## Task 9: Conclusion

| #  | Topic                        | What We Learned                                                                                            |
| -- | ---------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1  | **What is Repeater?**        | Burp tool used to **edit, send, and resend HTTP requests** manually.                                       |
| 2  | **Capture Request**          | Capture a request in **Proxy → HTTP history** and send it to Repeater.                                     |
| 3  | **Send Request**             | Click **Send** to send the request and view the server response.                                           |
| 4  | **Modify Request**           | Change the **URL, parameters, headers, cookies, method**, etc., then resend.                               |

| 7  | **Non-printable Characters** | `\n` / `\r\n` can be displayed to understand HTTP formatting and headers.                                  |
| 8  | **Inspector**                | Provides an organized way to view/edit **parameters, cookies, headers, attributes**, etc.                  |
| 9  | **Request Attributes**       | Can inspect/change **method, path, and HTTP protocol**.                                                    |
| 10 | **Query Parameters**         | Parameters sent through the URL, e.g. `?id=1`.                                                             |
| 11 | **Body Parameters**          | Parameters contained in POST/other request bodies.                                                         |
| 12 | **Cookies**                  | View and modify cookies sent with requests.                                                                |
| 13 | **Headers**                  | Add, remove, or modify HTTP request headers.                                                               |
| 14 | **Practical Testing**        | Repeater is useful for repeatedly testing requests with small changes.                                     |

| 21 | **Main Skill**               | **Capture → Send to Repeater → Modify → Send → Analyze → Repeat**                                          |
