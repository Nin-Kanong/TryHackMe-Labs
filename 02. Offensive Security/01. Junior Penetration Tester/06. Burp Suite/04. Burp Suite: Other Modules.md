## Task 2: Decoder
The **Burp Suite Decoder** is used to **decode, encode, and hash data**.

### What do you put in Decoder?

We can paste something like:
````
Data
````
Then Burp gives you options for what we want to do with it.

| Option           | Simple meaning                              |
| ---------------- | ------------------------------------------- |
| **Decode**       | Turn encoded data back into readable data   |
| **Encode**       | Turn normal data into an encoded format     |
| **Hash**         | Create a one-way hash from the data         |
| **Smart decode** | Automatically try to decode multiple layers |

### 1. Encode

**Encode = make data look different for transmission or representation**.

Example:
````
Data
  ↓
URL Encode
  ↓
%44%61%74%61
````
The original text is still represented by the encoded value.


### 2. Decode

Decode = reverse an encoding.
````
%44%61%74%61
       ↓
   URL Decode
       ↓
      Data
````
So:
````
Encode → Data → Encoded Data
Decode → Encoded Data → Data
````




### 3. Hash

Hashing creates a fixed-value representation of the input.
````
Data
  ↓
MD5 / SHA-1 / SHA-256
  ↓
Hash value
````
Unlike normal encoding, hashing is not simply reversed with a Decode button.



### 4. Text vs Hex

The Text / Hex option tells Decoder how to interpret the input.

| Mode     | Meaning                              |
| -------- | ------------------------------------ |
| **Text** | Treat the input as normal text       |
| **Hex**  | Treat the input as hexadecimal bytes |



### 5. Smart Decode

**Smart Decode** is useful when data has been encoded multiple times.
````
Encoded data
     ↓
Smart Decode
     ↓
Decode layer 1
     ↓
Decode layer 2
     ↓
Readable data
````

## Task 3: Decoder: Encoding / Decoding


### 1. Encoding / Decoding options

| Option        | What it does                                 | Example                      |
| ------------- | -------------------------------------------- | ---------------------------- |
| **Plain**     | Original/raw text                            | `Data`                       |
| **URL**       | Converts characters to URL-safe encoding     | `/` → `%2F`                  |
| **HTML**      | Converts special characters to HTML entities | `"` → `&quot;`               |
| **Base64**    | Converts data to Base64                      | `Data` → `RGF0YQ==`          |
| **ASCII Hex** | Converts text to hexadecimal                 | `ASCII` → hex representation |
| **Hex**       | Works with hexadecimal data                  | `41` → `A`                   |
| **Octal**     | Represents numbers in base 8                 | Decimal → Octal              |
| **Binary**    | Represents data using `0` and `1`            | `A` → binary                 |
| **Gzip**      | Compresses/decompresses data                 | Text → compressed data       |

#### 1. Plain
``Plain``: This refers to the raw text before any transformations are applied.


#### 2. URL
``URL``: URL encoding is utilized to ensure the safe transfer of data in the URL of a web request. It involves substituting characters for their ASCII character code in hexadecimal format, preceded by a percentage symbol (%). This method is vital for any type of web application testing.

````
   ↓

   ↓
URL
````

#### 6. Hex / Octal / Binary

#### 7. Gzip

``Gzip`` is different from simple encoding.

It compresses data to reduce its size.
````
Original text
      ↓
    Gzip
      ↓
Compressed data
````
And:
````
Compressed data
      ↓
   Gzip Decode
      ↓
Original text
````
The output may look like unreadable characters because compressed data is binary.

## Task 4: Decoder: Hashing

### 1. What is hashing?

Hashing = converting data into a fixed hash value.
````
Input Data
    ↓
 Hash Algorithm
    ↓
 Hash Value
````

<img width="1917" height="498" alt="image" src="https://github.com/user-attachments/assets/daafc27e-6c58-4764-8f89-9f1facd8763d" />


#### Why is this useful?
| Use                    | Explanation                                            |
| ---------------------- | ------------------------------------------------------ |
| **File integrity**     | Check whether a file has been changed.                 |
| **Document integrity** | Detect modifications to documents.                     |
| **Password storage**   | Store a derived hash instead of the original password. |
| **Verification**       | Compare hashes to determine whether data matches.      |



A hash is designed to be one-way:
````
Data → Hash
````
We normally cannot simply do:
````
Hash → Original data
````


### 2. Why are hashes used?
| Use                   | Purpose                                                 |
| --------------------- | ------------------------------------------------------- |
| **File integrity**    | Detect whether a file has changed                       |
| **Password storage**  | Store a derived value instead of the plaintext password |
| **Data verification** | Check whether data has been modified                    |

A tiny change in the input can produce a very different hash.




### 3. Hashing in Burp Decoder
````
Burp Suite
   ↓
Decoder
   ↓
Enter data
   ↓
Hash...
   ↓
Choose algorithm
````
Burp provides many algorithms in the Hash... dropdown.

| Algorithm   | Type |
| ----------- | ---- |
| **MD5**     | Hash |
| **SHA-1**   | Hash |
| **SHA-256** | Hash |
| **SHA-384** | Hash |
| **SHA-512** | Hash |
| **BLAKE2**  | Hash |

> **Note**: MD5 and SHA-1 are considered weak for modern security applications and should not be used for new password-storage systems.
