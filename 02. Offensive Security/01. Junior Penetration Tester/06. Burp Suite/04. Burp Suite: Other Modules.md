## Task 2: Decoder
The **Burp Suite Decoder** is used to **decode, encode, and hash data**.

### What do you put in Decoder?

We can paste something like:
````
Data
````
Then Burp gives you options for what we want to do with it.

| Option           | Simple meaning                              |
| ---------------- | ------------------------------------------- |
| **Decode**       | Turn encoded data back into readable data   |
| **Encode**       | Turn normal data into an encoded format     |
| **Hash**         | Create a one-way hash from the data         |
| **Smart decode** | Automatically try to decode multiple layers |

### 1. Encode

**Encode = make data look different for transmission or representation**.

Example:
````
Data
  ↓
URL Encode
  ↓
%44%61%74%61
````
The original text is still represented by the encoded value.


### 2. Decode

Decode = reverse an encoding.
````
%44%61%74%61
       ↓
   URL Decode
       ↓
      Data
````
So:
````
Encode → Data → Encoded Data
Decode → Encoded Data → Data
````




### 3. Hash

Hashing creates a fixed-value representation of the input.
````
Data
  ↓
MD5 / SHA-1 / SHA-256
  ↓
Hash value
````
Unlike normal encoding, hashing is not simply reversed with a Decode button.



### 4. Text vs Hex

The Text / Hex option tells Decoder how to interpret the input.

| Mode     | Meaning                              |
| -------- | ------------------------------------ |
| **Text** | Treat the input as normal text       |
| **Hex**  | Treat the input as hexadecimal bytes |



### 5. Smart Decode

**Smart Decode** is useful when data has been encoded multiple times.
````
Encoded data
     ↓
Smart Decode
     ↓
Decode layer 1
     ↓
Decode layer 2
     ↓
Readable data
````

## Task 3: Decoder: Encoding / Decoding


### 1. Encoding / Decoding options

| Option        | What it does                                 | Example                      |
| ------------- | -------------------------------------------- | ---------------------------- |
| **Plain**     | Original/raw text                            | `Data`                       |
| **URL**       | Converts characters to URL-safe encoding     | `/` → `%2F`                  |
| **HTML**      | Converts special characters to HTML entities | `"` → `&quot;`               |
| **Base64**    | Converts data to Base64                      | `Data` → `RGF0YQ==`          |
| **ASCII Hex** | Converts text to hexadecimal                 | `ASCII` → hex representation |
| **Hex**       | Works with hexadecimal data                  | `41` → `A`                   |
| **Octal**     | Represents numbers in base 8                 | Decimal → Octal              |
| **Binary**    | Represents data using `0` and `1`            | `A` → binary                 |
| **Gzip**      | Compresses/decompresses data                 | Text → compressed data       |

#### 1. Plain
``Plain``: This refers to the raw text before any transformations are applied.


#### 2. URL
``URL``: URL encoding is utilized to ensure the safe transfer of data in the URL of a web request. It involves substituting characters for their ASCII character code in hexadecimal format, preceded by a percentage symbol (%). This method is vital for any type of web application testing.

Go to:
````

   ↓
Encode as...
   ↓
URL
````


#### 3. HTML Encoding

``HTML`` encoding represents special characters using HTML entities.

#### 6. Hex / Octal / Binary

| Format      | Example for `10` |

| **Decimal** | `10`             |
| **Hex**     | `A`              |
| **Octal**   | `12`             |
| **Binary**  | `1010`           |

Burp Decoder can convert between these representations when the input is appropriate numeric data.



#### 7. Gzip

``Gzip`` is different from simple encoding.

It compresses data to reduce its size.
````
Original text
      ↓
    Gzip
      ↓
Compressed data
````
And:
````
Compressed data
      ↓
   Gzip Decode
      ↓
Original text
````
The output may look like unreadable characters because compressed data is binary.

## Task 4: Decoder: Hashing

### 1. What is hashing?

Hashing = converting data into a fixed hash value.
````
Input Data
    ↓
 Hash Algorithm
    ↓
 Hash Value
````

<img width="1917" height="498" alt="image" src="https://github.com/user-attachments/assets/daafc27e-6c58-4764-8f89-9f1facd8763d" />


#### Why is this useful?
| Use                    | Explanation                                            |
| ---------------------- | ------------------------------------------------------ |
| **File integrity**     | Check whether a file has been changed.                 |
| **Document integrity** | Detect modifications to documents.                     |
| **Password storage**   | Store a derived hash instead of the original password. |
| **Verification**       | Compare hashes to determine whether data matches.      |



A hash is designed to be one-way:
````
Data → Hash
````
We normally cannot simply do:
````
Hash → Original data
````


### 2. Why are hashes used?
| Use                   | Purpose                                                 |
| --------------------- | ------------------------------------------------------- |
| **File integrity**    | Detect whether a file has changed                       |
| **Password storage**  | Store a derived value instead of the plaintext password |
| **Data verification** | Check whether data has been modified                    |

A tiny change in the input can produce a very different hash.




### 3. Hashing in Burp Decoder
````
Burp Suite
   ↓
Decoder
   ↓
Enter data
   ↓
Hash...
   ↓
Choose algorithm
````
Burp provides many algorithms in the Hash... dropdown.

| Algorithm   | Type |
| ----------- | ---- |
| **MD5**     | Hash |
| **SHA-1**   | Hash |
| **SHA-256** | Hash |
| **SHA-384** | Hash |
| **SHA-512** | Hash |
| **BLAKE2**  | Hash |

> **Note**: MD5 and SHA-1 are considered weak for modern security applications and should not be used for new password-storage systems.

## Task 5: Comaprer: Overiew


Comparer, as the name implies, lets us compare two pieces of data, either by ASCII words or by bytes.


<img width="1100" height="763" alt="image" src="https://github.com/user-attachments/assets/9950ea38-04c0-4fb4-ada1-a3189e39186f" />


1. Left side — Data to compare
- Shows the datasets you add.
- Add at least 2 datasets.
- Select the two datasets you want to compare.

2. Upper-right — Data controls
- Paste → paste data from clipboard.
- Load → load data from a file.
- Remove → remove the selected dataset.
- Clear → remove all datasets.

3. Lower-right — Comparison
- Words → compare text/content.
- Bytes → compare data byte-by-byte.
- Click one after selecting 2 datasets.


**Send data from other Burp tools**: ``Right-click`` the ``data`` → ``Send to Comparer``.


Once we've added at least 2 datasets to compare and press on either ``Words`` or ``Bytes``, a pop-up window shows us the comparison:

<img width="914" height="435" alt="image" src="https://github.com/user-attachments/assets/8c96eea7-ab94-4604-97c5-8f5a1cbe42b8" />


1. Compared Data — Main area
- Shows the two datasets side-by-side.
- Can be viewed as:
  - ``Text`` → normal readable text
  - ``Hex`` → hexadecimal data
- The starting view depends on whether you selected Words or Bytes.
- We can change the view using the buttons above the comparison boxes.

2. Comparison Key — Bottom left
Shows what the colors mean:
- ``Modified`` → data was changed
- ``Deleted`` → data was removed
- ``Added`` → new data was added

3. Sync Views — Bottom right
- ``Checked`` → both datasets change view together.
- ``Example``: change one from **Text** → **Hex**, and the other also changes to **Hex**.

### Sequencer Analysis — Short & Easy

The **Summary** usually gives enough information to judge the token security.

But if something looks suspicious, check:

* **Character-level analysis** → checks randomness of individual characters.
* **Bit-level analysis** → checks randomness at the bit level.

#### Important

**Entropy is a strong indicator, but not absolute proof.**

Other factors can affect token security, and statistical tests always have some uncertainty.

In this example:

```
Effective entropy = 117 bits
Significance level = 1%
```

This indicates the tokens are **highly random and likely difficult to predict**.

**Because Burp Organizer saves a copy of the HTTP request at the moment we send it there.**

````
Proxy / Repeater
      ↓

      ↓
Saved copy
      ↓
Read-only
````

We cannot edit the saved request directly in Organizer.
