## Task 2: Wi-Fi Network Fundamentals

<img width="1901" height="865" alt="image" src="https://github.com/user-attachments/assets/d94e0735-4e55-479e-bfee-08ee29f7e6f8" />

Nowadays, people have adapted to using Wi-Fi to connect to the Internet. It can be found in homes, offices, coffee shops, and airports. It lets devices communicate using radio signals instead of physical cables, which makes connectivity flexible and convenient. But to secure it, we first need to understand how it works.
| Component             | Easy meaning                                                                               | Examples                                 |
| --------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------- |
| **Access Point (AP)** | The device that **provides/broadcasts Wi-Fi** and connects wireless devices to the network | Home router, office AP                   |
| **Clients**           | Devices that **connect to the Wi-Fi**                                                      | Phone, laptop, tablet, printer, smart TV |

> An **Access Point (AP)** is the device that creates a wireless network and bridges its wireless clients to the wired network behind it. A domestic router performs this role, and a corporate site may operate dozens of access points advertising the same network name so that coverage is continuous across a building.



### Identifiers in Wi-Fi Networks
Wi-Fi uses two important identifiers:
| Identifier | Easy meaning                                                           | Example             |
| ---------- | ---------------------------------------------------------------------- | ------------------- |
| **SSID**   | The **Wi-Fi network name** we see when connecting                     | `Office_WiFi`       |
| **BSSID**  | The **unique identifier of the Access Point**, usually its MAC address | `00:1A:2B:3C:4D:5E` |

> The **Service Set Identifier (SSID)** is the name field of a wireless network. In practice "SSID" and "ESSID" are used interchangeably, and tools such as airodump-ng and hostapd use both spellings for the same value.



### How Wireless Devices Communicate

Wi-Fi devices communicate by sending radio waves through the air. These radio waves operate at different frequency bands.

The frequency a Wi-Fi network uses affects four main things:
- **Range**: How far the signal can travel
- **Speed** How much data can be transmitted
- **Obstacle penetration** How well the signal passes through walls/floors
- **Congestion** How many other devices are competing for the same frequencies

| Feature                    | **2.4 GHz**                                        | **5 GHz**                                  |
| -------------------------- | -------------------------------------------------- | ------------------------------------------ |
| **Range**                  | Better - up to around **45 m indoors**             | Shorter - around **15 m indoors**          |
| **Speed**                  | Up to around **600 Mbps**                          | Up to around **1300 Mbps**                 |
| **Wall/Floor penetration** | **Better**                                         | **Worse**                                  |
| **Congestion**             | **High**                                           | **Lower**                                  |
| **Interference**           | Microwaves, Bluetooth, baby monitors, nearby Wi-Fi | Generally less interference                |
| **Best for**               | Longer distance and better coverage                | Higher speed and less congestion           |
| **Main disadvantage**      | Crowded and slower                                 | Shorter range and weaker through obstacles |

### Association Process

| Step                                | What happens                                          | Easy meaning                       |
| ----------------------------------- | ----------------------------------------------------- | ---------------------------------- |
| **1. Scan**                         | Device looks for available Wi-Fi networks             | What Wi-Fi networks are nearby?  |
| **2. Select**                       | Device chooses an AP/network                          | I want to connect to this Wi-Fi. |
| **3. Authentication + Association** | Device and AP communicate to establish the connection | Can I connect to this AP?        |
| **4. Key negotiation**              | Encryption keys are established                       | How will we protect the traffic? |
| **5. Data transfer**                | Normal network communication begins                   | Now I can use the network.       |

> The **association process** is how a wireless device **establishes a connection with a Wi-Fi Access Point (AP)** so it can communicate on the network.

##### Authentication vs Association
- **Authentication**: establishes whether the device can proceed with the connection.
- **Association**: establishes the device's connection with the AP.

With **Open System Authentication**, the authentication step itself does **not verify the Wi-Fi password**. It's basically:
````
Client → AP: Can I connect?
AP → Client: Yes
````
The actual security process depends on the Wi-Fi security type.


**WPA2-Personal**: ``Client`` -> ``Associate with AP`` -> ``4-Way Handshake`` -> ``Prove knowledge of the Pre-Shared Key (PSK)`` -> ``Encrypted communication``.

> The 4-way handshake is where the client and AP establish the keys needed to protect communication and demonstrate knowledge of the shared secret.



**WPA2-Enterprise**: ``Client`` -> ``Associate with AP`` -> ``802.1X authentication`` -> ``RADIUS server`` -> ``Credential authentication`` -> ``Encrypted communication``

Instead of everyone sharing one Wi-Fi password, **WPA2-Enterprise uses individual authentication through an authentication server such as RADIUS**.


> **Scan → Select → Authenticate/Associate → Key negotiation → Data**

And for the two WPA2 types:
|                            | WPA2-Personal         | WPA2-Enterprise                               |
| -------------------------- | --------------------- | --------------------------------------------- |
| Authentication             | PSK                   | 802.1X                                        |
| Main authentication method | Shared Wi-Fi password | Individual credentials                        |
| Authentication server      | Not required          | Usually RADIUS                                |
| Important handshake        | 4-way handshake       | 802.1X/EAP authentication + key establishment |

## Task 3: Wi-Fi Security


Wi-Fi is based on the IEEE 802.11 family of standards. Each generation introduced improvements in speed, range, efficiency, and the way devices communicate.

| **Standard** | **Generation** | **Year** | **Frequency** | **Key Improvement** |
|---|---|---:|---|---|
| **802.11** | — | 1997 | 2.4 GHz | First Wi-Fi standard; about **2 Mbps**; not widely adopted |
| **802.11b** | — | 1999 | 2.4 GHz | First widely adopted Wi-Fi standard; up to **11 Mbps** |
| **802.11g** | — | 2003 | 2.4 GHz | Increased speed to **54 Mbps** and remained backward-compatible with 802.11b |
| **802.11n** | **Wi-Fi 4** | 2009 | 2.4 & 5 GHz | Dual-band support, **MIMO**, up to **600 Mbps** |
| **802.11ac** | **Wi-Fi 5** | 2013 | 5 GHz | Much faster Wi-Fi, **MU-MIMO**, up to **6.9 Gbps** |
| **802.11ax** | **Wi-Fi 6 / 6E** | 2021 | 2.4, 5 & 6 GHz | High efficiency, **OFDMA**, up to **9.6 Gbps**, designed for dense networks |
| **802.11be** | **Wi-Fi 7** | 2024 | 2.4, 5 & 6 GHz | **Multi-Link Operation**, up to **320 MHz channels**, up to about **46 Gbps** |

> Most enterprises deploy Wi-Fi 5 and Wi-Fi 6 standards because they work well with modern laptops, smartphones, and access points, which is why they are often seen during security assessments.




### Authentication and Encryption in Wi-Fi

Wi-Fi security has two main jobs:
- **Authentication** → controls who can connect
- **Encryption** → protects the data


| Protocol | Encryption | Status          | Easy meaning                    |
| -------- | ---------- | --------------- | ------------------------------- |
| **WEP**  | RC4        | **Broken**      | Old and insecure                |
| **WPA**  | RC4 + TKIP | **Deprecated**  | Improved WEP but still outdated |
| **WPA2** | AES-CCMP   | **Widely used** | Strong and commonly used        |
| **WPA3** | AES-GCMP   | **Recommended** | Newer and stronger security     |


<img width="1900" height="895" alt="image" src="https://github.com/user-attachments/assets/7a125e76-0aa8-47e6-acdd-ab7fce9587ae" />


### Common Wi-Fi Misconfigurations

These are **mistakes in Wi-Fi** configuration that can make a network easier to attack:

| **Misconfiguration** | **What it means** | **Why it's dangerous** |
|---|---|---|
| **Outdated security protocols** | Using old protocols such as **WEP** | WEP has serious cryptographic weaknesses and can be attacked |
| **Weak passwords** | Using simple, short, or common Wi-Fi passwords | Attackers may guess or crack them |
| **WPS enabled unnecessarily** | Leaving **Wi-Fi Protected Setup** enabled when it isn't needed | Some WPS configurations can provide an alternative route to network access |
| **Default admin credentials** | Keeping the router/AP manufacturer's default username/password | Attackers may know or easily find the default credentials and access the AP's administration interface |


### Common Wi-Fi Attack Concepts

These are common ways attackers may try to exploit weak Wi-Fi security.

| **Attack** | **Meaning** | **Main Goal** |
|---|---|---|
| **Password Attack** | Trying many passwords or cracking captured authentication data | Obtain the Wi-Fi password |
| **Rogue Access Point** | An unauthorised AP physically connected to the target network | Gain unauthorised network access or create a security risk |
| **Evil Twin** | Fake AP using the same/similar SSID as a legitimate network but operating independently | Trick users into connecting to the attacker's AP |
| **Deauthentication Attack** | Sending frames that cause clients to disconnect from an AP | Force disconnections; can support other attacks |
| **Traffic Interception** | Capturing wireless traffic | Attempt to inspect data when protection is weak or absent |


##### Rogue AP vs Evil Twin
| **Rogue Access Point** | **Evil Twin** |
|---|---|
| Actually connected to the **target network** | Usually **not connected** to the target network |
| Provides unauthorised access to the internal network | Pretends to be the legitimate Wi-Fi |
| Can be installed by an attacker or accidentally by an employee | Deliberately designed to deceive users |
| Main concern = **unauthorised network entry** | Main concern = **tricking clients and potentially intercepting their traffic** |



### Protecting Wi-Fi Networks
These are the recommended defensive measures.

| **Protection** | **What it does** | **Security Benefit** |
|---|---|---|
| **WPA2/WPA3 + strong passphrase** | Uses modern Wi-Fi security and a difficult-to-guess password | Reduces unauthorised access |
| **Disable WEP** | Removes insecure legacy encryption | Prevents attacks against WEP weaknesses |
| **Disable WPS if unnecessary** | Removes the optional WPS authentication mechanism | Reduces another possible attack surface |
| **Change default admin credentials** | Replaces manufacturer defaults | Prevents easy administrative takeover |
| **Network segmentation** | Separates guest/untrusted devices from sensitive systems | Limits how far an attacker can move |
| **Update AP firmware** | Installs vendor security patches | Fixes known vulnerabilities |

## Task 4: Bluetooth Security

**Bluetooth**: is a **short-range wireless technology** that uses the **2.4 GHz band**.

Common uses:
- Keyboards/mice
- Headphones/speakers
- Smartwatches
- Cars
- IoT devices


> Bluetooth is commonly enabled on personal and corporate devices, which makes it an appealing target for attackers.


### Classic Bluetooth vs Bluetooth Low Energy (BLE)

There are two main variants of Bluetooth: Classic Bluetooth and Bluetooth Low Energy (BLE):

- **Classic Bluetooth**: Used for high-data activities like music, calls, and file transfers. Usually stays connected.
- **BLE**: Used for small, occasional data with low power, such as fitness trackers, smart locks, and beacons.



Security difference
- **Classic Bluetooth**: Uses a pairing process to establish a shared security key.
- **BLE**: Has multiple pairing methods. “Just Works” is common and provides no user verification, making Man-in-the-Middle (MITM) attacks easier.


<img width="900" height="946" alt="image" src="https://github.com/user-attachments/assets/48a5445a-b387-4c30-858e-2e066537abd7" />


| Aspect | Classic Bluetooth | Bluetooth Low Energy (BLE) |
|---|---|---|
| **Pairing Model** | Uses **Secure Simple Pairing (SSP)** with numeric comparison or passkey entry, providing better MITM protection. | **LE Legacy Pairing** is weak; **LE Secure Connections (4.2+)** uses ECDH and is stronger. |
| **Advertising & Discoverability** | **Lower risk** — Does not continuously advertise; devices are discoverable when explicitly enabled. | **Higher risk** — Continuously broadcasts advertising packets, potentially exposing device information and sensor data. |
| **Encryption** | **Varies** — Older devices may use the weaker E0 cipher; newer devices use AES-CCM. | **Stronger** — Uses **AES-CCM**, but security still depends on the pairing method. |
| **Privacy & Tracking** | **Weaker** — Fixed MAC address makes devices easier to track. | **Stronger** — Supports **MAC address randomization** to reduce tracking. |
| **MITM Protection** | **Better** — SSP methods such as Numeric Comparison and Passkey make MITM attacks harder. | **Weaker in “Just Works”** — No user verification, so MITM attacks are easier. |
| **Attack Surface** | **Smaller** — Connections are generally short-lived and user-initiated. | **Larger** — Continuous advertising creates a persistent attack surface, especially for IoT devices. |



### How Bluetooth Devices Pair and Exchange Data


#### Bluetooth Pairing 

Before two Bluetooth devices communicate, they need to pair to create a secure connection.

| Pairing Method | Bluetooth Version | How It Works | Security |
|---|---|---|---|
| **PIN Pairing** | Older Bluetooth | Enter the same PIN, such as `0000` or `1234`, on both devices. | Weak — easy to guess/brute-force |
| **Secure Simple Pairing (SSP)** | Classic Bluetooth 2.1+ | Uses cryptographic key exchange. May use a passkey or number comparison. | Stronger |
| **LE Legacy Pairing** | BLE 4.0–4.1 | Uses older pairing mechanisms. | Weaker |
| **LE Secure Connections** | BLE 4.2+ | Uses stronger cryptographic key exchange. | Stronger |
| **Just Works** | BLE | Devices pair automatically with little/no user verification. | Weaker against MITM |

### Common Bluetooth Security Risks

Bluetooth communication could introduce security risks despite its convenience. Below are common security risks that may affect Bluetooth-enabled devices.

| Risk | Easy explanation |
|---|---|
| Unnecessary Discoverability | Leaving Bluetooth visible makes your device easier for nearby attackers to find. |
| Weak Pairing | Simple PINs like `0000` or `1234` are easy to guess. |
| Unauthorized Pairing | An attacker connects to your device without proper permission. |
| Bluejacking | Sending unwanted messages to nearby Bluetooth devices. |
| Bluesnarfing | Exploiting Bluetooth to access private data without permission. |
| Bluebugging | Exploiting Bluetooth vulnerabilities to control certain phone functions. |
| Lack of Updates | Outdated software may contain security vulnerabilities that attackers can exploit. |


##### Where can these attacks happen?
Places with many nearby devices, such as offices, airports, and conferences.

> **Bluejacking = unwanted messages; Bluesnarfing = stealing data; Bluebugging = controlling device functions.**



### Security Considerations for Classic Bluetooth and BLE

Both Classic Bluetooth and BLE need proper security settings to prevent attacks and protect data.
Common security measures include:
- Turn off Bluetooth when not needed.
- Disable discoverability or advertising when possible.
- Use strong pairing and authentication methods.
- Reject unknown pairing requests.
- Keep device firmware and software updated.
- Use encryption to protect transmitted data.

<img width="820" height="930" alt="image" src="https://github.com/user-attachments/assets/f8d602f0-87b0-4d85-a442-36cce5992e21" />

Even though Bluetooth has a short range, attackers nearby can still exploit vulnerable devices to steal sensitive data or gain access to a larger network.


> **Example**: Bluetooth security is like a window left slightly open. Even a small weakness can let an intruder in.

## Task 5: RFID and NFC Security

* **Radio-Frequency Identification (RFID)** is a technology that uses electromagnetic fields to identify and track tags attached to objects. 

**RFID**: Uses radio waves to identify and track objects. Its range can reach 100 metres or more, depending on the type.
> **Examples**: inventory tags, employee access cards.


* **Near-Field Communication (NFC)** is a closely related standard that enables two devices to exchange data when brought into close proximity. 

**NFC**: Allows two devices to exchange data when they are very close, typically within 5 cm.
> **Examples**: contactless payments, phone pairing, transit cards.


| Feature | RFID | NFC |
|---|---|---|
| Range | Up to 100 m or more | About 5 cm |
| Purpose | Identify and track objects | Exchange data nearby |
| Example | Warehouse tracking | Phone payment |



> **RFID = longer-range identification. NFC = very short-range communication.**



### How RFID and NFC Work

RFID has two main parts:
- **Reader**: Sends radio waves to detect and communicate with a tag.
- **Tag**: Responds with stored information.

| Tag Type | How it works | Advantages | Disadvantages |
|---|---|---|---|
| Passive | Gets energy from the reader; no battery. | Cheap and lasts a long time. | Shorter range. |
| Active | Uses its own battery to transmit data. | Longer range, sometimes 100 m or more. | More expensive; battery eventually runs out. |

NFC uses a frequency of 13.56 MHz and allows two nearby devices to exchange data in both directions.
- **Initiator**: Creates a radio field and sends data.
- **Target**: Receives the signal and responds.
- **Data exchange**: The devices communicate to complete an action.

**RFID** and **NFC** are commonly used for identification, access control, and contactless transactions. Employee badges, warehouse inventory tags, hotel key cards, and payment terminals all rely on one or both of these technologies.



### Common RFID and NFC Security Risks

The following techniques are commonly performed by attackers to exploit RFID and NFC weaknesses:

| Risk | Simple meaning | Example |
|---|---|---|
| Eavesdropping | Secretly listening to communication between a card and reader. | An attacker captures card communication. |
| Cloning | Copying card data onto another card or device. | Someone copies an access badge. |
| Relay Attack | Forwarding communication between a real card and reader over a distance. | An attacker relays a victim's card signal to a payment terminal. |
| Unauthorized Scanning (Skimming) | Secretly scanning a card to obtain its data. | An attacker scans a card without the owner's knowledge. |
| Lost or Stolen Cards | Someone uses a lost or stolen card without permission. | A stolen employee badge is used to enter an office. |



How Relay attack work?
- The victim carries a contactless card.
- Attacker 1 places a reader near the victim's card.
- Attacker 2 relays the communication to a payment terminal.
- The terminal may process a transaction if the payment system accepts it.

> **A relay attack forwards communication; it does not necessarily clone the card.**

### Security Considerations for RFID and NFC

A multi-layered approach is required in order to secure RFID and NFC devices, which requires protection of data during transmission and securing physical access to devices. The following measures could help ensure that exposure to risks is minimised:
- Use cards that support encryption
- Limit sensitive data stored on cards or use tokenisation
- Immediately deactivate lost or stolen cards
- Use protective sleeves such as Faraday pouches to protect against unauthorised scanning
- Update access controls regularly
- Implement secondary biometric authentication where possible

## Task 6: Others Wireless Technologies


<img width="1900" height="895" alt="image" src="https://github.com/user-attachments/assets/f256f735-ead0-4ebe-baa7-51c63a56ed2e" />


In addition to Wi-Fi, Bluetooth, NFC, and RFID, many other wireless technologies are used in modern environments. These technologies support smart devices, automation systems, and connected infrastructure.


Several wireless technologies are commonly used in smart environments and Internet of Things (IoT) systems. 

> **IoT (Internet of Things)** refers to the network of physical objects, or **things**, that are embedded with sensors and software which allow them to collect and exchange data over the Internet. These objects can include various devices, from everyday household items like thermostats, refrigerators, and lightbulbs, to industrial equipment, vehicles, and more.



#### Zigbee

**Zigbee** is a low-power, short-range wireless technology used in smart-home devices.
- **Low power**: Uses little energy.
- **Short range**: Communicates over relatively short distances.
- **Mesh network**: Devices can relay data to nearby devices, extending the network's coverage.
- **Examples**: Smart lights, sensors, and smart plugs.
