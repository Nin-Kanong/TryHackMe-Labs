## Task 2: Introduction

<img width="1140" height="480" alt="image" src="https://github.com/user-attachments/assets/46a8939e-5403-43fc-8d2d-d1728f43d36c" />


The **Cyber Kill Chain**, introduced by Lockheed Martin in **2011**, explains a cyberattack as **7 stages** from initial information gathering to achieving the attacker’s goal.

<img width="650" height="800" alt="image" src="https://github.com/user-attachments/assets/05f80b55-558d-4a19-88d7-bab6ff7ae4d8" />



| Stage                            | Simple Meaning                      | Example                          |
| -------------------------------- | ----------------------------------- | -------------------------------- |
| 🔍 **1. Reconnaissance**         | Gather information about target     | Find emails, domains, systems    |
| 🛠️ **2. Weaponisation**         | Prepare malicious payload           | Create/modify malware            |
| 📦 **3. Delivery**               | Send payload to victim              | Phishing email                   |
| 💥 **4. Exploitation**           | Exploit a vulnerability             | Malicious payload executes       |
| 🦠 **5. Installation**           | Establish persistence               | Install malware/backdoor         |
| 🎮 **6. Command & Control (C2)** | Remotely control compromised system | Infected PC connects to attacker |
| 🎯 **7. Actions on Objectives**  | Achieve attacker's final goal       | Steal data, attack other systems |

## Task 2: Reconnaissance

<img width="800" height="800" alt="image" src="https://github.com/user-attachments/assets/7ca3a2cb-afb0-473f-995b-37372a35501d" />


**Reconnaissance** is the first stage of the Cyber Kill Chain.


> **Reconnaissance** = Gathering information about the target before attacking.


The goal is to discover ``systems``, ``people``, ``services``, ``vulnerabilities``, and ``possible entry points``.


#### Two Types of Reconnaissance
| Type                  | Meaning                                                             | Examples                                                       |
| --------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------- |
| 🕵️ **Passive Recon** | Gather information **without directly interacting** with the target | OSINT, WHOIS, DNS research, social media, Google Dorking       |
| 🔎 **Active Recon**   | **Directly interact** with the target                               | Port scanning, vulnerability scanning, physical reconnaissance |


### 1. Passive Reconnaissance

<img width="650" height="800" alt="image" src="https://github.com/user-attachments/assets/23d340f1-2429-4f4a-b9da-c745373458ed" />

Common examples:
- **WHOIS** → domain registration information
- **DNS** → DNS servers, records and public IP information
- **Google Dorking** → find publicly exposed information
- **Social media** → information about employees/organization
- **Website crawling/scraping** → discover public website information

Usually this creates little or no direct interaction with the target.

Passive Recon: https://github.com/Nin-Kanong/TryHackMe-Labs/blob/main/02.%20Offensive%20Security/01.%20Junior%20Penetration%20Tester/03.%20Network%20Reconnaissance/01.%20Passive_Reconnaissance.md


### 2. Active Reconnaissance

<img width="650" height="800" alt="image" src="https://github.com/user-attachments/assets/ef79c8d1-f515-4366-8dea-1fa8665d76c5" />

It can reveal:
- Live hosts
- Open ports
- Running services
- Potential vulnerabilities
- Security measures

Active recon is noisier because the target may detect the scanning activity.

Active Recon: https://github.com/Nin-Kanong/TryHackMe-Labs/blob/main/02.%20Offensive%20Security/01.%20Junior%20Penetration%20Tester/03.%20Network%20Reconnaissance/02.%20Active_Reconnaissance.md

## Task 3: Weaponisation

<img width="800" height="800" alt="image" src="https://github.com/user-attachments/assets/f225ae6e-f368-4446-aee0-d296f26af875" />

**Weaponisation** happens after reconnaissance. The attacker uses information discovered about the target to prepare a payload or exploit for later delivery.

> **Weaponisation** = **Prepare the cyber weapon**.

### Flow:

<img width="650" height="800" alt="image" src="https://github.com/user-attachments/assets/53c0dafc-9357-41ce-b172-2f0c43887a92" />



### Weaponisation Examples
| Example                 | Description                                 |
| ----------------------- | ------------------------------------------- |
| 📎 **Email Attachment** | Malicious content prepared for an email     |
| 📄 **Office Document**  | Document containing malicious functionality |
| 💾 **USB**              | Malicious content placed on removable media |
| 🌐 **Web Content**      | Payload prepared to be hosted online        |
| 🧰 **Exploit Kit**      | Toolkit that packages exploits and payloads |
| 🥷 **Obfuscation**      | Makes malicious content harder to detect    |
| 🔐 **Encryption**       | Conceals payload contents                   |

> **Attackers** may disguise malicious content as something that appears harmless, such as a normal document.


### Countermeasures

Defenders can reduce the risk through:
- Security awareness training
- Checking suspicious emails and attachments
- Disabling unnecessary Office macros
- Allowing only trusted/signed macros when required
- Removing unnecessary software and browser plugins
- Using security policies such as Group Policy
- Reducing the overall attack surface

## Task 4: Delivery

<img width="800" height="800" alt="image" src="https://github.com/user-attachments/assets/e59c26c7-ca5a-4fc1-a4b8-5137e6d8c3fb" />


**Delivery** is when the attacker transmits the prepared payload to the target.

> Delivery = Get the malicious payload to the victim.


### Attack Flow

<img width="650" height="800" alt="image" src="https://github.com/user-attachments/assets/3508373a-31bd-4d17-b62f-063daa4213eb" />




### Common Delivery Methods
| Method                       | Simple Meaning                                       |
| ---------------------------- | ---------------------------------------------------- |
| 📧 **Phishing Email**        | Malicious attachment or link sent by email           |
| 🎯 **Spear Phishing**        | Targeted phishing made to look like a trusted person |
| 🔗 **Malicious Web Link**    | Link redirects victim to malicious content           |
| ☁️ **File-Sharing Platform** | Malicious file uploaded to a file-sharing service    |
| 📢 **Malvertising**          | Malicious advertisements redirect users              |
| 📱 **Smishing**              | Phishing through SMS/text messages                   |
| 🧠 **Social Engineering**    | Convince the victim to download/run something        |
| 💾 **Physical Delivery**     | USB/DVD or other physical media                      |



### Phishing vs Spear Phishing vs Smishing
````
Phishing
   └──► 📧 General malicious email

Spear Phishing
   └──► 🎯 Targeted malicious email

Smishing
   └──► 📱 Malicious SMS/text message
````

### Defending Against Delivery

Organizations can try to break the Kill Chain at the Delivery stage using:
- Cybersecurity awareness training
- Email filtering
- Web filtering
- Web Application Firewalls (WAF)
- Network monitoring
- Patch management
- Blocking suspicious attachments and links

## Exploitation

<img width="800" height="800" alt="image" src="https://github.com/user-attachments/assets/9f99bbfb-635d-409d-b07d-ef37f4420e21" />


**Exploitation** happens after successful delivery. The attacker takes advantage of a **vulnerability or weakness** to gain access or execute malicious actions.

> Exploitation = Take advantage of a weakness.

### Attack Flow
````
🔍 Reconnaissance
      ↓
🛠️ Weaponisation
      ↓
📦 Delivery
      ↓
💥 EXPLOITATION
      ↓
🦠 Installation
````



### Common Exploitation Examples
| Weakness                      | Example                                           |
| ----------------------------- | ------------------------------------------------- |
| 🔑 **Weak/Default Password**  | Attacker discovers or guesses credentials         |
| 🎣 **Stolen Credentials**     | Phishing tricks a user into providing a password  |
| 🐞 **Software Vulnerability** | Exploit vulnerable software/service               |
| ⚙️ **Misconfiguration**       | Abuse incorrectly configured systems              |
| 💉 **SQL Injection**          | Manipulate vulnerable database queries            |
| 💥 **Buffer Overflow**        | Exploit improper memory handling                  |
| 🆕 **Zero-Day**               | Exploit a vulnerability before a fix is available |


### What is a Zero-Day?
A **zero-day vulnerability/exploit** involves a vulnerability for which an effective fix may not yet be available when attackers begin exploiting it.
````
🐞 Unknown/New Vulnerability
          ↓
💥 Attacker Exploits It
          ↓
⚠️ No Patch Available Yet
````


### Countermeasures Against Exploitation
| Defence                       | Purpose                                     |
| ----------------------------- | ------------------------------------------- |
| **Strong Password Policy** | Reduce weak/default passwords               |
| **MFA**                    | Add another authentication layer            |
| **Patch Management**       | Fix known vulnerabilities                   |
| **Vulnerability Scanning** | Discover weaknesses that need remediation   |
| **IPS**                   | Detect/block known exploitation attempts    |
| **WAF**                    | Help block web attacks such as SQLi and XSS |

## Task 6: Installation

<img width="800" height="800" alt="image" src="https://github.com/user-attachments/assets/42f868dc-b7dc-4c55-9726-a465f8bcbe7e" />

After successful **exploitation**, the attacker may try to establish **persistent access** so they can return later without exploiting the system again.

> Installation = Establish persistence on the compromised system.



### Attack Flow
````
🔍 Reconnaissance
      ↓
🛠️ Weaponisation
      ↓
📦 Delivery
      ↓
💥 Exploitation
      ↓
🦠 INSTALLATION
      ↓
🎮 Command & Control (C2)
````



### Installation / Persistence Examples

| Method                      | Simple Meaning                                        |
| --------------------------- | ----------------------------------------------------- |
| ⏰ **Scheduled Task**        | Configure something to run automatically on Windows   |
| ⏱️ **Cron Job**             | Schedule automatic execution on Linux                 |
| ⚙️ **Startup Modification** | Configure something to run at startup                 |
| 🔧 **New Service**          | Create a Windows/Linux service for persistence        |
| 🚪 **Backdoor**             | Maintain hidden access                                |
| 🦠 **Malware**              | Install malicious software                            |
| 🥷 **Rootkit**              | Hide malicious activity and maintain access           |
| 🌐 **Web Shell**            | Server-side script providing remote command execution |
| 🛠️ **LOLBin Abuse**        | Abuse legitimate built-in system tools                |


### Web Shell
````
Attacker
   │
   │ HTTPS
   ▼
🌐 Web Server
   │
   └── Web Shell
          │
          ▼
      OS Commands
````

A web shell can allow an attacker to interact with a compromised web server through web requests.


### Countermeasures Against Installation
| Defence                        | Purpose                                           |
| ------------------------------ | ------------------------------------------------- |
| 👁️ **Process Monitoring**     | Detect suspicious processes                       |
| 🔧 **Service Monitoring**      | Detect unauthorized/new services                  |
| 🛡️ **EDR**                    | Detect suspicious endpoint activity               |
| 📂 **File Monitoring**         | Detect unexpected file modifications              |
| 📋 **System Audits**           | Find unauthorized changes                         |
| 📏 **Secure Baseline**         | Compare systems against known-good configurations |
| ✅ **Application Allowlisting** | Only permit approved applications to execute      |

## Task 7: Command and Control (C2)

<img width="800" height="800" alt="image" src="https://github.com/user-attachments/assets/f31c3a9e-72d0-4a2f-bea4-4198c59416c4" />


After establishing persistence, the attacker needs a way to **communicate** with and **control the compromised system remotely**.

> C2 = Communication channel between a compromised system and attacker-controlled infrastructure.



### Attack Flow
````
💥 Exploitation
      ↓
🦠 Installation
      ↓
🎮 COMMAND & CONTROL (C2)
      ↓
🎯 Actions on Objectives
````


#### Simple C2 Flow
````
🥷 Attacker / C2 Server
          │
          │ Commands
          ▼
       Internet
          │
          ▼
💻 Compromised Computer
          │
          │ Results / Data
          └──────────────► C2 Server
````

The attacker tries to make this communication reliable and difficult to detect.


### Common C2 Techniques
| Technique             | Simple Meaning                                           |
| --------------------- | -------------------------------------------------------- |
| 🌐 **HTTP/HTTPS**     | C2 traffic blends with normal web traffic                |
| 🌍 **DNS**            | Data/commands can be hidden inside DNS traffic           |
| 📧 **SMTP**           | Email protocol may be used for communication             |
| 🔐 **Encryption**     | Makes C2 traffic harder to inspect                       |
| ☁️ **Cloud Services** | Legitimate services can be abused for communication      |
| 📱 **Social Media**   | Platforms may be abused to exchange commands             |
| 🔄 **DGA**            | Generates many possible C2 domain names                  |
| ⚡ **Fast Flux**       | Frequently changes IP addresses associated with a domain |


### DGA vs Fast Flux

DGA: Domain Generation Algorithm
````
Malware
  │
  ├──► abc123.com
  ├──► xzy789.com
  ├──► kdf321.com
  └──► ...
          ↓
     Find active C2
````
It generates **many domain names**, making C2 infrastructure harder to block.


#### Fast Flux
````
        evil-domain
             │
     ┌───────┼───────┐
     ▼       ▼       ▼
   IP #1   IP #2   IP #3
             ↓
       🔄 Change often
````

### Countermeasures Against C2

Defenders can use:
- Firewalls
- IDS/IPS
- DNS monitoring
- Network traffic analysis
- URL/content filtering
- Encrypted traffic inspection where appropriate
- Honeypots
- Detection of connections to known malicious IPs/domains

## Task 8: Actions on Objectives

After establishing **Command & Control (C2)**, the attacker carries out their main objective.

> Actions on Objectives = Attacker achieves their final goal.

### Full Kill Chain
````
🔍 Reconnaissance
      ↓
🛠️ Weaponisation
      ↓
📦 Delivery
      ↓
💥 Exploitation
      ↓
🦠 Installation
      ↓
🎮 Command & Control (C2)
      ↓
🎯 ACTIONS ON OBJECTIVES
````


### Common Attacker Objectives
| Objective                    | Meaning                                             |
| ---------------------------- | --------------------------------------------------- |
| 📤 **Data Exfiltration**     | Steal sensitive information                         |
| 🔐 **Ransomware**            | Encrypt data and demand payment                     |
| 💰 **Financial Theft**       | Steal money / fraudulent transfers                  |
| 💥 **Destruction**           | Delete/corrupt data or disrupt services             |
| 🕵️ **Espionage**            | Secretly steal sensitive information                |
| ↔️ **Lateral Movement**      | Move from one compromised system to others          |
| 🏭 **ICS Manipulation**      | Interfere with industrial control systems           |
| 🥷 **Long-term Persistence** | Remain inside the environment for future operations |



### Countermeasures
| Defence                          | Purpose                                     |
| -------------------------------- | ------------------------------------------- |
| 🛡️ **DLP**                      | Help prevent unauthorized data exfiltration |
| 💾 **Backups & Recovery**        | Recover from ransomware/destructive attacks |
| 🧱 **Network Segmentation**      | Limit movement between systems              |
| 🔒 **Access Controls**           | Restrict access to sensitive resources      |
| 👤 **Least Privilege**           | Give users only the permissions they need   |
| 👁️ **User Activity Monitoring** | Detect unusual user behaviour               |
| 🛡️ **EDR**                      | Detect suspicious endpoint activity         |
