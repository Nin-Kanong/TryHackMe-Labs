## Task 1: Introduction

**Active Directory (AD) enumeration** means collecting information about a Windows domain before attempting further attacks.

In an internal penetration test, we may receive **VPN or network access but no username or password**. Our first goal is therefore to understand what exists inside the AD environment.


### Why Do We Enumerate AD?

AD can contain a large amount of useful information:
- **Users**: Find valid domain accounts.
- **Groups**: Identify group memberships and privileged groups.
- **Computers**: Discover workstations, servers, and domain controllers.
- **Policies**: Examine password, account lockout, and security policies.
- **Services**: Identify services such as SMB, LDAP, Kerberos, DNS, and WinRM.
- **Domain information**: Discover the domain name, domain controllers, and network structure.

AD enumeration helps answer:

| Question      | What we discover                                            |
| ------------- | ----------------------------------------------------------- |
| **Who?**      | Users and groups                                            |
| **What?**     | Computers and servers                                       |
| **Where?**    | Domain controllers and network services                     |
| **How?**      | Authentication and security policies                        |
| **Weakness?** | Misconfigurations, exposed services, or vulnerable accounts |
| **Goal?**     | A realistic path to an initial foothold                     |

## Task 2: Mapping Out the Network

The main goal is to **discover which machines are alive and identify which one is the Domain Controller (DC)**.

Think like:

````mermaid
flowchart TD
    A[VPN Access] -->|1. Connect to network| B[Find Live Hosts]
    B -->|2. Scan their ports| C[Scan Their Ports]
    C -->|3. Identify services| D[Identify Services]
    D -->|4. Locate| E[Find the Domain Controller]
    E -->|5. Query| F[Enumerate AD]
````


### Host Discovery

**Host discovery** is the first step of network enumeration. The goal is to find out which IP addresses are alive in the target subnet.

``Target Network`` -> ``Find Live Hosts`` -> ``Save IPs`` -> ``Scan Their Ports``


#### fping

``fping`` is similar to ``ping``, but it can check many IP addresses or an entire subnet.
````
fping -agq 10.211.11.0/24
````
<img width="515" height="169" alt="image" src="https://github.com/user-attachments/assets/46e9ed0a-bef2-4afe-a666-636264eb9892" />



Each IP shown is a host that responded and is considered alive.

| Option           | Meaning                               |
| ---------------- | ------------------------------------- |
| `-a`             | Show only alive hosts                 |
| `-g`             | Generate IP addresses from the subnet |
| `-q`             | Quiet mode; hide unnecessary output   |
| `10.211.11.0/24` | Target subnet                         |

### Port Scanning

After finding the live hosts, the next step is to find out **which services and ports are open**.

The main goal here is to identify the **Domain Controller (DC)**.

Flow: ``Live Hosts`` -> ``Scan Ports`` -> ``Identify Services`` -> ``Find the Domain Controller``

Active Directory Ports
|  Port | Protocol / Service | Easy Meaning                                |
| ----: | ------------------ | ------------------------------------------- |
|  `88` | Kerberos           | AD authentication                           |
| `135` | MS-RPC             | Windows RPC communication                   |
| `139` | SMB/NetBIOS        | Older SMB/file sharing                      |
| `389` | LDAP               | Communicates with Active Directory          |
| `445` | SMB                | Modern Windows file sharing and enumeration |
| `464` | Kerberos/kpasswd   | Kerberos password operations                |



#### Service Scan
````
nmap -p 88,135,139,389,445 -sV -sC -iL hosts.txt
````

<img width="1159" height="626" alt="image" src="https://github.com/user-attachments/assets/dc5209c2-5f9b-421e-9f50-f974b8e63cbd" />


<img width="876" height="518" alt="image" src="https://github.com/user-attachments/assets/095ff0e7-acb7-47e6-a47c-7128a09bcf95" />


| Option          | Meaning                            |
| --------------- | ---------------------------------- |
| `-p`            | Specify which ports to scan        |
| `-sV`           | Detect service/version information |
| `-sC`           | Run Nmap's default scripts         |
| `-iL hosts.txt` | Read targets from `hosts.txt`      |

> This host is a strong Domain Controller candidate because it provides Kerberos, LDAP, and SMB.


#### Full Port Scan
Sometimes a service may run on an unusual port. For a more complete assessment:
````
nmap -sS -p- -T3 -iL hosts.txt -oN full_port_scan.txt
````


| Option          | Meaning                      |
| --------------- | ---------------------------- |
| `-sS`           | TCP SYN scan                 |
| `-p-`           | Scan all TCP ports `1–65535` |
| `-T3`           | Normal scan timing           |
| `-iL hosts.txt` | Read targets from the file   |
| `-oN`           | Save results to a text file  |

## Task 3: Network Enumeration With SMB

The main goal is to discover SMB services, find available shares, check permissions, and look for useful files.



### Discover Services

First, scan the important Windows/AD ports:
````
nmap -p 88,135,139,389,445,636 -sV -sC 10.211.11.10
````

<img width="1243" height="712" alt="image" src="https://github.com/user-attachments/assets/3ee36501-1b0c-4113-80a9-3661e2558923" />



| Port | Service     | Why Important                           |
| ---: | ----------- | --------------------------------------- |
|   88 | Kerberos    | AD authentication                       |
|  135 | MS-RPC      | Windows RPC services                    |
|  139 | NetBIOS/SMB | Older SMB                               |
|  389 | LDAP        | Query Active Directory                  |
|  445 | SMB         | File sharing and Windows administration |
|  636 | LDAPS       | Encrypted LDAP                          |


> Port ``445`` tells us SMB is available, so we can enumerate SMB shares.




#### List SMB Shares

Try anonymous access first:
````
smbclient -L //10.211.11.10 -N
````

<img width="545" height="275" alt="image" src="https://github.com/user-attachments/assets/57667a8c-db7f-427f-a740-a00ce9356ad7" />


- ``-L``: list available shares
- ``-N``: don't ask for a password

What are the interesting shares?
| Share         | Meaning                   |
| ------------- | ------------------------- |
| `ADMIN$`      | Administrative share      |
| `C$`          | Remote C: drive           |
| `IPC$`        | Windows IPC communication |
| `NETLOGON`    | Domain logon scripts      |
| `SYSVOL`      | AD domain files/policies  |
| `AnonShare`   | Custom share              |
| `SharedFiles` | Custom shared files       |
| `UserBackups` | Custom backup share       |

> The custom/non-standard shares are usually worth investigating first.



Then check Share Permissions:
````
smbmap -H 10.211.11.10
````
<img width="1036" height="542" alt="image" src="https://github.com/user-attachments/assets/e49eb26f-1637-4e01-bded-2c2829a97280" />


| Permission    | Meaning                          |
| ------------- | -------------------------------- |
| `NO ACCESS`   | Cannot access the share          |
| `READ`        | Can view/download files          |
| `WRITE`       | Can upload/modify files          |
| `READ, WRITE` | Can read and upload/modify files |

> READ/WRITE shares are especially important because they allow you to interact with files.

### What Can We Find in SMB Shares
SMB shares can contain useful information, especially when anonymous access or write access is allowed.

| What to Look For    | Why It Matters                                             |
| ------------------- | ---------------------------------------------------------- |
| Configuration files | May contain usernames, passwords, or connection strings    |
| Backup files        | Old credentials or sensitive data may remain               |
| Scripts             | May contain hardcoded credentials                          |
| Documents           | Can reveal users, systems, or internal information         |
| Usernames           | Useful for further AD enumeration                          |
| Passwords           | May provide valid credentials                              |
| Writable shares     | Users can upload files, creating additional security risks |

> Always inspect accessible SMB shares because they may contain information that helps with further enumeration.
