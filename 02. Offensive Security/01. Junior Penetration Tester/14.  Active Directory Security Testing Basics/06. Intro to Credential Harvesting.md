## Task 1: Introduction

When we gain access to a Windows computer, Windows may already have credentials and secrets stored in different places.

Instead of attacking the system with an exploit, we can sometimes find and extract credentials that Windows or applications have already stored.
| Concept                   | Simple meaning                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------------- |
| **Credential Harvesting** | Finding and extracting stored usernames, passwords, hashes, or other authentication secrets |
| **Credentials**           | Information used to prove who you are, such as usernames and passwords                      |
| **Stored Credentials**    | Credentials that Windows or applications have saved on the computer                         |
| **Local Administrator**   | An account with administrator-level control over a Windows computer                         |
| **Secrets**               | Sensitive authentication information stored by the operating system or applications         |
| **Credential Extraction** | Retrieving stored credentials/secrets from a system                                         |

> **Where Windows stores credentials and how security testers can extract them during an authorized assessment.**



### Learning Objectives
- Identify the central credential storage mechanisms in Windows and Active Directory
- Extract credentials using mimikatz and impacket
- Understand differences in output based on user privileges
- Crack hashes using Hashcat or John the Ripper

> **John the Ripper** is a free and open-source password-cracking tool. It can crack passwords stored in various formats, including hashes, passwords, and encrypted private keys. It can be used to test passwords' security and recover lost passwords.

## Task 2: Windows & Active Directory Credential Stores

Windows and Active Directory **do not store all credentials in one place**. Different authentication mechanisms require different types of credential material, so Windows stores them in different locations.

where credentials are stored, what they contain, and what privileges are required to access them is important for credential-access assessments.

| Credential Store       | Stored Where               | What It Contains                                             | Main Purpose                      |
| ---------------------- | -------------------------- | ------------------------------------------------------------ | --------------------------------- |
| **LSASS Memory**       | RAM                        | NTLM material, Kerberos tickets, and sometimes other secrets | Live authentication and SSO       |
| **SAM**                | Local Windows disk         | Local account password hashes                                | Local account authentication      |
| **NTDS.dit**           | Domain Controller disk     | Active Directory account data and password hashes            | Domain authentication             |
| **Credential Manager** | Local disk                 | Saved Windows/application credentials                        | Reusing saved credentials         |
| **Kerberos Cache**     | Memory                     | TGTs and service tickets                                     | Kerberos authentication           |
| **Windows Registry**   | Disk                       | Various configuration and credential-related secrets         | System/application configuration  |
| **DPAPI**              | Disk + user/system secrets | Protected credentials and secrets                            | Encrypting sensitive Windows data |


### LSASS Memory

**LSASS (Local Security Authority Subsystem Service)** is a Windows process that manages authentication and security policies.

The process is:
````
lsass.exe
   │
   ├── Handles Windows authentication
   ├── Enforces security policies
   ├── Maintains authentication information
   └── Supports Single Sign-On (SSO)
````

What can LSASS contain?
| Credential material          | Meaning                                                                                                                     |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **NTLM hashes**              | Password-derived hashes used by Windows authentication                                                                      |
| **LM hashes**                | Legacy password hashes; generally obsolete on modern Windows                                                                |
| **Kerberos TGT**             | Ticket-Granting Ticket used to request Kerberos service tickets                                                             |
| **Kerberos service tickets** | Tickets used to authenticate to particular services                                                                         |
| **Plaintext credentials**    | May appear in certain configurations/authentication scenarios, but are not normally present simply because a user logged in |

If an attacker gets high privileges such as **SYSTEM**, they may be able to access LSASS memory and extract authentication material, which could potentially be used for **lateral movement**.


> **LSASS (Local Security Authority Subsystem Service)** is a Windows process that enforces security policy and handles user authentication, storing credentials in memory.

> Kerberos is a computer network authentication protocol that operates based on tickets, allowing nodes to securely prove their identity to one another over a non-secure network.
> 
> It primarily aims at a client-server model and provides mutual authentication, where the user and the server verify each other's identity.
> 
> The Kerberos protocol messages are protected against eavesdropping and replay attacks, and it builds on symmetric-key cryptography, requiring a trusted third party.

> **Windows New Technology LAN Manager (NTLM)** is a suite of security protocols offered by Microsoft to authenticate users’ identity and protect the integrity and confidentiality of their activity.



### SAM + SYSTEM Hives

**Security Accounts Manager (SAM)** is a Windows database that stores password hashes for local accounts.
- **SAM**: contains local account password hashes.
- **SYSTEM**: contains the BootKey, needed to decrypt the SAM data.
- Attackers need both to recover the local password hashes.

> **SAM = password hashes**
>
> **SYSTEM = key needed to unlock them**

Typical locations:
````
C:\Windows\System32\config\SAM
C:\Windows\System32\config\SYSTEM
````
Accessing/extracting them normally requires **high privileges such as SYSTEM**.

> The recovered hashes can potentially be cracked to obtain passwords or used for authentication attacks against other systems where the same local credentials are reused.

Check:
````
dir C:\Windows\System32\config\SAM
cd C:\Windows\System32\config\
dir
````

### LSA Secrets

**LSA Secrets** are sensitive credentials that Windows stores in the registry.

They may contain:
- Cached domain credentials
- Service or scheduled-task passwords
- Other authentication secrets

Location:
````
HKLM\SECURITY\Policy\Secrets
````
Usually requires SYSTEM or high administrator privileges to access.

> **LSA Secrets = credentials Windows saves for services and authentication.**



### DPAPI Vault

**DPAPI (Data Protection API)** protects sensitive information stored by Windows and applications.

It can protect things like:
- Saved Wi-Fi passwords
- Browser credentials
- Application secrets

A **master key** is used to protect these secrets and is associated with the user's Windows account.

Master keys are commonly stored under:
````
%APPDATA%\Microsoft\Protect
````

> **DPAPI = Windows encryption system for protecting user/application secrets.**

| Store           | Main purpose                                   |
| --------------- | ---------------------------------------------- |
| **LSA Secrets** | Stores sensitive system/service credentials    |
| **DPAPI**       | Encrypts and protects user/application secrets |




### NTDS.dit

**NTDS.dit** is the main **Active Directory database** stored on a **Domain Controller**.

It contains information such as:

- Domain user accounts
- Computer accounts
- Service accounts
- NTLM password hashes
- Kerberos key material

Location:
````
C:\Windows\NTDS\ntds.dit
````
Why is it important?

If an attacker obtains the database and can recover its credential material, they may gain authentication capability for many accounts across the domain.

> **NTDS.dit = the main credential database for an Active Directory domain.**

## Task 3: Credential Extraction With Mimikatz

**Mimikatz** is one of the most powerful post-exploitation tools for Windows systems.

We will use **Mimikatz** to check different places where Windows keeps credential information:
| What we check    | Simple meaning                               |
| ---------------- | -------------------------------------------- |
| **LSASS Memory** | Credentials currently being used in memory   |
| **SAM + SYSTEM** | Password hashes of local Windows users       |
| **LSA Secrets**  | Cached/saved Windows and service credentials |
| **DPAPI**        | Protected passwords saved by Windows/apps    |


### Why Mimikatz?

Windows protects sensitive credential information. **Mimikatz is designed to interact with Windows security components and retrieve credential material** when you have sufficient privileges.

For example:
- ``LSASS``: live authentication information
- ``SAM``: local account hashes
- ``LSA``: cached/saved secrets
- ``DPAPI``: protected application credentials




### DPAPI safe
**Data Protection API (DPAPI)** is a Windows system that protects saved passwords and credentials.

Think of it like a locked storage box:
````mermaid
flowchart TD
    A[Windows / Apps] --> B[DPAPI Vault]
    B --> C[RDP credentials]
    B --> D[Web credentials]
    B --> E[Wi-Fi credentials]
    B --> F[Other saved secrets]
````


````cmd
vault::list
````

| --------------------- | -------------------------------------------------- |
| `Web Credentials`     | Web credential vault; `Items (0)` means none found |

We can extract the credentials:

This command attempts to export credentials from the available vaults.

> The password is hidden because Mimikatz cannot decrypt that particular secret in the current context.



Why can't ``svc-app`` be decrypted?

> **DPAPI secrets are tied to the Windows user who created them.**
````mermiad
flowchart TD
    subgraph Admin["Administrator"]
        A[Administrator] --> B[Can access Administrator's DPAPI data]
    end

    subgraph Svc["svc-app"]
        C[svc-app] --> D[Its DPAPI data belongs to svc-app]
    end
````
Being **Local Administrator** does not automatically mean we can decrypt every user's DPAPI secrets.

> **DPAPI = Windows' password-protection system**.

> ``vault::list`` = see the vaults

> ``vault::cred /export`` = try to extract saved credentials

> The user's DPAPI context/key is needed to decrypt that user's protected secrets.



### SAM + SYSTEM Hives

**Security Account Manager (SAM)** stores the password hashes of local Windows accounts.

However, the SAM data is protected using key material from the SYSTEM hive.

Think of it like:
````mermaid
flowchart TD
    A[SAM] --> B[Local account password hashes]
    B -->|protected by| C[SYSTEM]
````

So we need **both SAM and SYSTEM** to recover the local account hashes.

## Task 4: Credentials Harvesting With Secretsdump

#### What is secretsdump.py?

``secretsdump.py`` is part of the Impacket toolkit.

It can communicate with Windows remotely using built-in services such as:
- **SMB**: Windows file/network sharing
- **RPC** Remote Procedure Call
- **Remote Registry**: Access to registry information

What can it collect?
| Credential source      | What you may get                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| **SAM**                | Local account NTLM hashes                                                                        |
| **LSA Secrets**        | Saved Windows/service secrets                                                                    |
| **Cached credentials** | DCC2/MSCacheV2 hashes                                                                            |
| **NTDS.dit**           | Domain account credential material when targeting a Domain Controller with sufficient privileges |


### Dumping Hashes with Local Administrator

In this we run it on our attackbox:
````
secretsdump.py WRK/Administrator:'N3w34829DJdd?1'@10.220.10.20 -output local_dump
````
<img width="1852" height="740" alt="image" src="https://github.com/user-attachments/assets/93b04809-b693-4ade-8077-05adbb5df068" />



| Part                 | Meaning                          |
| -------------------- | -------------------------------- |
| `WRK`                | Target Windows computer          |
| `Administrator`      | Local Administrator account      |
| Password             | Password for that account        |
| `10.220.10.20`       | WRK's IP address                 |
| `-output local_dump` | Save the results to output files |


##### What happens?

``secretsdump.py`` connects to WRK using Windows services such as SMB/RPC.

It then retrieves two important types of information:
````mermaid
flowchart TD
    A[WRK] --> B[SAM]
    A --> C[Cached Domain Logons]

    B --> D[Local NTLM hashes]
    C --> E[DCC2 / MSCacheV2 hashes]
````

Unlike NTLM hashes, we cannot use DCC2 hashes for pass-the-hash attacks. However, we can use them to crack offline passwords. Let's add ``drgonzo``'s hash to a file called ``dc2_hash.txt``, so that we can crack it.

So in this I want to crack it on my local terminal:
````
echo '$DCC2$10240#drgonzo#d0dc1647e45cf7364ecec3c7740fce0f' > dc2_hash.txt
cat dc2_hash.txt
````

## Task 5: Conclusion


| **Topic**            | **Important Point**                                                           | **Remember**                              |
| -------------------- | ----------------------------------------------------------------------------- | ----------------------------------------- |
| **LSASS Memory**     | Stores active authentication material in memory                               | **LSASS = live credentials**              |
| **SAM**              | Stores local Windows account password hashes                                  | **SAM = local hashes**                    |
| **SYSTEM Hive**      | Contains key material needed to work with the SAM                             | **SYSTEM + SAM = local hashes**           |
| **LSA Secrets**      | Stores protected/cached credentials and service secrets                       | **LSA = saved Windows secrets**           |
| **DPAPI**            | Protects saved application/user credentials                                   | **DPAPI = protected credentials**         |
| **NTDS.dit**         | Active Directory database on a Domain Controller                              | **NTDS.dit = domain credentials**         |
| **Mimikatz**         | Can interact with LSASS, SAM, LSA, and DPAPI                                  | **Credential extraction tool**            |
| **Secretsdump**      | Can remotely retrieve Windows credential material                             | **Remote credential extraction**          |
| **DCC2 / MSCacheV2** | Cached domain logon credential; useful for offline password cracking          | **DCC2 ≠ NTLM**                           |
| **NTLM Hash**        | Password-derived hash used by Windows authentication                          | Can potentially support **Pass-the-Hash** |
| **DCSync**           | Uses AD replication functionality to retrieve domain credential material      | Can expose many domain accounts           |
| **Pass-the-Hash**    | Authenticate using an NTLM hash instead of the plaintext password             | **Hash → authentication**                 |
| **PsExec**           | Can provide a remote Windows shell when the account has sufficient privileges | **Remote shell**                          |
