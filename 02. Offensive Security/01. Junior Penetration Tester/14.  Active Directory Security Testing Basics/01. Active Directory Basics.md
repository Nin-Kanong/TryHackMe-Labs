## Task 1: Introduction

#### What is Active Directory?

**Active Directory (AD)** is Microsoft's directory service used mainly in Windows enterprise networks.

Instead of managing every computer and user separately, an organization can manage them centrally.


#### Sample:

##### Without AD:
````
Computer 1 → User accounts managed locally
Computer 2 → User accounts managed locally
Computer 3 → User accounts managed locally
Server     → User accounts managed separately
````

##### With AD:
````
              Active Directory
                     |
        ┌────────────┼────────────┐
        ↓            ↓            ↓
      Users       Computers     Servers
        |            |            |
     Alice         PC-01        Server-01
     Bob           PC-02        Server-02
````

The **Domain Controller (DC)** is the main server responsible for managing the Active Directory domain.



#### What is an Active Directory Domain?

An **AD Domain** is a logical environment containing users, computers, groups, policies, and other resources.


##### Domain Controller

A **Domain Controller (DC)** is a Windows Server that provides important AD services.

It handles things such as:
| Function            | Meaning                                 |
| ------------------- | --------------------------------------- |
| Authentication      | Verifies usernames/passwords            |
| Authorization       | Determines what users can access        |
| User management     | Creates/manages domain accounts         |
| Computer management | Manages domain computers                |
| Group management    | Controls users through groups           |
| Group Policy        | Applies security/configuration settings |
| DNS integration     | Helps computers locate domain services  |



#### Important Active Directory Components

| Component                  | Simple meaning                                 |
| -------------------------- | ---------------------------------------------- |
| **Domain**                 | A logical AD environment                       |
| **Domain Controller (DC)** | Server that manages the domain                 |
| **User**                   | Account representing a person/service          |
| **Computer**               | Machine joined to the domain                   |
| **Group**                  | Collection of users/computers                  |
| **OU**                     | Container used to organize AD objects          |
| **Group Policy**           | Rules/configuration applied to users/computers |
| **Forest**                 | Collection of one or more AD domains           |
| **Trust**                  | Relationship allowing domains to interact      |



##### **Forest

A **forest** is the highest-level structure in Active Directory.**


##### Child Domain

A **child domain** is a domain underneath another domain.


##### What is a Trust?

An **AD trust** is a relationship between domains that allows authentication or resource access across those domains.

## Task 2: Windows Domains




### Why Active Directory

Imagine a company has **5 computers** and **5 users**. An administrator can manage each computer manually.

But imagine the company grows to **157 computers** and **320 users** across multiple offices. Managing every computer separately would become difficult.

This is where **Active Directory (AD)** helps.



#### What is Active Directory?
**Active Directory** is a centralized system for managing Windows users, computers, and security policies.

The server that manages Active Directory is called a **Domain Controller (DC)**.

> **AD = Central management system**
>
> **DC = Server running AD**

<img width="452" height="362" alt="image" src="https://github.com/user-attachments/assets/0757ee60-14f8-4599-8f8c-ac24f38d52f2" />



#### Main Benefits

| Feature                    | What it does                         |
| -------------------------- | ------------------------------------ |
| **User Management**        | Create and manage users in one place |
| **Computer Management**    | Manage many Windows computers        |
| **Authentication**         | Verify usernames and passwords       |
| **Security Policies**      | Apply rules to users and computers   |
| **Centralized Management** | Manage the network from the DC       |

---

### Real-World Example

At a university, we may use:
````
Username: student01
Password: ********
````
We can log into different university computers using the same account.

The process is roughly: ``Student`` -> ``Login to Computer`` -> ``Computer asks Domain Controller`` -> ``Active Directory checks credentials`` -> ``Access granted / denied``

We don't need a separate account stored on every computer.


**DC = the server that provides Active Directory services**.

> **Note**: Active Directory centrally manages users, computers, authentication, and security policies in a Windows domain.

### Active Directory Domain Service

**AD DS** is the central system that stores and manages users, computers, groups, and other objects in a Windows domain.


Think of AD DS like a **company directory + permission system**:
````
                    AD DS
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
     Users        Machines       Groups
       │             │             │
     john          PC01$       Domain Users
     mary          PC02$       Domain Admins
````



#### Users

A **User** is an account representing either a person or a service.

##### People

For example:
````
john
mary
administrator
````
A person can use their account to:
- Log in
- Access files
- Access printers
- Use applications
 -Access network resources

##### Services

A user account can also represent a service:
````
MSSQL_Service
IIS_Service
````
A service account should normally have only the permissions required to run that service.


> **User = Person or service identity**



#### Machines

A **machine** is a computer that has joined an Active Directory domain.

When it joins the domain, AD creates a **machine account** for it.
````
Computer: ROOTDC
Machine account: ROOTDC$
````

Key Points:
- Machine accounts are security principals.
- They have limited domain permissions.
- Their passwords are automatically changed and are very long/random.
- A machine account is easy to identify because it ends with $.

> **Computer joins domain → Machine account is created** → ``PC01$``.



#### Security Groups

A **security group** is a collection of **users or machines** used to manage permissions easily.

Instead of giving permissions to each user individually:
````
John → Permission
Mary → Permission
David → Permission
````
Put them in a group:
````
IT Group
 ├── John
 ├── Mary
 └── David
````
Then give the **group** the permission, and its members inherit it.

Key Points:
- Groups can contain users and machines.
- Groups can contain other groups.
- Security groups are also security principals.
- Groups make permission management easier.
- AD creates several default groups with specific privileges.

> **Security Group = Put users/computers together and manage their permissions as one**.



Several groups are created by default in a domain that can be used to grant specific privileges to users. As an example, here are some of the most important groups in a domain:
| Security Group         | Easy Explanation                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Domain Admins**      | Full administrative control over the domain, including Domain Controllers                                  |
| **Server Operators**   | Can perform administrative tasks on Domain Controllers, but cannot modify administrative group memberships |
| **Backup Operators**   | Can perform backups and have special access to files for backup purposes                                   |
| **Account Operators**  | Can create or modify many domain accounts                                                                  |
| **Domain Users**       | Contains domain user accounts                                                                              |
| **Domain Computers**   | Contains domain computer accounts                                                                          |
| **Domain Controllers** | Contains Domain Controller computer accounts                                                               |


We can obtain the complete list of default security groups from the: https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-groups

### Security Groups vs OUs

Both **Security Groups** and **Organizational Units (OUs)** organize users and computers, but they have different purposes.

> OU = Apply policies
> 
> Group = Give permissions


#### 1. Organizational Units (OUs)

An **OU** is mainly used to organize users/computers and apply Group Policies to them.

Example:
````
THM
├── IT
│   ├── John
│   └── Mary
├── Sales
│   ├── David
│   └── Lisa
````
We could apply an IT-specific policy to everyone in the IT OU.

A user/computer belongs to one OU at a time.

> **OU → Organization + Policies**



#### 2. Security Groups

A **Security Group** is mainly used to give users or computers permissions to resources.

Example:
````
File Server
     │
     └── HR-Files
            ↑
       HR Security Group
        ├── John
        ├── Mary
        └── David
````
Members of the group can receive access to the shared folder.

A user can belong to many security groups.

Example:
````
John
 ├── IT Group
 ├── VPN Group
 └── Printer Group
````

Group → Permissions + Resources

## Task 4: Authentication Methods


When a user logs into a Windows domain, the **Domain Controller (DC)** verifies their credentials.

There are two main authentication protocols:
| Protocol     | Easy meaning                  |
| ------------ | ----------------------------- |
| **Kerberos** | Modern/default authentication |
| **NetNTLM**  | Older/legacy authentication   |

> Kerberos = Modern/default
>
> NetNTLM = Legacy/compatibility


### Kerberos Authentication

**Kerberos** is the default authentication protocol in modern Windows domains.

Instead of sending our password every time we access a service, Kerberos uses tickets.

> Authenticate once → Get a ticket → Use the ticket to access services


#### Key Distribution Center (KDC)

The **KDC** is a service running on the **Domain Controller**.

Its job is to issue Kerberos tickets: ``User`` -> ``KDC`` -> ``Kerberos Ticket`` -> ``Access services``

> **KDC = Kerberos ticket issuer**


#### Ticket Granting Ticket (TGT)

The first important ticket is the TGT.

When the user logs in: ``User`` -> ``Sends username + timestamp`` -> ``KDC`` -> ``TGT + Session Key``

The **TGT** proves that the user has already authenticated.

The user can then use the TGT to request tickets for specific services.

> **TGT = Ticket used to request other service tickets**


<img width="1047" height="416" alt="image" src="https://github.com/user-attachments/assets/2285ee7f-64e3-46e5-9c14-37782515c5a6" />



#### Session Key

When the KDC gives the user a TGT, it also provides a **Session Key**.

The session key is used for later communication/authentication steps.

Think: ``TGT + Session Key`` -> ``Request service tickets``

> Session Key = Key used during the authenticated session

<img width="1049" height="486" alt="image" src="https://github.com/user-attachments/assets/97c9bce5-60bb-4d38-a769-a9783a0eb4b9" />



#### Service Principal Name (SPN)

When a user wants to access a specific service, Kerberos needs to know which service they want.

This is identified using an **SPN**.

Example: ``MSSQL/SRV``

This could represent an SQL service running on a server.


> SPN = Identifies the service you want to access



#### Ticket Granting Service (TGS) Ticket

After receiving a TGT, the user can request a TGS ticket for a specific service.

The process is: ``TGT`` -> ``Request service ticket`` -> ``KDC`` -> ``TGS`` -> ``Access specific service``

For example: ``User`` -> ``TGT`` -> ``Request MSSQL service`` -> ``KDC`` -> ``TGS for MSSQL`` -> ``MSSQL Server``

<img width="1029" height="362" alt="image" src="https://github.com/user-attachments/assets/0a9e983f-1543-4ab9-92a0-12bbb702b422" />


| Ticket  | Purpose                      |
| ------- | ---------------------------- |
| **TGT** | Request tickets for services |
| **TGS** | Access a specific service    |

### NetNTLM Authentication

**NetNTLM** is an older authentication protocol kept mainly for compatibility.

Instead of using Kerberos tickets, NetNTLM uses a **challenge-response** process.


> **Server asks a challenge → Client creates response → DC verifies it**

<img width="1051" height="605" alt="image" src="https://github.com/user-attachments/assets/c551c99f-3bfe-48ea-b8cb-252b95fe1e3b" />


process is: ``Client`` -> ``Authentication Request`` -> ``Server`` -> ``Challenge`` -> ``Client`` -> ``Response`` -> ``Server`` -> ``Domain Controller`` -> ``Verify`` -> ``Allow / Deny``

The user's password itself is not sent across the network.



NetNTLM uses a challenge-response process to authenticate a user.

#### 1. Authentication Request

The client asks the server for access: ``Client`` → ``Server`` (Authentication Request)


#### 2. Challenge

The server creates a random challenge and sends it to the client: ``Server`` → ``Client`` (Random Challenge)



#### 3. Response

The client combines:
````
NTLM Password Hash + Challenge
          ↓
       Response
````
The client sends this response back to the server.

#### 4. Verification

The server sends the challenge + response to the Domain Controller.

``Server`` → ``Domain Controller`` (Challenge + Response)



#### 5. DC Checks

The Domain Controller calculates/checks the expected response.

``Response matches → Authentication successful``

``Response doesn't match`` → ``Authentication denied``



#### 6. Result

The server sends the result back to the client: ``DC → Server → Client`` -> ``Allow / Deny``



> **Request → Challenge → Response → Verify → Allow/Deny**

### Trees


A **Tree** is a collection of related Active Directory domains that share the same **DNS namespace**.

> **Tree = Parent domain + related subdomains**


#### Single Domain

A company can start with one domain:
````
thm.local
   │
 DC-ROOT
````
Everything is managed inside this domain.



#### Why Create More Domains?


As a company grows, it may have different departments, countries, or business divisions.

Instead of putting everything into one huge domain, we can create subdomains.

Sample:
````
thm.local
   │
   ├── uk.thm.local
   │
   └── us.thm.local
````

Here:
- ``thm.local`` = Parent domain
- ``uk.thm.local`` = Child domain
- ``us.thm.local`` = Child domain

Each domain can have its own:
- Users
- Computers
- Groups
- Domain Controller



#### Tree Structure

<img width="1218" height="963" alt="image" src="https://github.com/user-attachments/assets/38b14a8f-1c62-4bf4-8cae-65806b2d119d" />


Think of it like a family tree:
````
                 thm.local
                (Parent)
                 /      \
                /        \
     uk.thm.local       us.thm.local
       (Child)             (Child)
````
All of these domains together form a Tree.

> **Tree = Multiple related domains connected under one namespace**


##### Example

Imagine TryHackMe has: ``thm.local``

Then it creates a banking division: ``tbm.thm.local``

It could also have regional domains:
````
us.tbm.thm.local
uk.tbm.thm.local
````
Each can have its own AD environment while still being part of the larger structure.


#### Domain Admins vs Enterprise Admins

##### Domain Admins

Controls one domain: ``Domain Admins`` -> ``thm.local``



##### Enterprise Admins

Has administrative privileges across the **entire AD forest**:

``Enterprise Admins`` -> ``Entire Forest`` -> ``All Domains``

Think like:

``Domain Admins`` → One domain

``Enterprise Admins`` → Entire enterprise/forest

### Forests

A **Forest** is a collection of **multiple Active Directory Trees** that can work together and share resources.

> **Forest = Collection of Trees**

<img width="2778" height="1119" alt="image" src="https://github.com/user-attachments/assets/c774a5e8-512f-47c8-aa91-ab41b5735539" />


The two trees can have **different namespaces**, but they can be connected so that resources can be shared between them.

> **Domain -> Tree -> Forest**

### Trust Relationships

<img width="963" height="386" alt="image" src="https://github.com/user-attachments/assets/3fc59cf4-b91b-4a53-bbac-75335d0129ca" />


A **trust relationship** allows users from one Active Directory domain to access resources in another domain.


> **Trust = One domain trusts another domain's users**.


#### 1. One-Way Trust

````
Domain AAA  ─────trusts────→  Domain BBB
````

This means users from BBB can be authorized to access resources in ``AAA``: ``BBB User`` -> ``Access resource`` -> ``AAA``


> **Trust direction and access direction are opposite**.


#### 2. Two-Way Trust

Both domains trust each other: ``Domain AAA``  ←────→  ``Domain BBB``

Users from both domains can potentially be authorized to access resources in the other domain.

## Task 12: Conclusion


| Topic                          | What you need to remember                                                                            |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- |
| **AD DS**                      | Central directory for managing users, computers, groups, and policies.                               |
| **Domain Controller (DC)**     | Server that runs AD DS and authenticates/manages the domain.                                         |
| **Domain**                     | A Windows environment managed by AD.                                                                 |
| **OU (Organizational Unit)**   | Organizes users/computers and allows policies to be applied.                                         |
| **Security Group**             | Groups users/computers to manage permissions.                                                        |
| **OU vs Group**                | **OU → Policy/Organization**; **Group → Permissions**                                                |
| **Users**                      | Accounts representing people or services.                                                            |
| **Computer Accounts**          | Machines joined to the domain; usually end with `$`, e.g. `SERVER1$`.                                |
| **Workstations**               | Normal user computers. Should have fewer privileges.                                                 |
| **Servers**                    | Machines providing services to users/other servers.                                                  |
| **Domain Controllers**         | Most sensitive servers because they contain AD information and credential data.                      |
| **Kerberos**                   | Main modern AD authentication protocol.                                                              |
| **TGT**                        | Ticket used to request service tickets.                                                              |
| **TGS**                        | Ticket used to access a specific service.                                                            |
| **NetNTLM**                    | Challenge-response authentication, mainly for compatibility/legacy scenarios.                        |
| **Tree**                       | Multiple related domains sharing a namespace.                                                        |
| **Forest**                     | Collection of one or more AD trees.                                                                  |
| **Trust**                      | Allows authentication between different domains/forests.                                             |
| **Two-way trust**              | Both sides can authenticate across the trust.                                                        |
| **Delegation**                 | Give a user/group a specific administrative task without making them Domain Admin.                   |
| **GPO**                        | Group Policy Object containing Windows configuration/security settings.                              |
| **GPO Link**                   | Connects a GPO to a domain or OU so its policies apply there.                                        |
| **Security Filtering**         | Controls which users/computers a GPO applies to.                                                     |
| **Default Domain Policy**      | GPO applied to the domain.                                                                           |
| **Restricted Groups**          | Can control membership of local groups such as `Administrators`.                                     |
| **SYSVOL**                     | Network share used to distribute GPO files across domain machines.                                   |
| **GPO refresh**                | `gpupdate /force` forces a machine to refresh policies.                                              |
| **Check GPO**                  | `gpresult /r` shows which GPOs were actually applied.                                                |
| **Cross-forest user**          | With a trust, a user such as `TVM\alice.king` can potentially be added to a group in another domain. |
| **Foreign Security Principal** | AD object representing a security principal from another trusted domain/forest.                      |




### Command:

| Command                                                | Purpose                                |
| ------------------------------------------------------ | -------------------------------------- |
| `gpupdate /force`                                      | Force Group Policy update              |
| `gpresult /r`                                          | See applied GPOs                       |
| `net localgroup administrators`                        | See local Administrators group members |
| `systeminfo \| findstr /B /C:"Domain"`                 | Check computer's domain                |
| `ipconfig /all`                                        | Check IP/DNS configuration             |
| `whoami`                                               | Show current account                   |
| `Get-ADDomainController -Filter *`                     | Find domain controllers                |
| `Get-ADDomainController -Server tbm.thm.loc -Filter *` | Find DCs in a specific domain          |



| AD Concept   | Easy Meaning                         |
| ------------ | ------------------------------------ |
| **OU**       | Organization + Policy                |
| **Group**    | Permissions                          |
| **GPO**      | Configuration                        |
| **SYSVOL**   | GPO Distribution                     |
| **Kerberos** | Authentication                       |
| **Trust**    | Cross-domain / forest authentication |
| **DC**       | Central AD Server                    |
