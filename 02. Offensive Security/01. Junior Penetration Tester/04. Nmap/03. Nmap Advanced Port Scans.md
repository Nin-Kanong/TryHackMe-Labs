## Task 1: Introduction

This room is about **stealth/evasion scanning**: manipulating the TCP flags in the TCP header (RFC 793) so we can probe ports without completing a connection, and hiding who is scanning.

### 1. The Core Idea (TCP Flags)
<img width="2400" height="1600" alt="image" src="https://github.com/user-attachments/assets/cefcca9a-1af9-4506-96e2-a135bc675dac" />

The TCP header has 6 flags: **URG, ACK, PSH, RST, SYN, FIN**.

Normal connection = SYN → SYN/ACK → ACK (3‑way handshake).

Stealth scans send **"weird" flag combinations** that don't belong to any real connection, then watch the reaction:

| **Response 
you get**                | **Meaning**                                                |
| ----------------------------------- | ---------------------------------------------------------- |
| **RST** back                        | Port is **closed**                                         |
| **No response** (or **ICMP error**) | Port is **open | filtered** *(packet was dropped/ignored)* |



### 2. Advanced Scan Types (most important table)
| **Scan**         | **Nmap flag** | **What it sends**         | **Purpose / Explanation**                                    |
| ---------------- | ------------- | ------------------------- | ------------------------------------------------------------ |
| **Null Scan**    | `-sN`         | No flags                  | Closed → **RST**; open/filtered → **silent**                 |
| **FIN Scan**     | `-sF`         | FIN only                  | Probes without starting a TCP connection                     |
| **Xmas Scan** 🎄 | `-sX`         | FIN + PSH + URG           | Similar to FIN; may bypass some stateless firewalls          |
| **Maimon Scan**  | `-sM`         | FIN + ACK                 | Exploits behavior in some older BSD-derived systems          |
| **ACK Scan**     | `-sA`         | ACK only                  | **Does not identify open ports**; maps firewall rules        |
| **Window Scan**  | `-sW`         | ACK + checks Window field | On some older systems: **Window > 0 = open**, **0 = closed** |
| **Custom Scan**  | `--scanflags` | Any flags we choose      | Create a custom TCP probe for testing firewall/IDS behavior  |


#### Memory trick:
- Null = nothing
- FIN = FIN only
- Xmas = FIN+PSH+URG
- Maimon = FIN+ACK


### 3. Evasion & Spoofing
| **Technique**          | **Nmap option**     | **Explanation**                                                             |
| ---------------------- | ------------------- | --------------------------------------------------------------------------- |
| **Spoof IP**           | `-S <IP>`           | Fake your source IP; replies go to the spoofed IP instead of you            |
| **Spoof MAC**          | `--spoof-mac <MAC>` | Fake your hardware/MAC address; works on the same local network             |
| **Decoy Scan**         | `-D <decoys>`       | Mix your real IP with fake IPs so the target has difficulty identifying you |
| **Fragmented Packets** | `-f` / `-ff`        | Split packets into smaller fragments to test how firewalls/IDS handle them  |
| **Idle / Zombie Scan** | `-sI <zombie>`      | Use another idle host as the apparent source of the scan                    |


### 4. Getting More Detail (verbosity)
- ``-v`` / ``-vv``: verbose output
- ``--reason``: shows why Nmap decided a port is open/closed (e.g. "rst", "no‑response")
- debug flags: deepest troubleshooting level

### 1. NULL Scan — -sN

**What it sends**: TCP packet with NO flags.

<img width="2400" height="1240" alt="image" src="https://github.com/user-attachments/assets/8630844e-d5e5-46d4-943d-da5cb319415d" />

| Server port | Response    | Meaning              |
| ----------- | ----------- | -------------------- |
| 🟢 Open     | No response | `open` or `filtered` |
| 🔴 Closed   | `RST, ACK`  | `closed`             |

**Null scan (-sN)** sends a flag‑less packet; closed ports scream RST, open ports stay silent — and silence means "open|filtered."

## Task 3: TCP Maimon Scan

### 1. What is a Maimon Scan?
A TCP Maimon Scan is an Nmap scan that sends a TCP packet with two flags:
| Flag    | Full Name      | Purpose                               |
| ------- | -------------- | ------------------------------------- |
| **FIN** | Finish         | Indicates the end of a TCP connection |
| **ACK** | Acknowledgment | Acknowledges a TCP packet             |

<img width="2400" height="1400" alt="image" src="https://github.com/user-attachments/assets/48d4f470-c31b-453f-b476-0773d749c91e" />

#### Command:
````
sudo nmap -sM TARGET
````


Example:
````
sudo nmap -sM 10.201.89.221
````
<img width="983" height="180" alt="image" src="https://github.com/user-attachments/assets/b94a6b4e-7dd2-455b-b1a4-03d708986457" />


- ``-sM`` = Maimon scan (sends FIN+ACK flags).
- ``All 1000 scanned ports are in ignored states`` + ``Not shown: 1000 closed tcp ports (reset)`` → every port replied with RST, so Nmap considers all 1000 ports closed and hides them (nothing interesting to show).


> The target is Linux. Per the TCP rules, any packet containing **ACK** that isn't part of a real connection gets an **RST back — even from open ports**. So the Maimon scan sees everything as closed and finds 0 open ports here.


### 2. How does it work?
The scanner sends:
````
Scanner
   |
   | FIN + ACK
   ↓
 Target
````
On certain BSD-derived systems:

| Target Port | Response    | Nmap Interpretation |
| ----------- | ----------- | ------------------- |
| Open        | No response | Open                |
| Closed      | RST         | Closed              |

> The important point is that some systems respond differently depending on whether the port is open.

### 3. Why is it unusual?

On most modern systems, both open and closed ports may respond with RST.
````
FIN + ACK
    ↓
Target
    ↓
RST
````
Therefore:
````
Open port   → RST
Closed port → RST
````
Nmap cannot tell them apart.

That's why the Maimon scan is not reliable on most modern networks.

## Task 5: Spoofing and Decoys

### 1. IP Spoofing

**Spoofing** means making the scan packets look like they came from another IP address.

<img width="2400" height="1476" alt="image" src="https://github.com/user-attachments/assets/169dabb2-9d13-4b7c-8566-ac9eb6009b69" />

#### Command Syntax:
````
nmap -S SPOOFED_IP TARGET
````

Example:
````
nmap -S 192.168.157.89 10.48.140.243
````
<img width="1891" height="779" alt="image" src="https://github.com/user-attachments/assets/6ddbe216-1933-4429-9480-e5c6d1c7e21c" />

Now we see this, but not yet full correct.

### 2. Specify Network Interface

Use ``-e`` to tell Nmap which network interface to use.

````
nmap -e INTERFACE -Pn -S SPOOFED_IP TARGET
````
| Option | Meaning                       |
| ------ | ----------------------------- |
| `-e`   | Select network interface      |
| `-Pn`  | Don't use ping/host discovery |
| `-S`   | Set spoofed source IP         |


````
nmap -e eth3 -Pn -S 192.168.157.89 10.48.140.243
````


### 3. MAC Address Spoofing
We can also change the source MAC address when the attacker and target are on the same Ethernet/Wi-Fi network.
````
nmap --spoof-mac SPOOFED_MAC TARGET
````

| Type         | Option        |
| ------------ | ------------- |
| IP spoofing  | `-S`          |
| MAC spoofing | `--spoof-mac` |


### 4. Decoy Scan
A decoy scan makes the scan appear to come from multiple IP addresses.
````
        IP 10.10.0.1
             \
        IP 10.10.0.2 ----\
                          → Target
        Attacker IP -----/
````
Nmap option:
````
-D
````
Example from the lesson:
````
nmap -D 10.10.0.1,10.10.0.2,ME 10.48.140.243
````

| Value       | Meaning      |
| ----------- | ------------ |
| `10.10.0.1` | Decoy IP     |
| `10.10.0.2` | Decoy IP     |
| `ME`        | Our real IP |

## Task 6: Fragmented Packets


### Firewall

A firewall controls network traffic based on rules.

| Firewall | Meaning                            |
| -------- | ---------------------------------- |
| Allow    | Lets traffic through               |
| Block    | Stops traffic                      |
| Filter   | Decides whether traffic is allowed |

A firewall can inspect IP and TCP/UDP headers.


### IDS

**IDS = Intrusion Detection System**

It monitors network traffic and looks for suspicious patterns.
````
Network traffic
      ↓
     IDS
      ↓
Suspicious?
   ↓       ↓
  Yes      No
 Alert    Allow
````

## Task 7: Idle / Zombie Scan

### 1. What is an Idle Scan?

An Idle Scan uses another machine, called the zombie, to make the scan appear to come from the zombie's IP address.

Source: https://nmap.org/book/idlescan.html

#### Main command
````
nmap -sI ZOMBIE_IP TARGET
````
| Part        | Meaning                     |
| ----------- | --------------------------- |
| `-sI`       | Idle/Zombie Scan            |
| `ZOMBIE_IP` | IP address of the idle host |
| `TARGET`    | Target machine              |

<img width="2400" height="1420" alt="image" src="https://github.com/user-attachments/assets/65af2fb1-b54e-4449-b88f-551011be9861" />

#### 3 step:
| Step  | What happens                                                  |
| ----- | ------------------------------------------------------------- |
| **1** | Ask the zombie to respond and record its current **IP ID**    |
| **2** | Send a SYN to the target, pretending it came from the zombie  |
| **3** | Ask the zombie to respond again and compare its new **IP ID** |

> The zombie's IP ID increases when it responds to traffic.



### Idle Scan — Closed Port

<img width="2400" height="1460" alt="image" src="https://github.com/user-attachments/assets/84e5cc89-c773-4c59-a3ee-690aabded94b" />

| Step | What happens                                                              |
| ---- | ------------------------------------------------------------------------- |
| 1    | Attacker sends a SYN to the target using the **Zombie IP** as the source. |
| 2    | Target port is **closed**.                                                |
| 3    | Target sends **RST** to the Zombie.                                       |
| 4    | Zombie does not respond to the unexpected RST.                            |
| 5    | Zombie's **IP ID does not increase** because it did not send a response.  |



### Idle Scan — Open Port

<img width="2400" height="1460" alt="image" src="https://github.com/user-attachments/assets/737267b3-75f2-4fa1-a5e8-158cd2333823" />

| Step | What happens                                                              |
| ---- | ------------------------------------------------------------------------- |
| 1    | Attacker sends a SYN to the target using the **Zombie IP** as the source. |
| 2    | Target port is **open**.                                                  |
| 3    | Target sends **SYN/ACK** to the Zombie.                                   |
| 4    | Zombie receives this unexpected packet and sends **RST**.                 |
| 5    | Zombie's **IP ID increases by 1**.                                        |
| 6    | Attacker compares the IP ID before and after the scan.                    |


#### Compare the IP ID
| IP ID Difference | Result             |
| ---------------: | ------------------ |
|            **1** | Closed or filtered |
|            **2** | Open               |

## Task 9: Summary

### Scan Types

| Scan            | Option        | Main Purpose              |
| --------------- | ------------- | ------------------------- |
| TCP Null Scan   | `-sN`         | Sends no TCP flags        |
| TCP FIN Scan    | `-sF`         | Sends FIN                 |
| TCP Xmas Scan   | `-sX`         | Sends FIN + PSH + URG     |
| TCP Maimon Scan | `-sM`         | Sends FIN + ACK           |
| TCP ACK Scan    | `-sA`         | Check firewall filtering  |
| TCP Window Scan | `-sW`         | Check TCP Window behavior |
| Custom TCP Scan | `--scanflags` | Choose custom TCP flags   |



### Spoofing & Evasion

| Technique         | Option            | Purpose                        |
| ----------------- | ----------------- | ------------------------------ |
| Spoofed Source IP | `-S IP`           | Change source IP               |
| Spoofed MAC       | `--spoof-mac MAC` | Change source MAC              |
| Decoy Scan        | `-D IP1,IP2,ME`   | Make multiple apparent sources |
| Idle/Zombie Scan  | `-sI ZOMBIE_IP`   | Scan through an idle host      |
| Fragment 8 bytes  | `-f`              | Fragment IP packets            |
| Fragment 16 bytes | `-ff`             | Use larger fragments           |


### Other Useful Options
| Option               | Purpose                                 |
| -------------------- | --------------------------------------- |
| `--source-port PORT` | Specify source port                     |
| `--data-length NUM`  | Add random data to packets              |
| `--reason`           | Explain why Nmap reached its conclusion |
| `-v`                 | Verbose                                 |
| `-vv`                | Very verbose                            |
| `-d`                 | Debugging                               |
| `-dd`                | More debugging                          |
