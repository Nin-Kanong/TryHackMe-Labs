### 3. Tables, Rows, and Columns
Imagine a ``Books`` table:
| id | Name                       | Published_date |
| -: | -------------------------- | -------------- |
|  1 | Android Security Internals | 2014-10-14     |
|  2 | Bug Bounty Bootcamp        | 2021-11-16     |
|  3 | Car Hacker's Handbook      | 2016-02-25     |


**Table** = entire collection of related data.

**Column** = one type of information, such as Name.

**Row** = one complete record, such as:

````
1 | Android Security Internals | 2014-10-14
````
Remember:
````
DATABASE
   │
   └── TABLE
        ├── Column → What information?
        │
        └── Row    → One complete record
````



### 4. Data Types
Columns usually specify what kind of data they accept.
| Data Type     | Stores         | Example      |
| ------------- | -------------- | ------------ |
| String        | Text           | `"John"`     |
| Integer       | Whole number   | `25`         |
| Float/Decimal | Decimal number | `19.99`      |
| Date          | Date           | `2026-08-01` |

Example:
````
id             → Integer
name           → String
published_date → Date
````

### 5. Primary Key
A **Primary Key (PK)** uniquely identifies each row.
````
Books
┌────┬──────────────────────────┐
│ id │ Name                     │
├────┼──────────────────────────┤
│ 1  │ Android Security         │
│ 2  │ Bug Bounty Bootcamp      │
│ 3  │ Car Hacker's Handbook    │
└────┴──────────────────────────┘
  ↑
Primary Key
````
The ``id`` cannot identify two different records with the same value.

**Primary Key** = **unique ID of a record**.


### 6. Foreign Key
A **Foreign Key (FK)** connects one table to another.

Example:
````
BOOKS                         AUTHORS
┌────┬───────────┬─────────┐   ┌────┬──────────┐
│ id │ Book      │author_id│   │ id │ Author   │
├────┼───────────┼─────────┤   ├────┼──────────┤
│ 1  │ Book A    │    2    │──►│ 2  │ Nikolay  │
└────┴───────────┴─────────┘   └────┴──────────┘
                    FK              PK
````
Here:
````
Books.author_id
       │
       └──────────► Authors.id
````
This creates a relationship between the two tables.

### 1. What is SQL?
**SQL** = **Structured Query Language**

SQL is used to communicate with and manage data in relational databases.
<img width="650" height="700" alt="image" src="https://github.com/user-attachments/assets/b0946b16-b688-4f8a-9871-08b30566a371" />

Example:
````

````
Database, show me all records from the ``users`` table.



### 2. What is a DBMS?
A **DBMS (Database Management System)** is software that manages databases.

Examples include ``MySQL``, ``PostgreSQL``, ``MariaDB``, and ``Microsoft SQL Server``.

Think of the relationship as:
````
SQL = Language
DBMS = Software
Database = Stored Data
````
For this lab, we're using **MySQL**.


### 3. What Can SQL Do?
SQL can **query**, **create**, **update**, and **manage** database data.

The four operations you'll use frequently are:
| Operation | SQL      | Meaning       |
| --------- | -------- | ------------- |
| Create    | `INSERT` | Add new data  |
| Read      | `SELECT` | Retrieve data |
| Update    | `UPDATE` | Modify data   |
| Delete    | `DELETE` | Remove data   |

These are known as **CRUD**.


### 4. Why Use SQL?
Our lesson highlights four main benefits:
| Benefit              | Meaning                                          |
| -------------------- | ------------------------------------------------ |
| **Fast**           | Can retrieve large amounts of data quickly       |
| **Easy to learn** | Syntax is relatively close to English            |
| **Reliable**       | Structured databases help maintain accurate data |
| **Flexible**      | Supports simple and complex data queries         |

Example:
````
SELECT name
FROM users
WHERE age >= 18;
````
Mean: Select the ``name`` from ``users`` where age is 18 or older.

## Task 5: CRUD Operations

**CRUD** represents the four basic operations used to manage data in a database:
| CRUD  | Operation | SQL Command | Purpose              |
| ----- | --------- | ----------- | -------------------- |
| **C** | Create    | `INSERT`    | Add new data         |
| **R** | Read      | `SELECT`    | Retrieve/view data   |
| **U** | Update    | `UPDATE`    | Modify existing data |
| **D** | Delete    | `DELETE`    | Remove data          |


### 1. CREATE: INSERT INTO
``Create`` means adding a ``new row/record`` to a table.
````
INSERT INTO books (id, name, published_date, description)
VALUES (
    1,
    'Android Security Internals',
    '2014-10-14',
    'An In-Depth Guide to Android''s Security Architecture'
);
````


Example:
````
USE thm_books;
SELECT * FROM books;
````
````
INSERT INTO books (id, name, published_date, description)
VALUES (
    99,
    'Test Book',
    '2026-08-02',
    'This is a test book'
);
````

| ------------------- | ----------------------- |
| `INSERT INTO books` | Add a record to `books` |
| `(id, name, ...)`   | Columns receiving data  |

### 3. UPDATE: UPDATE
Update means modifying an existing record.
````
UPDATE books
SET description = 'This book has been updated.'
WHERE id = 99;
````
<img width="545" height="171" alt="image" src="https://github.com/user-attachments/assets/4fc6d9f8-53ac-4e66-8352-6e4a34b5fa5d" />

Verify:

<img width="656" height="219" alt="image" src="https://github.com/user-attachments/assets/13d9173f-2880-4a1c-a5fb-e20e9a49197c" />


| Part                    | Meaning                  |
| ----------------------- | ------------------------ |
| `UPDATE books`          | Modify the `books` table |
| `SET description = ...` | Set a new value          |
| `WHERE id = 1`          | Only modify book ID `1`  |


``WHERE`` is very important
Compare:
````
UPDATE books
SET description = 'New';
````
This could change **every row**.

But:
````
UPDATE books
SET description = 'New'
WHERE id = 1;
````
changes only the selected row.

````


Again, ``WHERE`` is extremely important.
````

````
could delete all rows from ``books``.

Whereas:
````
DELETE FROM books
WHERE id = 1;
````
deletes only ID ``1``.

## Task 6: SQL Clauses
A **clause** is a part of an SQL statement that controls ``which data is selected``, ``grouped``, ``filtered``, or ``sorted``.

In this task, use:
````
USE thm_books;
````

The four important clauses are:
| Clause     | Simple meaning         |
| ---------- | ---------------------- |
| `DISTINCT` | Remove duplicates      |
| `GROUP BY` | Group matching values  |
| `ORDER BY` | Sort results           |
| `HAVING`   | Filter grouped results |

Return matching groups
````



### WHERE vs HAVING

This distinction is important:
| Clause   | Filters                             |
| -------- | ----------------------------------- |
| `WHERE`  | Individual rows **before grouping** |
| `HAVING` | Groups **after `GROUP BY`**         |

## Task 7: Operators
**Operators** help SQL **filter and compare data**.

````
USE thm_books2;
````
<img width="662" height="159" alt="image" src="https://github.com/user-attachments/assets/681e1ac1-064f-4a61-8744-6a1c8226eb1b" />


There are two main groups:
````
SQL Operators
     │
     ├── Logical Operators
     │    ├── LIKE
     │    ├── AND
     │    ├── OR
     │    ├── NOT
     │    └── BETWEEN
     │
     └── Comparison Operators
          ├── =
          ├── !=
          ├── <
          ├── >
          ├── <=
          └── >=
````


### 1. LIKE: Search for a Pattern
``LIKE`` finds text matching a pattern.
````
SELECT *
FROM books
WHERE description LIKE '%guide%';
````
<img width="1244" height="302" alt="image" src="https://github.com/user-attachments/assets/97b78622-0183-4105-813c-e46fe2b3edf2" />

``%`` means anything can appear before or after.
````
'%guide%'

A Guide for Developers       ✅
The Guide to Security        ✅
Security Guide               ✅
Hello World                  ❌
````
Easy memory: ``LIKE`` = **contains/matches text**



## 2. AND: Both Conditions Must Be True
````
SELECT *
FROM books
WHERE category = 'Offensive Security'
AND name = 'Bug Bounty Bootcamp';
````
<img width="1191" height="258" alt="image" src="https://github.com/user-attachments/assets/beade5da-8df5-4736-94c0-0ef8ca94d9f0" />


``AND`` = **condition 1 AND condition 2**




### 3. OR: At Least One Condition Must Be True
````
SELECT *
FROM books
WHERE name LIKE '%Android%'
OR name LIKE '%iOS%';
````


``OR`` = **either condition can be true**



### 4. NOT: Opposite / Exclude
``NOT`` excludes matching values.
````
SELECT *
FROM books
WHERE NOT description LIKE '%guide%';
````
<img width="987" height="232" alt="image" src="https://github.com/user-attachments/assets/40dec588-1160-4b9d-bd9f-f06686ef674f" />


Meaning:
````
Contains "guide"     → ❌ Don't show
Doesn't contain it   → ✅ Show
````

``NOT`` = **exclude / opposite**




### 5. BETWEEN — Inside a Range
````
SELECT *
FROM books
WHERE id BETWEEN 2 AND 4;
````
<img width="1223" height="271" alt="image" src="https://github.com/user-attachments/assets/4c1969d5-e405-469c-bd08-c217abca47f6" />
