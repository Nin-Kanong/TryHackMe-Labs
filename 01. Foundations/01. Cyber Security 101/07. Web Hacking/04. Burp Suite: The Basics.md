## Task 2: What is Burp Suite?

### What is Burp Suite?

**Burp Suite** is a **Java-based web application security testing framework**. It is commonly used by penetration testers to test:
- Websites
- Web applications
- Mobile application backends
- APIs

Its key capability is working with HTTP/HTTPS traffic between a browser and web server.
````
Browser
   │
   │ HTTP/HTTPS
   ▼
┌──────────────────┐
│    Burp Suite    │
│ Intercept        │
│ Inspect          │
│ Modify           │
└──────────────────┘
   │
   ▼
Web Server
````
<img width="675" height="290" alt="image" src="https://github.com/user-attachments/assets/7d2924b4-a6fe-4ba1-a0f0-b700ae0acc4c" />




Burp can intercept a request before it reaches the server, allow you to inspect or modify it, and then forward it. It can also inspect responses coming back from the server.


### Burp Suite Editions
| Edition          | Main Purpose                                     | License |
| ---------------- | ------------------------------------------------ | ------- |
| **Community**    | Learning and manual web testing                  | Free    |
| **Professional** | Professional penetration testing                 | Paid    |
| **Enterprise**   | Automated, continuous web vulnerability scanning | Paid    |


### Community Edition
This is the edition used in this room. It provides the core Burp Suite features needed to learn manual web application testing.


### Professional Edition

Adds advanced functionality such as:
- Automated vulnerability scanner
- Faster/unrestricted Intruder
- Report generation
- Extensions
- Burp Collaborator
- Built-in API/integration capabilities

### Enterprise Edition
Primarily designed for organizations to perform continuous automated vulnerability scanning across many web applications.

````
Community
   ↓
Manual Security Testing

Professional
   ↓
Advanced Penetration Testing

Enterprise
   ↓
Continuous Automated Scanning
````

## Task 3: Features of Burp Community
Burp Suite Community provides several important tools for manual web application security testing.

| Tool          | What it does                                              | Easy way to remember       |
| ------------- | --------------------------------------------------------- | -------------------------- |
| **Proxy**     | Intercepts and modifies HTTP/HTTPS requests and responses | **Capture traffic**        |
| **Repeater**  | Resends and modifies the same request repeatedly          | **Test again & again**     |
| **Intruder**  | Sends many requests with different input values           | **Automate/fuzz requests** |
| **Decoder**   | Encodes and decodes data                                  | **Transform data**         |
| **Comparer**  | Compares two pieces of data                               | **Find differences**       |
| **Sequencer** | Tests randomness of tokens/session values                 | **Check randomness**       |
| **Extender**  | Adds extensions/plugins to Burp                           | **Add features**           |

#### Intercept On

Click Intercept is off to turn interception on.
````
Browser
   │
   │ Request
   ▼
┌────────────────┐
│   Burp Proxy   │
│ INTERCEPT ON   │
└────────────────┘
        │
        │ Request PAUSED
        ▼
   Inspect/Edit
        │
     Forward
        ▼
     Server
````
Now Burp pauses matching requests so you can inspect or modify them before continuing.

## Task 5: The Dashboard
The **Dashboard** is Burp Suite's main monitoring area. It shows what Burp is doing, events occurring, and security findings.

<img width="1919" height="1079" alt="image" src="https://github.com/user-attachments/assets/3ea9b087-9231-4ce8-863c-6569d8245686" />


### The 4 Dashboard Sections
| #     | Section            | What it does                                               | Easy meaning                    |
| ----- | ------------------ | ---------------------------------------------------------- | ------------------------------- |
| **1** | **Tasks**          | Shows and manages background tasks                         | 🛠️ What Burp is **doing**      |
| **2** | **Event log**      | Shows Burp events, errors, connections and Proxy activity  | 📋 What **happened**            |
| **3** | **Issue activity** | Shows vulnerabilities discovered by scanning               | ⚠️ What Burp **found**          |
| **4** | **Advisory**       | Explains a selected vulnerability and possible remediation | 📖 How to **understand/fix it** |



### 1. Tasks

The top-left area.

It manages background activities performed by Burp.

Tasks

  ├── Running
  ├── Paused
  └── Finished
````
For example, Burp Community may have a Live passive crawl task that records pages you visit.

The bottom-left area.

It records operational information such as:
````
Proxy started

Error occurred
Task started
````
Useful when something isn't working and you need to troubleshoot.

> **Remember**: ``Event Log = Burp's activity history``

#### filters
- **Critical** → serious Burp problems
- **Error** → failed connections/operations

### 3. Issue Activity
**Issue Activity** shows security vulnerabilities/issues that Burp Suite discovers while testing a web application.

It displays security issues/vulnerabilities found by Burp's automated scanning features, particularly in Burp Suite Professional.

Examples shown in your screenshot include:
````
Cross-site scripting (XSS)
XML external entity injection
Web cache poisoning
External service interaction
````
Issues may also be classified by severity:
````
High → Medium → Low → Information
````
> **Remember**: Issue Activity = Vulnerabilities found

> **⚠️ Important**: This feature is mainly associated with Burp Suite Professional's automated scanning. In Community Edition, you generally won't get the same automated Issue Activity results.

````

## Task 8: Introduction to the Burp Proxy


| Feature                   | What it does                                                    | Easy meaning                |
| ------------------------- | --------------------------------------------------------------- | --------------------------- |
| **Intercept requests**    | Stops requests before they reach the server                     | 🛑 Catch outgoing requests  |
| **Forward**               | Sends an intercepted request onward                             | ➡️ Let it continue          |
| **Drop**                  | Deletes/stops the intercepted request                           | ❌ Block it                  |
| **Edit request**          | Lets you modify headers, parameters, cookies, etc.              | ✏️ Change request           |
| **Capture & Logging**     | Records traffic passing through Proxy                           | 📝 Save traffic             |
| **HTTP history**          | Shows previously captured HTTP/HTTPS requests and responses     | 📜 HTTP traffic history     |
| **WebSockets history**    | Records WebSocket messages                                      | 🔄 WebSocket history        |
| **Proxy settings**        | Controls how the Proxy operates                                 | ⚙️ Configure Proxy          |
| **Response interception** | Stops responses before they reach your browser                  | 🛑 Catch incoming responses |
| **Match and Replace**     | Automatically finds and modifies matching request/response data | 🔄 Automatic modification   |
