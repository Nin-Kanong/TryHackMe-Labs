## Essential Concepts

### 1. VARIABLES

Three ways to declare variables:
| **Keyword** | **Scope**       | **Use When**                                 |
| ----------- | --------------- | -------------------------------------------- |
| `var`       | Function-scoped | Older code (avoid in modern JavaScript)      |
| `let`       | Block-scoped    | When the value will change                   |
| `const`     | Block-scoped    | When the value won't change (default choice) |

Use ``const`` by default, ``let`` when you need reassignment, avoid ``var``.


### 2. DATA TYPES

Primitive Types:
- **string**: text (``"hello"``)
- **number**: integers/decimals (``42``, ``3.14``)
- **boolean**: ``true`` or ``false``
- **null**: intentional empty value
- **undefined**: variable declared but not assigned
- **object**: complex data (arrays, objects)

## Task 3: Javascript Overview

JavaScript (JS) is an interpreted language (runs directly in the browser, no compilation needed).

JS code can:
- Create variables to store data.
- Use data types (number, string, boolean, etc.).
- Make decisions with control flow (if, else, switch).
- Repeat actions with loops.
- Organize code into functions for reuse.

These are the basic building blocks for creating interactive web applications.

````
// Hello, World! program
console.log("Hello, World!");

// Variable and Data Type
let age = 25; // Number type

// Control Flow Statement
if (age >= 18) {
    console.log("You are an adult.");
} else {
    console.log("You are a minor.");
}

// Function
function greet(name) {
    console.log("Hello, " + name + "!");
}

// Calling the function
greet("Bob");
````

## Task 4: Integrating JavaScript in HTML

- JavaScript (JS) works with HTML and CSS to make web pages dynamic and interactive.
- JS is not used to create page content—HTML does that. JS adds behavior and interactivity.
- There are 2 ways to add JavaScript to HTML:
  - Internal JavaScript – write JS inside the HTML file using the ``<script>`` tag.
  - External JavaScript – write JS in a separate ``.js`` file and link it to the HTML file.


Internal JavaScript
JS code is written inside the HTML file.
Use the ``<script>`` tag.
The ``<script>`` tag can be placed:
Inside the ``<head>`` section (runs before page content loads).
Inside the ``<body>`` section (commonly placed near the end to interact with page elements).

````
<!DOCTYPE html>
<html>
<head>
    <title>Internal JavaScript</title>
</head>
<body>

    <h1>Hello JavaScript</h1>

    <script>
        console.log("Hello, World!");
    </script>

</body>
</html>
````
| Method          | Description                                   |
| --------------- | --------------------------------------------- |
| **Internal JS** | JS code inside the HTML file using `<script>` |
| **External JS** | JS code stored in a separate `.js` file       |

## Task 6: Bypassing Control Flow Statements

JavaScript control flow determines which code executes and when.
| Control flow | Purpose                            | Example                |
| ------------ | ---------------------------------- | ---------------------- |
| `if`         | Run code when a condition is true  | `if (age >= 18)`       |
| `if...else`  | Choose between two paths           | Adult vs minor         |
| `switch`     | Choose between multiple cases      | Menu/options           |
| `for`        | Repeat code a set number of times  | `for (...)`            |
| `while`      | Repeat while condition is true     | `while (...)`          |
| `do...while` | Execute once, then check condition | `do {...} while (...)` |

#### Why this design is insecure
The major problem is where the authentication decision happens.

If authentication is implemented entirely in browser-side JavaScript:
````
Browser
   │
   ├── login.html
   ├── JavaScript
   │      │
   │      └── Credentials / validation logic
   │
   ▼
Authentication decision
````
the user controls the environment executing that JavaScript.

That means client-side code can generally be viewed and modified through browser development tools.

A secure design instead looks like:
````
User
 │
 ▼
Browser
 │
 │ Username + Password
 ▼
Server
 │
 ├── Validate credentials
 ├── Check database
 └── Create authenticated session
 │
 ▼
Browser receives session
````
The server, rather than JavaScript in the browser, makes the final authorization decision.


#### Client-side vs Server-side Authentication
| Client-side check              | Server-side check                        |
| ------------------------------ | ---------------------------------------- |
| Runs in user's browser         | Runs on server                           |
| User can inspect code          | Server logic isn't sent to browser       |
| User can modify execution      | User cannot directly modify server logic |
| Good for UI validation         | Appropriate for authentication           |
| Must not enforce authorization | Server should enforce authorization      |

## Task 7: Exploring Minified Files
This section explains JavaScript minification, obfuscation, and deobfuscation.


### 1. Minification
``Minification`` makes JavaScript files smaller by removing unnecessary characters.

Normal JavaScript:
````
function hi() {
    alert("Welcome to THM");
}

hi();
````

A minified version might look like:
````
function hi(){alert("Welcome to THM")}hi();
````
Both perform the same action.

| Normal code                 | Minified code                  |
| --------------------------- | ------------------------------ |
| Easy for humans to read     | Harder to read                 |
| Contains spaces/line breaks | Removes unnecessary formatting |
| Larger file                 | Smaller file                   |
| Same functionality          | Same functionality             |
