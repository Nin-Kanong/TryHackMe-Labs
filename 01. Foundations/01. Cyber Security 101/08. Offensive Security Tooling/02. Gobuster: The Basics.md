## Task 3: Gobuster: Introduction


### 1. What is Gobuster?
**Gobuster** is an open-source offensive-security enumeration tool written in Go.

It uses **wordlists + brute force** to discover resources.
| Gobuster can enumerate | Example                         |
| ---------------------- | ------------------------------- |
| Web directories        | `/admin`, `/images`, `/uploads` |
| Files                  | `/login.php`, `/config.php`     |
| DNS subdomains         | `dev.example.com`               |
| Virtual Hosts (VHosts) | `admin.example.com`             |
| Amazon S3 buckets      | Bucket names                    |
| Google Cloud Storage   | Bucket names                    |


### 2. Enumeration vs Brute Force


#### Enumeration
**Enumeration** means listing/discovering available resources, whether they are accessible or not.

Example:
````
Target Website
     │
     ▼
 Gobuster
     │
     ├── /admin
     ├── /images
     ├── /backup
     └── /login
````


#### Brute Force
**Brute force** means trying many possibilities until something matches.

Gobuster normally gets those possibilities from a wordlist:
````
Wordlist
│
├── admin
├── images
├── login
├── backup
└── uploads
       │
       ▼
    Gobuster
       │
       ▼
Target Website
````

## Task 4: Directory & File Enumeration

### What is dir mode?
Gobuster ``dir`` mode finds hidden directories and files on a web server.
````
Website
   │
   ▼
Gobuster + Wordlist
   │
   ├── /admin       → 200
   ├── /login       → 200
   ├── /images      → 301
   └── /backup      → 404
````
For example, a WordPress site commonly has directories like:
````
wordpress/
├── wp-admin/

└── wp-includes/
````

## Task 5: Subdomain Enumeration
Gobuster's ``dns`` mode is used to discover subdomains of a target domain.

### Simple idea
Suppose the main domain is:
````
example.thm
````
There might also be:
````
example.thm
│
├── www.example.thm
├── shop.example.thm
├── academy.example.thm
└── primary.example.thm
````
Gobuster uses a wordlist to try possible subdomain names.


### Basic command
````
gobuster dns -d DOMAIN -w WORDLIST
````

Example:
````
gobuster dns -d "offensivetools.thm" -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt
````
<img width="1276" height="498" alt="image" src="https://github.com/user-attachments/assets/342d7a97-3ea2-4c29-bf85-e26468e5af6f" />


````
gobuster dns --help
````
<img width="1132" height="561" alt="image" src="https://github.com/user-attachments/assets/e0b1d183-ad83-4fb9-ba5f-7ba1c276302e" />

| Flag | Long flag      | Purpose                                   |
| ---- | -------------- | ----------------------------------------- |
| `-d` | `--domain`     | Target domain                             |
| `-w` | `--wordlist`   | Subdomain wordlist                        |
| `-i` | `--show-ips`   | Show IP address for discovered subdomains |
| `-c` | `--show-cname` | Show CNAME records                        |
| `-r` | `--resolver`   | Use a specific DNS server                 |


#### How it works
If we wordlist contains:
````
www
admin
shop
dev
academy
````
Gobuster generates DNS queries for:
````
www.example.thm
admin.example.thm
shop.example.thm
dev.example.thm
academy.example.thm
````
Then it reports the ones that resolve.

From our screenshot:
````
Found: www.example.thm
Found: shop.example.thm
Found: academy.example.thm
Found: primary.example.thm
````

### Show IP addresses

Add ``-i``:
````
gobuster dns -d example.thm -w WORDLIST -i
````
Think of it as:
````
gobuster dns
     │
     ├── -d → Which domain?
     │
     ├── -w → Which names should I try?
     │
     └── -i → Show their IPs
````


### Custom DNS server
If we need to tell Gobuster which DNS server to query:
````
gobuster dns -d example.thm -w WORDLIST -r DNS_SERVER
````

## Task 6: VHost Enumeration

### What is a VHost?

A **Virtual Host (VHost)** allows one web server/IP to host multiple websites.
````
              Same Server
             10.48.178.212
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
 blog.example.thm  shop...   admin...
````
The server decides which website to return based mainly on the HTTP Host header.
````
GET / HTTP/1.1
Host: blog.example.thm
````


### VHost vs DNS mode

This is the most important difference:
| Mode             | What it does                                          |
| ---------------- | ----------------------------------------------------- |
| `gobuster dns`   | Performs **DNS lookups** for subdomains               |
| `gobuster vhost` | Sends **HTTP requests** with different `Host:` values |

So a VHost may exist even when it doesn't have a normal DNS record.



### Basic command

#### Syntax:
````
gobuster vhost -u http://TARGET -w WORDLIST
````

#### Example:
````
gobuster vhost -u http://TARGET_IP --domain example.thm --append-domain -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt
````


Eample:
````
gobuster vhost -u "http://10.48.178.212" --domain offensivetools.thm -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt --append-domain --exclude-length 250-320 
````
<img width="1908" height="894" alt="image" src="https://github.com/user-attachments/assets/5b214b9b-cf08-4bb9-b072-d95d1e8ed91c" />

- ``--append-domain`` = add the domain to every word in the wordlist.

In this without `--append-domain` it will show like:
````
admin
shop
blog
````
With ``--append-domain``:
````
admin.offensivetools.thm
shop.offensivetools.thm
blog.offensivetools.thm
````


##### Important flags
| Flag                      | Meaning                           |
| ------------------------- | --------------------------------- |
| `-u`, `--url`             | Target server/IP                  |
| `-w`                      | Wordlist                          |
| `--domain`                | Base domain, e.g. `example.thm`   |
| `--append-domain`         | Add domain to each word           |
| `--exclude-length`        | Hide responses of specified sizes |
| `-r`, `--follow-redirect` | Follow redirects                  |
| `-m`, `--method`          | HTTP method, e.g. GET/POST        |


### Why --append-domain matters

Suppose the wordlist contains:
````
www
blog
shop
````
Without ``--append-domain``, Gobuster could try:
````
Host: www
Host: blog
Host: shop
````
With it:
````
Host: www.example.thm
Host: blog.example.thm
Host: shop.example.thm
````
That's what we normally want here.

### Why --exclude-length?

Sometimes the server returns a response for every fake hostname:
````
fake.example.thm     → Size: 276
hello.example.thm    → Size: 276
random.example.thm   → Size: 276
````
This creates false positives.

If the unwanted response size is 276, you can filter it:
````
--exclude-length 276
````
Then an unusual result stands out:
````
❌ random.example.thm  Size: 276 → filtered
❌ test.example.thm    Size: 276 → filtered

✅ blog.example.thm    Size: 1493
✅ shop.example.thm    Size: 2983
````

## Task 7: Conclusion

| Mode    | Finds                  | Example                |
| ------- | ---------------------- | ---------------------- |
| `dir`   | 📁 Directories & files | `/admin`, `/login.php` |
| `dns`   | 🌐 DNS subdomains      | `dev.example.thm`      |
| `vhost` | 🖥️ Virtual hosts      | `secret.example.thm`   |



### 1. DIR Mode

Find hidden directories/files:
````
gobuster dir -u http://TARGET -w WORDLIST
````
````
example.thm
   ├── /admin
   ├── /uploads
   └── /login.php
````


### 2. DNS Mode

Find subdomains using DNS queries:
````
gobuster dns -d example.thm -w WORDLIST
````
````
example.thm
   ├── www.example.thm
   ├── shop.example.thm
   └── dev.example.thm
````


> **Note**: in your newer local Gobuster version, use --domain instead of -d.

### 3. VHOST Mode

Find virtual hosts by changing the HTTP Host header:
````
gobuster vhost -u http://TARGET_IP --domain example.thm --append-domain -w WORDLIST
````
````
Target IP
   │
   ├── Host: www.example.thm
   ├── Host: shop.example.thm
   └── Host: secret.example.thm
````
