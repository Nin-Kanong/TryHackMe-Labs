## Task 1: Introduction

### What is a Database?

A **database** stores and manages website data.

Examples:
- Usernames & passwords
- Products
- Books
- Customer information

#### How a Website Uses a Database
<img width="650" height="800" alt="image" src="https://github.com/user-attachments/assets/8f909787-6b8b-48e7-a900-0be439de0163" />


### What is SQL?

**SQL** = **Structured Query Language**

**SQL** lets a website communicate with its database.

Example:
````
SELECT * FROM users;
````



### What is SQL Injection?

**SQL Injection (SQLi)** happens when unsafe user input can change a website's SQL query.
````
User Input
    ↓
Website
    ↓
SQL Query
    ↓
Database
````


#### Learning Objective:

| Topic         | What you'll learn                      |
| ------------- | -------------------------------------- |
| SQL Injection | Understand SQLi vulnerabilities        |
| SQLMap        | Find/test SQLi using an automated tool |

## Task 2: SQL Injection Vulnerability

### Normal Login

The user enters a username and password.
````
Username: John
Password: Un@detectable444
````
The website creates an SQL query:
````
SELECT * FROM users
WHERE username='John'
AND password='Un@detectable444';
````

Result:
- ✅ Username is correct
- ✅ Password is correct
- ➜ Login successful




### Vulnerable Login (SQL Injection)
If the website doesn't validate input, an attacker can inject SQL.
````
Username: John
Password: abc' OR 1=1;-- -
````

The SQL query becomes:
````
SELECT * FROM users
WHERE username='John'
AND password='abc'
OR 1=1;-- -;
````

#### Why It Works
| Part   | Meaning                            |
| ------ | ---------------------------------- |
| `abc'` | Closes the password string         |
| `OR`   | Adds another condition             |
| `1=1`  | Always **TRUE**                    |
| `-- -` | Comments out the rest of the query |

Since ``1=1`` is always true, the database may ignore the incorrect password and allow login.

#### Visual Flow

<img width="1536" height="1024" alt="image" src="https://github.com/user-attachments/assets/d9cee810-812a-49a0-bbd4-7b92ae7eaed8" />


#### Key:
| Concept                  | Description                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| **SQL Injection (SQLi)** | Injecting SQL code through user input                                                            |
| **Cause**                | No input validation or sanitization                                                              |
| **Risk**                 | Bypass login, read, modify, or delete database data                                              |
| **Prevention**           | Parameterized queries (prepared statements), input validation, least-privilege database accounts |

## Task 3: Automated SQL Injection Tool


### 1. What is SQLMap?

**SQLMap** is a command-line tool that automatically finds and tests **SQL Injection (SQLi)** vulnerabilities.
````
Manual SQLi → More work/time
SQLMap      → Automated testing
````
> Use SQLMap only on labs or systems you have permission to test.


### 2. Basic SQLMap Commands
| Command / Flag    | Short meaning                      |
| ----------------- | ---------------------------------- |
| `sqlmap --help`   | Show available options             |
| `sqlmap --wizard` | Beginner interactive mode          |
| `-u`              | Target URL                         |
| `--dbs`           | List databases                     |
| `-D`              | Choose database                    |
| `--tables`        | List tables                        |
| `-T`              | Choose table                       |
| `--dump`          | Display/extract table records      |
| `--cookie`        | Send session/authentication cookie |
| `-r`              | Load an HTTP request from a file   |


### 3. Interactive Wizard
````
sqlmap --wizard
````

<img width="1919" height="431" alt="image" src="https://github.com/user-attachments/assets/42b9f6b0-3c5e-4643-b7bd-239e0f10b1bc" />

SQLMap asks questions step-by-step:
````

      ▼

````





### 4. Test a GET Parameter

Example URL from the lesson:
````
http://sqlmaptesting.thm/search/cat=1
````
Here:
````
/search/cat=1
        └─┬─┘
          ▼
     GET parameter
````
Test it with:
````
sqlmap -u http://sqlmaptesting.thm/search/cat=1
````

<img width="924" height="828" alt="image" src="https://github.com/user-attachments/assets/51d0d73d-23c5-4795-84cc-41cd10ac7d73" />

Meaning

````
sqlmap
  │
  ├── -u → Target URL
  │
  └── cat=1 → Parameter being tested
````

SQLMap checks whether the parameter is vulnerable to SQL injection.


### 5. SQLMap Results

SQLMap identifying several SQLi techniques:

| SQLi Type               | Simple meaning                           |
| ----------------------- | ---------------------------------------- |
| **Boolean-based blind** | Uses TRUE/FALSE responses                |
| **Error-based**         | Gets information from database errors    |
| **Time-based blind**    | Uses response delays                     |
| **UNION query**         | Uses `UNION` to retrieve additional data |


Example:
````
cat=1
  │
  ▼
SQLMap tests parameter
  │
  ├── Boolean-based
  ├── Error-based
  ├── Time-based
  └── UNION
  │
  ▼
Vulnerable ✓
````

### 9. Cookie-Based Testing

Some pages require you to be logged in.

SQLMap can send our authorized session cookie:
````
sqlmap -u <URL> --cookie="SESSIONID=abcdef123456"
````


Flow:
````
SQLMap
   │
   │ Session Cookie
   ▼
Logged-in Page
   │
   ▼
Test accessible parameter
````
Common cookie names can include things like ``PHPSESSID`` or ``JSESSIONID``, depending on the application.




### 10. POST Request Testing — -r

Not every parameter appears in the URL. Login and registration forms commonly send data in an HTTP request body.

If an intercepted authorized request is saved as:
````
intercepted_request.txt
````
SQLMap can load it with:
````
sqlmap -r intercepted_request.txt
````
````
Browser
   │
   ▼
HTTP POST Request
   │
   ▼
Save request.txt
   │
   ▼
sqlmap -r request.txt
   │
   ▼
Test request
````
